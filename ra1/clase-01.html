1.ºperiodo

Quién os da clase y por qué esto se aprende haciendo

  • A qué se dedica el docente: SRE (fiabilidad de sistemas en producción) y qué tiene que ver con la seguridad.
  • Experiencia práctica en hacking con proyectos propios, con demostración en vivo.
  • Nadie sabe de todo: lo que cuenta es mirar, probar, romper en un entorno controlado y aprender de ello.
  • Cómo funciona la asignatura: el documento del curso, una cuenta AWS emulada por alumno, la IA como compañera y una entrega por bloque en git.
  • Regla del curso: solo se ataca lo que está dentro del alcance autorizado.
2.ºperiodo

Git, GitHub y Docker

  1. Instala Git (git-scm.com/downloads; en Linux, sudo apt install git) y configura tu identidad: 
    git config --global user.name "Tu Nombre"
git config --global user.email "tu@correo"
git config --global init.defaultBranch main
  2. Cuenta en github.com si no la tienes. Pásale tu usuario al docente: con él se crea tu repositorio privado en la organización de la asignatura.
  3. Docker. Windows: Docker Desktop con el motor WSL 2. macOS: Docker Desktop. Linux: Docker Engine y tu usuario en el grupo docker. 
    docker run --rm hello-world
docker compose version
  4. Con Docker funcionando podréis levantar Floci, la cuenta AWS emulada en la que trabajaremos todo el curso. Si hay tiempo, dejadla descargando: docker pull floci/floci:latest.

Regla de la IA para todo el curso

Lo que diga la IA se comprueba contra la salida real de la herramienta antes de darlo por bueno. Si no coincide, gana la herramienta.

3.ºperiodo

Minijuego «Hackea el ranking»

El docente despliega en su equipo un juego (una web con su API y un ranking) y os da la dirección en la red del aula. El objetivo es subir al primer puesto del ranking sin jugar limpio. Cada fallo del servidor que aprovechéis pone una bandera junto a vuestro nombre en el marcador del proyector.

Alcance

Autorizado: solo la dirección del juego que da el docente, solo durante esta clase. Nada de atacar la red del aula, los equipos de compañeros ni ningún otro servicio. Fuera de esto, lo mismo sería delito.

Con qué contáis: el navegador y sus herramientas de desarrollo (F12), la terminal y curl, y vuestra IA para que os explique lo que vayáis encontrando.

Mientras jugáis, apuntad qué habéis probado y en qué orden (es el principio de las fases de un ataque), qué funcionó, por qué creéis que funcionó y cómo lo arreglaríais. En la clase 2 cada truco se convierte en una vulnerabilidad documentada.

Jueves

1periodo

Primer commit

  1. Clona tu repositorio privado de la organización y crea la carpeta ra1/.
  2. Guarda en ra1/puesto.txt la salida de git --version, docker compose version y una respuesta de tu IA a «qué es un escaneo de puertos».
  3. Commit y push. Es el primero de los que se miran en la entrega del bloque.
  4. Con el tiempo que quede: el servidor del juego pasa a modo validado. Probad si los trucos de ayer siguen funcionando y pensad por qué.

Comprobación final

  • git --version responde y tu identidad está configurada
  • Usuario de GitHub enviado al docente
  • docker run --rm hello-world funciona
  • IA local o en la nube respondiendo
  • Al menos una bandera en el marcador y vuestras notas guardadas
  • ra1/puesto.txt subido a vuestro repositorio
