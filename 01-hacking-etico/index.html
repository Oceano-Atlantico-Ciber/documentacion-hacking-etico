Hacking ético

Hacking ético, alcance y monitorización

RA1 · Determina herramientas de monitorización para detectar vulnerabilidades aplicando técnicas de hacking ético.

Unidades

Cuatro unidades, una por cada bloque de contenidos del currículo. Cada una tiene sus temas y sus ejercicios.

01 · Qué es el hacking éticoTerminología, Código Penal, datos personales y divulgación responsable. Criterios a y b. 02 · Permisos y alcanceCaja negra, gris y blanca; autorización, alcance y reglas de un test de intrusión. Criterio c. 03 · Vulnerabilidades y ataquesPropiedades de la seguridad, fases de un ataque, tipos de vulnerabilidades y ataques, y cómo documentarlas. Criterios d a h. 04 · Herramientas y monitorizaciónFamilias de herramientas, monitorización según la organización, Suricata y darknets. Criterios a e i.

Contenidos básicos

Determinación de las herramientas de monitorización para detectar vulnerabilidades

  • Elementos esenciales del hacking ético. → 1.1
  • Diferencias entre hacking, hacking ético, tests de penetración y hacktivismo. → 1.1 y 1.2
  • Recolección de permisos y autorizaciones previos a un test de intrusión. → 2.2
  • Fases del hacking. → 3.2
  • Auditorías de caja negra y de caja blanca. → 2.1

  • ClearNet, Deep Web, Dark Web, Darknets. Conocimiento, diferencias y herramientas de acceso: Tor, ZeroNet, FreeNet. → 4.3

Entrega

Diez ejercicios en la carpeta ra1/ de tu repositorio de entregas, todos en main. Antes de empezar, termina la Presentación y las unidades de Git y Docker de Fundamentos.

Cada ejercicio empieza con preparar.py, que deja su plantilla en ra1/<ejercicio>/. Lánzalo desde tu repositorio de entregas:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-hacking-etico/preparar.py u1-e1

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/01-hacking-etico/preparar.py u1-e1

Cada alumno tiene su propio escenario: casos, direcciones, fechas, registros y rutas salen de su usuario de GitHub. Antes de etiquetar, pruebas.py pasa las mismas comprobaciones públicas que el corrector:

Windows · PowerShell

py ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u1-e1

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u1-e1

Algunas preguntas tienen una sola respuesta correcta, que guarda el docente: es la clave (qué figura es cada caso, qué cláusula falla, qué técnica es cada evento…). Esas respuestas solo las compara el corrector, que te dice cuántas fallan, pero no cuáles. El resultado lo ves en GitHub, en la comprobación Corrector ra1 de tu último commit de main (el icono ✓ o ✗ junto al commit).

Cada ejercicio se entrega con su etiqueta anotada sobre main. Si corriges algo después, mueve la etiqueta (git tag -fa y git push --force origin <etiqueta>). No hay fecha límite.
