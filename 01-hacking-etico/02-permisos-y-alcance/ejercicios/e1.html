FicheroQué lleva

Así quedaría el alcance de otro encargo inventado, el de una gestoría; el tuyo lleva los datos de la clínica:

{
  "cliente": "Gestoría Norte SL",
  "autoriza": "Pedro Sanz, director",
  "tipo": "caja negra",
  "dentro": ["198.51.100.20", "10.20.0.0/24"],
  "fuera": ["10.20.0.5"],
  "inicio": "2027-03-08",
  "fin": "2027-03-10",
  "horario": {"desde": "08:00", "hasta": "14:00"},
  "prohibido": ["denegación de servicio"],
  "emergencia": {"nombre": "Lola Vidal", "telefono": "611 222 333"}
}

Las comillas, las comas y los corchetes son obligatorios: es JSON. Las listas van entre corchetes, con cada valor entre comillas.

1Prepara el ejercicio

Desde tu repositorio de entregas:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-hacking-etico/preparar.py u2-e1
cd ra1/u2-e1
code LEEME.md alcance.json

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/01-hacking-etico/preparar.py u2-e1
cd ra1/u2-e1
code LEEME.md alcance.json

LEEME.md es tu encargo: las direcciones, las fechas y el horario son distintos para cada alumno. alcance.json trae todos los campos vacíos. en_alcance.py es un programa pequeño que lee tu alcance.json y responde si una dirección se puede probar en un momento dado; lo usas en el paso 3.

2Escribe el alcance

CampoQué va
cliente, autorizaLa empresa, y nombre y cargo de quien firma.
tipocaja negra, caja gris o caja blanca, según lo que te dan.
dentroLista de direcciones y redes que se pueden probar, como "203.0.113.10" o "192.168.1.0/24".
fueraLista de direcciones que no se tocan aunque estén dentro de una red de dentro.
inicio, finPrimera y última noche de la prueba, como "2027-02-01".
horariodesde y hasta como "20:00". Si cruza la medianoche, la madrugada cuenta como parte de la noche anterior.
prohibidoValores de esta lista, tal cual: denegación de servicio, ingeniería social, modificar datos, borrar datos, escaneo, explotación.
emergencianombre y telefono del contacto de emergencia.

El correo en Microsoft 365 no tiene dirección en tu encargo: no lo pongas en dentro. El diagrama del alcance de 2.2 te ayuda con las exclusiones y con el horario que cruza la medianoche.

3Pregúntale a tu alcance

Desde ra1/u2-e1, pasa a en_alcance.py una dirección y un momento:

Windows · PowerShell

py en_alcance.py 203.0.113.10 "2027-02-03 23:30"
py en_alcance.py 203.0.113.10 "2027-02-03 12:00"

macOS / Linux · Terminal

python3 en_alcance.py 203.0.113.10 "2027-02-03 23:30"
python3 en_alcance.py 203.0.113.10 "2027-02-03 12:00"

Cada orden responde DENTRO del alcance o FUERA del alcance. Cambia las direcciones y las fechas por las de tu encargo y prueba los casos difíciles: el datáfono, la madrugada de la última noche, la noche antes de empezar.

Las pruebas y el corrector hacen lo mismo: le hacen nueve preguntas a tu alcance.json con esta misma regla. No ves qué dirección y qué momento usa cada pregunta, pero sí cuántas fallan y de qué trata la primera que falla (por ejemplo, «el datáfono»).

El corrector marca fallo si:

  • alcance.json no es JSON válido, o falta un campo o no tiene el formato de la tabla.
  • Alguna de las nueve preguntas (una dirección y un momento) sale distinta de lo que permite el encargo. Dice cuántas y pone un ejemplo.
  • El tipo, lo prohibido, quién autoriza o el contacto de emergencia no son los del encargo. Esto va con clave: solo lo mira el corrector.

4Pruébalo en tu equipo

Primero guarda tu trabajo en un commit: las pruebas solo ven lo que está en commits.

cd ~/hacking-etico/entregas-<tu-usuario>
git add ra1/u2-e1
git commit -m "docs(ra1-u2-e1): alcance del test de intrusión de la clínica"

Después pasa las mismas comprobaciones públicas que el corrector, nueve preguntas incluidas:

Windows · PowerShell

py ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u2-e1

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u2-e1

Tiene que salir ✓ formato correcto. Cada ✗ dice qué falla: corrige, haz otro commit y repite. El tipo, lo prohibido, quién autoriza y el contacto de emergencia solo los compara el corrector.

5Sube y mira el corrector

git push

En GitHub, abre tu repositorio y pulsa el icono ✓ o ✗ junto a tu último commit de main. Abre Details en la comprobación Corrector ra1: hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección.

6Etiqueta

Cuando la fila de U2·E1 salga sin fallos:

git tag -a entrega-ra1-u2-e1 -m "U2·E1 resuelto"
git push origin entrega-ra1-u2-e1

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta.
