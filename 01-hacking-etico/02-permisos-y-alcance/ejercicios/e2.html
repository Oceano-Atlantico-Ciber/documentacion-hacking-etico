U2·E2 · Un alcance con fallos

Otro auditor dejó firmado el alcance de una prueba para Transportes Atlántico SL, con doce cláusulas. Seis de ellas meten en problemas al auditor, al cliente o a terceros, cada una por un motivo distinto: encuéntralas y di de qué tipo es cada fallo.

Qué entregas

En ra1/u2-e2/:

FicheroQué lleva
fallos.mdLas doce cláusulas, tal como las deja preparar.py, y la tabla de debajo rellena: una fila por cláusula, de C1 a C12.

En cada fila va «no» o un tipo de fallo. Por ejemplo, con dos cláusulas inventadas, «C1. El cliente es Panadería Sol SL» (está bien) y «C2. Se prueba la wifi del local de al lado» (no es del cliente), las filas quedarían así:

| Cláusula | Fallo |
|---|---|
| C1 | no |
| C2 | terceros |

1Prepara el ejercicio

Desde tu repositorio de entregas:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-hacking-etico/preparar.py u2-e2
code ra1/u2-e2/fallos.md

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/01-hacking-etico/preparar.py u2-e2
code ra1/u2-e2/fallos.md

Las cláusulas están en fallos.md, numeradas en un orden distinto para cada alumno.

2Clasifica cada cláusula

En la columna Fallo, escribe «no» si la cláusula está bien, o el tipo de fallo tal cual:

TipoEl fallo está en…
autorizaciónquién autoriza o cómo.
objetivosqué se puede probar.
fechascuándo.
técnicascómo se prueba.
datosqué se hace con los datos que aparezcan.
tercerosalgo que no es del cliente.

El corrector marca fallo si:

  • Falta una cláusula, o un valor no es «no» ni un tipo de la lista.
  • No has marcado exactamente seis, o repites un tipo.
  • Hay cláusulas mal clasificadas. Dice cuántas, no cuáles.

3Pruébalo en tu equipo

Primero guarda tu trabajo en un commit: las pruebas solo ven lo que está en commits.

cd ~/hacking-etico/entregas-<tu-usuario>
git add ra1/u2-e2
git commit -m "docs(ra1-u2-e2): fallos del alcance de Transportes Atlántico"

Después pasa las mismas comprobaciones públicas que el corrector:

Windows · PowerShell

py ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u2-e2

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u2-e2

Tiene que salir ✓ formato correcto. Cada ✗ dice qué falla: corrige, haz otro commit y repite. Si cada cláusula está bien clasificada solo lo mira el corrector.

4Sube y mira el corrector

git push

En GitHub, abre tu repositorio y pulsa el icono ✓ o ✗ junto a tu último commit de main. Abre Details en la comprobación Corrector ra1: hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección.

5Etiqueta

Cuando la fila de U2·E2 salga sin fallos:

git tag -a entrega-ra1-u2-e2 -m "U2·E2 resuelto"
git push origin entrega-ra1-u2-e2

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta.
