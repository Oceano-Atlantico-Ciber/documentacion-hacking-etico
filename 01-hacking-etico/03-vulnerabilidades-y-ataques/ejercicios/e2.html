U3·E2 · Ficha de un CVE real

Cada alumno recibe una vulnerabilidad conocida que se ha explotado de verdad. Consultas sus datos oficiales desde PowerShell, en el catálogo de CISA y en NVD, y la documentas en una ficha JSON.

1Prepara el ejercicio

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-hacking-etico/preparar.py u3-e2
code ra1/u3-e2/ficha.json

Tu CVE ya está en el campo cve. No lo cambies.

2Búscalo en el catálogo KEV

Todas las órdenes de este ejercicio son de PowerShell. Cambia el CVE por el tuyo:

$cve = "CVE-2021-44228"
$kev = Invoke-RestMethod https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json
$kev.vulnerabilities | Where-Object cveID -eq $cve

De ahí salen el fabricante y el producto, y la fecha en que CISA lo añadió (dateAdded), que va en fecha_kev.

3Consulta NVD

$r = Invoke-RestMethod "https://services.nvd.nist.gov/rest/json/cves/2.0?cveId=$cve"
$r.vulnerabilities[0].cve.metrics.cvssMetricV31.cvssData | Select-Object baseScore, vectorString
$r.vulnerabilities[0].cve.weaknesses.description
$r.vulnerabilities[0].cve.descriptions | Where-Object lang -eq en

Puede haber dos notas CVSS 3.1, la de NVD y la del fabricante: elige una y copia su baseScore en cvss.nota (un número, sin comillas) y su vectorString completo en cvss.vector. El CWE va en cwe. Las versiones afectadas y la corregida están en el aviso del fabricante, enlazado en la ficha de NVD.

4Completa la ficha

propiedades es una lista con las que rompe, escritas como en el tema 3.1. En defensa, separa lo que corrige el fallo de lo que solo reduce el riesgo. En fuentes, al menos la ficha de NVD (https://nvd.nist.gov/vuln/detail/…). Si el JSON no es válido, VS Code lo marca en rojo.

El corrector marca fallo si:

  • ficha.json no es JSON válido, has cambiado el CVE o falta un campo.
  • Un campo no tiene su formato: CWE como CWE-79, nota numérica, vector que empieza por CVSS:3.1/, fecha como aaaa-mm-dd.
  • La fecha en KEV, el CWE o la nota con su vector no coinciden con los datos oficiales de tu CVE.

5Pruébalo, sube y etiqueta

py ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u3-e2
git add ra1/u3-e2
git commit -m "docs(ra1-u3-e2): ficha de un CVE del catálogo KEV"
git push
git tag -a entrega-ra1-u3-e2 -m "U3·E2 resuelto"
git push origin entrega-ra1-u3-e2

pruebas.py comprueba el formato; los datos los compara el corrector. Etiqueta cuando la fila de U3·E2 de Corrector ra1 salga sin fallos.
