U3·E1 · Ficha de Hackea el ranking

Convierte en vulnerabilidades los seis retos del juego del primer día: di qué debilidad del catálogo CWE es cada reto y qué propiedad de la seguridad rompe.

Teoría
3.1, 3.3 y 3.5
Aprendes
A poner nombre a un fallo con el catálogo CWE y a decir qué propiedad rompe.
Criterios
d, f, h
Trabajas en
ra1/u3-e1/
Etiqueta
entrega-ra1-u3-e1 sobre main

Qué entregas

En ra1/u3-e1/:

FicheroQué lleva
ranking.mdLa tabla de la plantilla con las columnas CWE y Propiedad rellenas para los seis retos.

Así quedaría una fila de un reto inventado, «entrar con la contraseña por defecto admin/admin»; en tu fichero solo están los seis retos del juego:

| Reto | Qué se hace | CWE | Propiedad |
|---|---|---|---|
| 7 | Entrar con la contraseña por defecto admin/admin | CWE-1392 | autenticidad |

1Prepara el ejercicio

Desde tu repositorio de entregas:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-hacking-etico/preparar.py u3-e1
code ra1/u3-e1/ranking.md

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/01-hacking-etico/preparar.py u3-e1
code ra1/u3-e1/ranking.md

2Repasa los retos

Tienes el juego, sus ficheros y la solución reto a reto en Hackea el ranking. Si guardaste tus notas de la partida, úsalas. Para cada reto, busca su CWE en cwe.mitre.org: lee la descripción y comprueba que encaja con lo que pasaba en el juego.

3Rellena la ficha

En cada fila, escribe el CWE con la forma CWE-123 y una de las cuatro propiedades tal cual: confidencialidad, integridad, disponibilidad o autenticidad. No cambies las columnas Reto ni Qué se hace.

El corrector marca fallo si:

  • Falta un reto o un valor no tiene el formato de su columna.
  • Hay retos cuyo CWE o propiedad no coinciden con la clave. Dice cuántos, no cuáles.

4Pruébalo en tu equipo

Primero guarda tu trabajo en un commit: las pruebas solo ven lo que está en commits.

cd ~/hacking-etico/entregas-<tu-usuario>
git add ra1/u3-e1
git commit -m "docs(ra1-u3-e1): ficha de los fallos de Hackea el ranking"

Después pasa las mismas comprobaciones públicas que el corrector:

Windows · PowerShell

py ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u3-e1

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u3-e1

Tiene que salir ✓ formato correcto. Cada ✗ dice qué falla: corrige, haz otro commit y repite. La comparación con la clave solo la hace el corrector.

5Sube y mira el corrector

git push

En GitHub, abre tu repositorio y pulsa el icono ✓ o ✗ junto a tu último commit de main. Abre Details en la comprobación Corrector ra1: hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección.

6Etiqueta

Cuando la fila de U3·E1 salga sin fallos:

git tag -a entrega-ra1-u3-e1 -m "U3·E1 resuelto"
git push origin entrega-ra1-u3-e1

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta.
