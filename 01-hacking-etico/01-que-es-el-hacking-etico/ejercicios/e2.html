U1·E2 · El security.txt de la empresa

Lee el security.txt de una web real y escribe el de tu empresa ficticia, servido con nginx en Docker. Es el fichero donde una empresa dice cómo quiere que le avisen de sus fallos.

Teoría
1.2 · Ética y ley · Divulgación responsable
Aprendes
A publicar, con el formato estándar, por dónde y cómo debe llegar el aviso de un fallo.
Criterio

Qué entregas

En ra1/u1-e2/:

FicheroQué lleva
web/.well-known/security.txtLo escribes tú, con los valores de tu LEEME.md.
LEEME.md, docker-compose.yml, web/index.htmlTal como los deja preparar.py, sin cambios.

El fichero tiene una línea Campo: valor por campo y puede llevar comentarios con #. Así quedaría el de otra empresa inventada, tienda-ejemplo.test; el tuyo lleva los valores de tu LEEME.md:

# Cómo avisar de un fallo de seguridad
Contact: mailto:avisos@tienda-ejemplo.test
Policy: https://tienda-ejemplo.test/avisos
Canonical: https://tienda-ejemplo.test/.well-known/security.txt
Preferred-Languages: es, en
Expires: 2027-06-30T23:59:59Z

1Prepara el ejercicio

Desde tu repositorio de entregas:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-hacking-etico/preparar.py u1-e2
cd ra1/u1-e2
code LEEME.md

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/01-hacking-etico/preparar.py u1-e2
cd ra1/u1-e2
code LEEME.md

LEEME.md trae el dominio de tu empresa y los valores que tiene que llevar su fichero. Hay también una web mínima en web/ y un docker-compose.yml que la sirve. Las órdenes de los pasos 2 a 4 se lanzan desde ra1/u1-e2.

2Lee uno de verdad

Pedir un fichero que una web publica para esto no es ninguna prueba de seguridad:

Windows · PowerShell

curl.exe -s https://github.com/.well-known/security.txt

macOS / Linux · Terminal

curl -s https://github.com/.well-known/security.txt

Fíjate en el formato: una línea por campo, Campo: valor, y comentarios con #. Los campos están en el RFC 9116. GitHub añade alguno propio, como Hiring, que no es del estándar: no lo copies.

3Escribe el de tu empresa

mkdir web/.well-known
code web/.well-known/security.txt

Escribe estos campos con los valores de LEEME.md: Contact, Policy, Canonical, Preferred-Languages con es, y un Expires de dentro de menos de un año en formato RFC 3339 (fecha y hora en UTC con una Z al final, por ejemplo 2027-06-30T23:59:59Z; elige una que caiga dentro de los próximos doce meses). Puedes añadir comentarios.

mkdir muestra la carpeta que acaba de crear: es normal.

4Sírvelo

Con Docker Desktop en marcha:

Windows · PowerShell

docker compose up -d
curl.exe -i http://localhost:8081/.well-known/security.txt
docker compose down

macOS / Linux · Terminal

docker compose up -d
curl -i http://localhost:8081/.well-known/security.txt
docker compose down

Tiene que responder 200 con tu fichero. Si sale 404, revisa el nombre de la carpeta, que empieza por punto.

El corrector marca fallo si:

  • Falta web/.well-known/security.txt, o tiene líneas que no son Campo: valor.
  • Falta Contact, Policy o Canonical con los valores de tu LEEME.md, o Preferred-Languages con es.
  • No hay un solo Expires, no es RFC 3339 o no es una fecha futura de dentro de menos de un año.
  • Hay campos que no son del RFC 9116.

5Pruébalo en tu equipo

Primero guarda tu trabajo en un commit: las pruebas solo ven lo que está en commits.

cd ~/hacking-etico/entregas-<tu-usuario>
git add ra1/u1-e2
git commit -m "feat(ra1-u1-e2): security.txt de la empresa"

Después pasa las mismas comprobaciones que el corrector:

Windows · PowerShell

py ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u1-e2

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u1-e2

Tiene que salir ✓ formato correcto. Cada ✗ dice qué falla: corrige, haz otro commit y repite.

6Sube y mira el corrector

git push

En GitHub, abre tu repositorio y pulsa el icono ✓ o ✗ junto a tu último commit de main. Abre Details en la comprobación Corrector ra1: hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección.

7Etiqueta

Cuando la fila de U1·E2 salga sin fallos:

git tag -a entrega-ra1-u1-e2 -m "U1·E2 resuelto"
git push origin entrega-ra1-u1-e2

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta.
