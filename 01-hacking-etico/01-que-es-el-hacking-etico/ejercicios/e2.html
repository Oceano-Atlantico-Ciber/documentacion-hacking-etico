U1·E2 · El security.txt de la empresa

Una empresa que quiere que le avisen de sus fallos publica cómo hacerlo en /.well-known/security.txt. Lees el de una web real y escribes el de tu empresa ficticia, servido con nginx en Docker.

Teoría
1.2 · Ética y ley · Divulgación responsable
Criterio
b
Trabajas en
ra1/u1-e2/web/.well-known/security.txt
Etiqueta
entrega-ra1-u1-e2 sobre main
Necesitas
Docker Desktop, solo para verlo servido

1Prepara el ejercicio

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-hacking-etico/preparar.py u1-e2
cd ra1/u1-e2
code LEEME.md

LEEME.md trae el dominio de tu empresa y los valores que tiene que llevar su fichero. Hay también una web mínima en web/ y un docker-compose.yml que la sirve.

2Lee uno de verdad

Pedir un fichero que una web publica para esto no es ninguna prueba de seguridad. En PowerShell:

(Invoke-WebRequest https://github.com/.well-known/security.txt).Content

Fíjate en el formato: una línea por campo, Campo: valor, y comentarios con #. Los campos están en la RFC 9116.

3Escribe el de tu empresa

mkdir web/.well-known
code web/.well-known/security.txt

Con los valores de LEEME.md: Contact, Policy, Canonical, Preferred-Languages con es, y un Expires de dentro de menos de un año en formato RFC 3339 (como 2027-10-31T23:59:59Z). Puedes añadir comentarios.

4Sírvelo

docker compose up -d
curl.exe -i http://localhost:8081/.well-known/security.txt
docker compose down

Tiene que responder 200 con tu fichero. Si sale 404, revisa el nombre de la carpeta, que empieza por punto.

El corrector marca fallo si:

  • Falta web/.well-known/security.txt, o tiene líneas que no son Campo: valor.
  • Falta Contact, Policy o Canonical con los valores de tu LEEME.md, o Preferred-Languages con es.
  • No hay un solo Expires, no es RFC 3339 o no es una fecha futura de dentro de menos de un año.
  • Hay campos que no son de la RFC 9116.

5Pruébalo, sube y etiqueta

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u1-e2
git add ra1/u1-e2
git commit -m "feat(ra1-u1-e2): security.txt de la empresa"
git push
git tag -a entrega-ra1-u1-e2 -m "U1·E2 resuelto"
git push origin entrega-ra1-u1-e2

Etiqueta cuando la fila de U1·E2 de Corrector ra1 salga sin fallos.
