Qué entregas

En ra1/u1-e1/:

FicheroQué lleva
casos.mdTus ocho casos, tal como los deja preparar.py, y la tabla de debajo rellena: una fila por caso con su figura y su artículo.

Cada fila lleva el código del caso, una figura y un artículo, escritos tal cual aparecen en las listas. Por ejemplo, para un caso inventado, el X01 («alguien entra en el correo de un famoso con una contraseña filtrada»), la fila quedaría así:

| Caso | Figura | Artículo |
|---|---|---|
| X01 | ciberdelito | 197 bis |

1Prepara el ejercicio

Desde tu repositorio de entregas:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-hacking-etico/preparar.py u1-e1
code ra1/u1-e1/casos.md

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/01-hacking-etico/preparar.py u1-e1
code ra1/u1-e1/casos.md

preparar.py elige tus ocho casos de un banco de veinte y los escribe al principio de casos.md, con la tabla vacía debajo.

2Clasifica cada caso

Rellena cada fila con un valor de cada lista, escrito tal cual:

  • Figura: hacking ético, hacktivismo o ciberdelito.
  • Artículo: ninguno, 197 bis, 197 ter, 264 o 264 bis.

El hacktivismo sin permiso también es delito, así que lleva su artículo. Si dudas entre dos artículos, quédate con el que describe lo principal que se hizo.

El corrector marca fallo si:

  • Falta o sobra una fila, o cambias los códigos de los casos.
  • Un valor no es de su lista, o un caso de hacking ético lleva artículo.
  • Hay casos cuya figura o artículo no coinciden con la clave. Dice cuántos, no cuáles.

3Pruébalo en tu equipo

Primero guarda tu trabajo en un commit: las pruebas solo ven lo que está en commits.

cd ~/hacking-etico/entregas-<tu-usuario>
git add ra1/u1-e1
git commit -m "docs(ra1-u1-e1): casos clasificados"

Después pasa las mismas comprobaciones públicas que el corrector:

Windows · PowerShell

py ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u1-e1

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u1-e1

Tiene que salir ✓ formato correcto. Cada ✗ dice qué falla: corrige, haz otro commit y repite. La comparación con la clave solo la hace el corrector.

4Sube y mira el corrector

git push

En GitHub, abre tu repositorio y pulsa el icono ✓ o ✗ junto a tu último commit de main. Abre Details en la comprobación Corrector ra1: hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección.

5Etiqueta

Cuando la fila de U1·E1 salga sin fallos:

git tag -a entrega-ra1-u1-e1 -m "U1·E1 resuelto"
git push origin entrega-ra1-u1-e1

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. El corrector evalúa siempre lo que haya en la etiqueta.
