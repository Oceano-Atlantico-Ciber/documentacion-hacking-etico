U4·E2 · Un sensor vigilando la web

El servidor web de una empresa ficticia tiene pegado un sensor Suricata. Haces una pequeña auditoría desde tu puesto, miras qué ha visto el sensor y escribes una regla para lo que se le escapó.

1Prepara el laboratorio

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-hacking-etico/preparar.py u4-e2
cd ra1/u4-e2
docker compose up -d
docker compose logs suricata

Espera a ver Engine started en el registro de Suricata. El laboratorio es tuyo y está solo en tu equipo: es tu alcance.

ContenedorDirecciónQué es
web172.28.0.20El servidor web de la empresa. Suricata escucha pegado a él.
auditordinámicaTu puesto: nmap dentro de la misma red.
curldinámicacurl dentro de la misma red, para pedir páginas.

2Haz la auditoría

Reconocimiento y escaneo de la red y del servidor:

docker compose run --rm auditor -sn 172.28.0.0/24
docker compose run --rm auditor -sV 172.28.0.20

Mira la web: la portada, lo que pide no indexar y lo que aparezca allí.

docker compose run --rm curl -i http://172.28.0.20/
docker compose run --rm curl -i http://172.28.0.20/robots.txt
docker compose run --rm curl -i http://172.28.0.20/admin/
docker compose run --rm curl -i http://172.28.0.20/<lo-que-diga-robots.txt>/

3Mira qué ha visto el sensor

py etiquetar.py > alertas.txt
cat alertas.txt

etiquetar.py resume las alertas de salidas/suricata/eve.json por fase y por origen. Compáralo con lo que hiciste: la visita al directorio de copias que aparece en robots.txt, que expone copias de seguridad de la empresa, no tiene ninguna alerta propia. Su nombre es distinto para cada alumno. Las reglas están en suricata/local.rules; léelas para ver por qué.

4Escribe tu regla

Añade al final de suricata/local.rules una regla que salte cuando alguien pida tu directorio de copias, y solo entonces. Copia la de /admin como punto de partida, cambia lo que haga falta y usa un sid desde 1000100. Pon la fase al principio del mensaje para que etiquetar.py la cuente bien.

docker compose restart suricata
docker compose run --rm curl -i http://172.28.0.20/<lo-que-diga-robots.txt>/
py etiquetar.py > alertas.txt
cat alertas.txt

Comprueba que tu alerta aparece. Si Suricata no arranca, docker compose logs suricata dice qué línea no entiende.

Si pides la regla a la IA, comprueba cada palabra clave en la documentación de reglas de Suricata 7 y pruébala antes de darla por buena.

El corrector levanta su propio laboratorio con tu local.rules, repite la portada, robots.txt y /admin/, y después pide tu directorio de copias. Marca fallo si:

  • Falta suricata/local.rules o alertas.txt, o alertas.txt no es la salida de etiquetar.py.
  • Has borrado reglas de la plantilla, o no hay ninguna regla tuya con sid desde 1000100.
  • Suricata no acepta el fichero.
  • Tu regla no salta al pedir tu directorio de copias, o salta también con lo demás.

5Pruébalo en tu equipo

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u4-e2

Monta un laboratorio aparte, igual que el del corrector, y lo quita al terminar. Tarda un par de minutos.

6Sube, etiqueta y apaga

git add ra1/u4-e2
git commit -m "feat(ra1-u4-e2): regla de Suricata para las copias expuestas"
git push
git tag -a entrega-ra1-u4-e2 -m "U4·E2 resuelto"
git push origin entrega-ra1-u4-e2
cd ra1/u4-e2
docker compose down

Lo que escribe Suricata en salidas/ no se sube: ya lo excluye el .gitignore de la plantilla.
