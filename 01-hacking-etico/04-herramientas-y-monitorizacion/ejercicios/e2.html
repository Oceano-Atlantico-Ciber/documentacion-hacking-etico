U4·E2 · Un sensor vigilando la web

El servidor web de una empresa ficticia tiene pegado un sensor Suricata. Haz una pequeña auditoría desde tu puesto, mira qué ha visto el sensor y escribe una regla para lo que se le escapó.

1Prepara el laboratorio

Desde tu repositorio de entregas, con Docker Desktop en marcha:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-hacking-etico/preparar.py u4-e2
cd ra1/u4-e2
docker compose up -d
docker compose logs -f suricata

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/01-hacking-etico/preparar.py u4-e2
cd ra1/u4-e2
docker compose up -d
docker compose logs -f suricata

La última orden va mostrando el registro de Suricata: pulsa Ctrl+C cuando veas Engine started. Las órdenes de los pasos 2 a 4 se lanzan desde ra1/u4-e2. El laboratorio es tuyo y está solo en tu equipo: es tu alcance.

ContenedorDirecciónQué es
web172.28.0.20El servidor web de la empresa. Suricata escucha pegado a él.
auditorla que le toqueTu puesto: nmap dentro de la misma red.
curlla que le toquecurl dentro de la misma red, para pedir páginas.

2Haz la auditoría

Primero, el escaneo de la red y del servidor:

docker compose run --rm auditor -sn 172.28.0.0/24
docker compose run --rm auditor -sV 172.28.0.20

Con -sn, nmap solo busca qué equipos de la red responden, sin mirar sus puertos. Con -sV, mira los puertos abiertos del servidor y averigua qué programa y qué versión hay detrás de cada uno.

Después, mira la web: la portada, su robots.txt y lo que aparezca allí. El robots.txt es el fichero donde una web pide a los buscadores que no indexen ciertas rutas; a quien audita le dice justo qué rutas pueden ser interesantes.

docker compose run --rm curl -s -i http://172.28.0.20/
docker compose run --rm curl -s -i http://172.28.0.20/robots.txt
docker compose run --rm curl -s -i http://172.28.0.20/admin/

En el robots.txt aparece, además de /admin/, un directorio de copias de seguridad, con un nombre distinto para cada alumno. Pídelo, cambiando <copias> por ese nombre (sin las barras):

docker compose run --rm curl -s -i http://172.28.0.20/<copias>/

3Mira qué ha visto el sensor

Windows · PowerShell

py etiquetar.py alertas.txt
Get-Content alertas.txt

macOS / Linux · Terminal

python3 etiquetar.py alertas.txt
cat alertas.txt

etiquetar.py resume por fase y por origen las alertas de salidas/suricata/eve.json, y guarda el resumen en alertas.txt. Si preparaste el ejercicio antes de este cambio y la orden da un error, tu etiquetar.py es la versión anterior: en Windows usa py etiquetar.py | Out-File -Encoding utf8 alertas.txt y en macOS o Linux python3 etiquetar.py > alertas.txt.

Compáralo con lo que hiciste: la visita al directorio de copias, que expone copias de seguridad de la empresa, no tiene ninguna alerta propia. Lee las reglas de suricata/local.rules para ver por qué.

Cada regla tiene un msg (el mensaje de la alerta, que empieza por la fase) y un sid, el número que la identifica: no puede haber dos reglas con el mismo.

4Escribe tu regla

Añade al final de suricata/local.rules una regla que salte cuando alguien pida tu directorio de copias, y solo entonces. Copia la de /admin como punto de partida, cambia lo que haga falta y usa un sid desde 1000100. Empieza el mensaje por la fase, en mayúsculas y sin tildes, para que etiquetar.py la cuente bien. Las reglas del laboratorio usan dos: RECONOCIMIENTO (descubrir qué equipos y servicios hay) y ENUMERACION (pedir rutas concretas de la web para ver qué expone, dentro del escaneo del tema 3.2); por ejemplo, para otra ruta: msg:"ENUMERACION ruta /phpmyadmin";.

Después, reinicia Suricata y espera de nuevo a Engine started (Ctrl+C para salir del registro; --since 1m muestra solo el último minuto, para no confundirte con el arranque anterior). Pide otra vez tu directorio de copias y vuelve a resumir:

Windows · PowerShell

docker compose restart suricata
docker compose logs -f --since 1m suricata
docker compose run --rm curl -s -i http://172.28.0.20/<copias>/
py etiquetar.py alertas.txt
Get-Content alertas.txt

macOS / Linux · Terminal

docker compose restart suricata
docker compose logs -f --since 1m suricata
docker compose run --rm curl -s -i http://172.28.0.20/<copias>/
python3 etiquetar.py alertas.txt
cat alertas.txt

Tu alerta tiene que aparecer en alertas.txt. Si Suricata no arranca, el registro dice qué línea no entiende.

Si pides la regla a la IA, comprueba cada palabra clave en la documentación de reglas de Suricata 7 y pruébala antes de darla por buena.

El corrector levanta su propio laboratorio con tu local.rules, repite la portada, robots.txt y /admin/, y después pide tu directorio de copias. Marca fallo si:

  • Falta suricata/local.rules o alertas.txt, o alertas.txt no es la salida de etiquetar.py.
  • Has borrado reglas de la plantilla, o no hay ninguna regla tuya con sid desde 1000100.
  • Suricata no acepta el fichero.
  • Tu regla no salta al pedir tu directorio de copias, o salta también con lo demás.

5Pruébalo en tu equipo

Primero guarda tu trabajo en un commit: las pruebas solo ven lo que está en commits. Lo que escribe Suricata en salidas/ no se sube: ya lo excluye el .gitignore de la plantilla.

cd ~/hacking-etico/entregas-<tu-usuario>
git add ra1/u4-e2
git commit -m "feat(ra1-u4-e2): regla de Suricata para las copias expuestas"

Después, con Docker Desktop en marcha, pasa las mismas comprobaciones que el corrector:

Windows · PowerShell

py ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u4-e2

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/01-hacking-etico/pruebas.py u4-e2

Montan un laboratorio aparte, igual que el del corrector, y lo quitan al terminar; tardan un par de minutos. Tiene que salir ✓ formato correcto. Cada ✗ dice qué falla: corrige, haz otro commit y repite.

6Sube y mira el corrector

git push

En GitHub, abre tu repositorio y pulsa el icono ✓ o ✗ junto a tu último commit de main. Abre Details en la comprobación Corrector ra1: hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección.

7Etiqueta y apaga

Cuando la fila de U4·E2 salga sin fallos, etiqueta y apaga el laboratorio:

git tag -a entrega-ra1-u4-e2 -m "U4·E2 resuelto"
git push origin entrega-ra1-u4-e2
cd ra1/u4-e2
docker compose down

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta.
