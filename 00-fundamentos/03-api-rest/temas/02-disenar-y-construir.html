Diseñar y construir

Primero se decide qué promete la API, en un contrato. Después se escribe el programa que lo cumple, en el lenguaje que sea. Aquí harás las dos cosas, y el programa, tres veces: en Go, en Python y en Node. Si las tres responden igual, has entendido que una API REST es HTTP y nada más.

Antes: API 1 · REST es HTTPEjercicios: E2, E3, E4 y E5

Palabras de este tema

Contrato
La descripción de lo que la API promete: rutas, métodos, datos de entrada y salida, códigos. Es lo único que ve un cliente.
OpenAPI
El formato estándar para escribir ese contrato, en YAML. Lo leen personas, editores y herramientas de pruebas.
Enrutador
La parte del servidor que mira el método y la ruta de cada petición y decide qué función la atiende.
Manejador
La función que atiende una ruta: lee la petición y escribe la respuesta. En inglés, handler.
Framework
Una biblioteca que da hecho el enrutador y otras piezas: FastAPI en Python, Express en Node. En Go basta la biblioteca estándar.
Caja negra
Probar algo solo por lo que hace desde fuera, sin mirar dentro. Así prueban tu API el corrector y cualquier cliente.

Primero, el contrato

Antes de escribir una línea de código se decide qué rutas tendrá la API, qué hará cada método y qué responderá en cada caso, también en los errores. Así el equipo que hace la web, el que hace la app y el que hace la API pueden trabajar a la vez, y cualquier cambio se discute sobre el contrato y no sobre el código.

El contrato se escribe en OpenAPI. Esta es una operación del contrato del curso:

paths:
  /api/v1/incidencias/{id}:
    get:
      summary: Leer una incidencia
      parameters:
        - { name: id, in: path, required: true, schema: { type: integer } }
      responses:
        "200":
          description: La incidencia
          content:
            application/json:
              schema: { $ref: "#/components/schemas/Incidencia" }
        "404":
          description: No existe

Para verlo como documentación, pega el fichero en editor.swagger.io o instala en VS Code la extensión OpenAPI (Swagger) Editor. Las dos señalan los errores de formato.

Reglas de diseño

Son las que siguen las guías públicas de empresas con cientos de APIs, como las de Zalando y Microsoft, y las que comprueba el corrector del E2:

ReglaBienMal
Las rutas son nombres de recursos, en plural/api/v1/incidencias/api/v1/incidencia
Sin verbos: la acción la dice el métodoPATCH /api/v1/incidencias/7POST /api/v1/cerrarIncidencia
Lo que pertenece a un recurso cuelga de él/api/v1/incidencias/7/comentarios/api/v1/comentarios?incidencia=7
La versión va en la ruta/api/v1/…cambiar la API sin avisar
Crear responde 201 y Location201 Created200 OK sin decir dónde quedó
Borrar responde 204 sin cuerpo204 No Content200 {"ok": true}
Cada operación declara sus errores404, 422…solo el caso feliz
Un GET nunca cambia nada ni lleva cuerpoGET /api/v1/incidenciasGET /api/v1/incidencias/7/borrar

Cada lenguaje trae su forma de instalar dependencias: Go las baja solo al compilar, Python usa pip dentro de un entorno virtual y Node usa npm. Ninguna se sube al repositorio: el .gitignore de cada esqueleto deja fuera .venv/ y node_modules/.

Qué hace cualquier servidor HTTP

Da igual el lenguaje: todo servidor de una API hace estos cuatro pasos con cada petición. El framework solo te ahorra escribir los dos primeros.

La misma API en tres lenguajes

Elige un lenguaje y todos los bloques de código de la página cambian a él. Compara: cambia la forma de escribirlo, no lo que viaja.

Leer una incidencia

// Desde Go 1.22 el patrón lleva el método y {id} se lee con PathValue.
mux.HandleFunc("GET /api/v1/incidencias/{id}", func(w http.ResponseWriter, r *http.Request) {
	id, err := strconv.Atoi(r.PathValue("id"))
	mu.Lock()
	defer mu.Unlock()
	for _, inc := range datos.Incidencias {
		if err == nil && inc.ID == id {
			responder(w, http.StatusOK, inc)
			return
		}
	}
	responder(w, http.StatusNotFound, map[string]string{"error": "no existe"})
})
# id se declara como texto: si fuese int, FastAPI respondería 422 a /incidencias/abc
# y el contrato dice 404, porque esa ruta no existe.
@app.get("/api/v1/incidencias/{id}")
def leer(id: str):
    if not id.isdigit() or int(id) not in incidencias:
        return responder(404, {"error": "no existe"})
    return responder(200, incidencias[int(id)])
// Number("abc") es NaN, que no está en el Map: sale 404 sin hacer nada más.
app.get("/api/v1/incidencias/:id", (req, res) => {
  const inc = incidencias.get(Number(req.params.id));
  if (!inc) return responder(res, 404, { error: "no existe" });
  responder(res, 200, inc);
});

Crear una incidencia

mux.HandleFunc("POST /api/v1/incidencias", func(w http.ResponseWriter, r *http.Request) {
	nueva := Incidencia{Estado: "abierta"}  // lo que no venga en el JSON, por defecto
	if err := json.NewDecoder(r.Body).Decode(&nueva); err != nil {
		responder(w, http.StatusBadRequest, map[string]string{"error": "JSON no válido"})
		return
	}
	mu.Lock()
	defer mu.Unlock()
	nueva.ID = siguiente
	siguiente++
	datos.Incidencias = append(datos.Incidencias, nueva)
	w.Header().Set("Location", fmt.Sprintf("/api/v1/incidencias/%d", nueva.ID))
	responder(w, http.StatusCreated, nueva)
})
from fastapi import Request

@app.post("/api/v1/incidencias")
async def crear(request: Request):
    global siguiente
    try:
        cuerpo = await request.json()
    except ValueError:
        return responder(400, {"error": "JSON no válido"})
    nueva = {"id": siguiente, "estado": "abierta", "tecnico": None, **cuerpo}
    incidencias[siguiente] = nueva
    siguiente += 1
    respuesta = responder(201, nueva)
    respuesta.headers["Location"] = f"/api/v1/incidencias/{nueva['id']}"
    return respuesta
app.post("/api/v1/incidencias", (req, res) => {
  const nueva = { id: siguiente++, estado: "abierta", tecnico: null, ...req.body };
  incidencias.set(nueva.id, nueva);
  res.location(`/api/v1/incidencias/${nueva.id}`);
  responder(res, 201, nueva);
});

Los tres ejemplos cumplen el contrato en el caso feliz. Fíjate en lo que cada uno resuelve a su manera: en Go, varias peticiones llegan a la vez y los datos compartidos se protegen con un sync.Mutex (mu); en Python, los valores por defecto se ponen antes de lo recibido; en Node, express.json() ya ha leído el cuerpo. Validar lo recibido llega en API 3.

Lo que hace cada framework sin pedírselo

Un cliente no sabe en qué lenguaje está la API: solo ve lo que responde. Estas costumbres de cada uno hacen que tres APIs «iguales» no lo sean. En el E5 tendrás que igualarlas.

SituaciónGo net/httpFastAPIExpress 5Contrato
Ruta que no existe404 en texto plano404 en JSON {"detail": …}404 en HTML404 en JSON
Método no admitido405 con Allow, en texto405 en JSON, con un Allow que solo lista los métodos de una de las rutas404405 con Allow
Id que no es un númerolo que hagas tú422 si lo declaras intlo que hagas tú404

Cabeceras extraningunaserver: uvicornX-Powered-By: Expressninguna que diga la tecnología

La buena práctica es la misma en los tres: manda el contrato, no el framework. Cuando el comportamiento de serie no coincide, se cambia.

Empaquetar con Docker

El corrector arranca tu API como la arrancaría cualquier servidor: construye su imagen y la ejecuta. Cada esqueleto trae un Dockerfile a medias que completas con lo visto en Docker 2.

# Dos etapas: se compila con la imagen de Go y solo el binario pasa a la final.
FROM golang:1.24-alpine AS compilar
WORKDIR /src
COPY go.mod ./
COPY *.go ./
RUN CGO_ENABLED=0 go build -o /api .

FROM alpine:3.21
WORKDIR /app
COPY --from=compilar /api ./api
COPY incidencias.json ./
USER nobody
EXPOSE 8000
ENTRYPOINT ["./api"]
FROM python:3.12-alpine
WORKDIR /app
COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt
COPY main.py incidencias.json ./
USER nobody
EXPOSE 8000
ENTRYPOINT ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
FROM node:22-alpine
WORKDIR /app
COPY package.json ./
RUN npm install --omit=dev
COPY main.js incidencias.json ./
USER node
EXPOSE 8000
ENTRYPOINT ["node", "main.js"]
docker build -t api-incidencias:e3 .
docker run -d --rm --name api -p 8000:8000 api-incidencias:e3
curl -i http://localhost:8000/api/v1/salud
docker stop api

Dentro del contenedor la API tiene que escuchar en todas las interfaces (0.0.0.0), no solo en localhost: si no, el puerto publicado no llega (Docker 3). Go y Express ya lo hacen; uvicorn hay que pedírselo con --host 0.0.0.0.

Regla de la IA

La IA traduce bien código de un lenguaje a otro, y es útil en el E5. Pero traduce también las costumbres del framework de destino: pasa pruebas.py a lo que te proponga antes de darlo por bueno.

Comprobación

  • Escribes en OpenAPI una operación con su ruta, su método, sus datos y todas sus respuestas
  • Corriges una ruta que incumple las reglas de diseño y explicas por qué
  • Arrancas un proyecto en Go, en Python y en Node, y sabes dónde está su enrutador y su manejador
  • Sabes qué responde cada framework de serie a una ruta que no existe, y cómo hacer que cumpla el contrato
  • Construyes la imagen de tu API y la pruebas con pruebas.py
