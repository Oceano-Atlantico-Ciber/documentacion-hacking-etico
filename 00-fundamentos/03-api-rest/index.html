Hacking ético · Fundamentos

03 · API REST

HTTP en crudo, diseñar un contrato, implementarlo en Go, Python y Node y defenderlo. Cuatro temas y ocho ejercicios.

Temas

API 1 · REST es HTTPEl mensaje HTTP en crudo, la URL, qué añade REST, JSON, métodos, códigos, cabeceras y curl, con una API simulada. API 2 · Diseñar y construirEl contrato en OpenAPI y sus reglas de diseño; la misma API en Go, Python y Node, en Docker y probada desde fuera. API 3 · Buenas prácticasValidación y errores en problem+json, paginación con cursor, caché con ETag y cambios que no se pisan con If-Match. API 4 · SeguridadLa OWASP API Security Top 10: autenticación, BOLA, asignación masiva, BFLA, límites y no delatar la tecnología.

Ejercicios

Antes de empezar: Docker Desktop en marcha y Go, Python y Node instalados, como explica API 2.

Las órdenes de los ejercicios cuentan con que tienes dos repositorios uno al lado del otro, dentro de ~/hacking-etico/ (~ es tu carpeta personal, también en PowerShell), como se montó en Primer commit:

hacking-etico/
├── documentacion-hacking-etico/   el material del curso: preparar.py, plantillas y pruebas
└── entregas-<tu-usuario>/         tu repositorio: aquí trabajas y entregas

Desde tu repositorio llegan al material con ../documentacion-hacking-etico/. Si no tienes esa carpeta, clónala; esta orden es la misma en todos los sistemas y crea hacking-etico/ si no existe:

cd ~
git clone https://github.com/Oceano-Atlantico-Ciber/documentacion-hacking-etico.git hacking-etico/documentacion-hacking-etico

Si ya la tienes, tráete la última versión antes de cada ejercicio, porque las plantillas y las pruebas se corrigen durante el curso:

cd ~/hacking-etico/documentacion-hacking-etico
git pull

Tu repositorio entregas-<tu-usuario> tiene que estar también en ~/hacking-etico/; si lo tienes en otro sitio, muévelo ahí o clónalo de nuevo.

Ocho ejercicios en fundamentos/api/ de tu repositorio de entregas, todos en main. Cada uno trabaja una buena práctica de HTTP y parte del anterior: en el E3 programas la API de incidencias en el lenguaje que prefieras, en el E5 la escribes en los otros dos y desde ahí sigues con las tres a la vez. Todos empiezan con preparar.py, que escribe los ficheros de partida con datos generados para tu usuario de GitHub. Ejecútalo desde tu repositorio, en la terminal de tu sistema:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/preparar.py e1

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/preparar.py e1

Cuando una orden cambia según el sistema, la unidad la da en dos bloques seguidos: Windows · PowerShell y macOS / Linux · Terminal. En Windows, Python se llama py y curl se escribe curl.exe; en macOS y Linux, python3 y curl. Las órdenes que no cambian, como docker o git, van en un solo bloque.

Desde el E3, cada carpeta de lenguaje trae pruebas.py: las pruebas de caja negra del contrato, que hablan con tu API solo por HTTP. Pásalas antes de etiquetar; el corrector pasa las mismas y alguna más. Cada ejercicio se entrega con su etiqueta anotada, entrega-fundamentos-api-eN, sobre main.
