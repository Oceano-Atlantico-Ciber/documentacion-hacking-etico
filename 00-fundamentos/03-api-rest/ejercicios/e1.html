E1 · HTTP a mano

Escribe dos peticiones HTTP en un fichero de texto, mándalas a una API por una conexión sin más y comprueba que recibes lo mismo que con curl.

Teoría
API 1 · REST es HTTP
Aprendes
Que una API REST no es más que texto HTTP, y a leer y escribir ese texto.
Buena práctica
Entender el mensaje antes que la herramienta.

Qué entregas

Siete ficheros en fundamentos/api/e1/, con estos nombres exactos. Los que escribes tú son tres; los otros cuatro los genera una orden.

FicheroQué llevaLo haces

Los ejemplos de esta página son para un alumno cuya incidencia es la 11. La tuya es otra: la dice LEEME.md.

Cuando una orden cambia según el sistema, va en dos bloques seguidos: usa solo el tuyo. En Windows se trabaja en PowerShell, Python se llama py y curl se escribe curl.exe (curl a secas es otra orden de PowerShell); en macOS y Linux, en la Terminal, con python3 y curl.

1Prepara el laboratorio

Con Docker Desktop en marcha, abre la terminal y ejecuta, cambiando <tu-usuario> por tu usuario de GitHub:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/preparar.py e1
cd fundamentos/api/e1
[Console]::OutputEncoding = [Text.Encoding]::UTF8
curl.exe -i http://localhost:8080/api/v1/incidencias

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/preparar.py e1
cd fundamentos/api/e1
curl -i http://localhost:8080/api/v1/incidencias

preparar.py construye y arranca la API de incidencias del laboratorio en http://localhost:8080, con datos generados para tu usuario, y deja en fundamentos/api/e1/ los ficheros enviar.py y LEEME.md y la carpeta laboratorio/. Al terminar escribe una línea como esta, con tu número:

La API del laboratorio escucha en http://localhost:8080. Tu incidencia es la 11.

El curl -i del final tiene que responder HTTP/1.1 200 OK y una lista en JSON. Si preparar.py terminó con un error de docker (Docker Desktop no estaba en marcha), los ficheros ya están escritos y repetirlo solo dice que e1 ya está preparado. Arranca Docker Desktop y levanta tú el laboratorio desde fundamentos/api/e1/, en cualquier sistema:

docker build -t api-incidencias:e1 laboratorio
docker run -d --name api-e1 -p 8080:8080 api-incidencias:e1

Tu número de incidencia también está en LEEME.md.

En Windows, la línea de [Console]::OutputEncoding hace que PowerShell muestre y guarde bien las tildes de las respuestas; vale para esa ventana, así que repítela si abres otra. Todas las órdenes que siguen se lanzan desde esta carpeta, fundamentos/api/e1/.

2Escribe la petición que lee tu incidencia

code peticion-get.txt

Se abre en Visual Studio Code un fichero nuevo en la carpeta e1/. (En macOS, si la terminal no encuentra code, en VS Code pulsa Cmd+Shift+P y ejecuta Shell Command: Install 'code' command in PATH.) El fichero tiene tres líneas: la línea de petición (método, ruta de tu incidencia y versión), la cabecera Host y una línea en blanco que cierra las cabeceras. Nada más: ni la URL completa, ni comillas, ni comentarios. Para la incidencia 11 queda así (la tercera línea está vacía):

GET /api/v1/incidencias/11 HTTP/1.1
Host: localhost:8080

Ojo con el final: escribe la línea Host y pulsa Enter dos veces. La primera termina la línea Host; la segunda termina la línea vacía. El cursor tiene que quedar en la línea 4, vacía. Si solo pulsas una, falta la línea en blanco y enviar.py avisa «no hay línea en blanco».

Guárdalo en UTF-8 sin BOM, que es lo que hace VS Code: en la barra de estado, abajo a la derecha, tiene que poner UTF-8. Si pone UTF-8 with BOM, haz clic ahí, elige Save with Encoding y después UTF-8. No lo escribas con el Bloc de notas ni con Set-Content -Encoding UTF8: añaden al principio tres bytes invisibles (la BOM) que viajan delante de GET, y la API no reconoce el método: responde 501 Unsupported method. Para comprobar las dos cosas a la vez, mira los bytes del fichero:

Windows · PowerShell

Format-Hex peticion-get.txt

macOS / Linux · Terminal

od -c peticion-get.txt

Tiene que empezar por 47 45 54 (G E T), no por EF BB BF (la BOM). Y tiene que acabar en dos saltos de línea seguidos: 0D 0A 0D 0A en Windows, \n \n en macOS o Linux. Si tu petición es la del ejemplo, en Windows son 61 bytes y la última fila empieza por 00000030.

Envíala y deja la respuesta en su fichero:

Windows · PowerShell

py enviar.py peticion-get.txt | Tee-Object respuesta-get.txt

macOS / Linux · Terminal

python3 enviar.py peticion-get.txt | tee respuesta-get.txt

Tee-Object y tee hacen lo mismo: enseñan la salida en pantalla y la guardan en el fichero. Si repites el envío, el fichero se sobrescribe. Según la configuración de tu PowerShell, Tee-Object lo guarda en UTF-16 o en UTF-8; da igual, el corrector lee UTF-8, con BOM o sin ella, y UTF-16.

enviar.py abre una conexión TCP, escribe el fichero tal cual (solo cambia los saltos de línea por \r\n) y enseña lo que vuelve. Es lo que hace cualquier cliente HTTP. Una respuesta válida empieza por 200 OK y trae en el cuerpo tu número de incidencia:

--- Enviando 61 bytes a localhost:8080 ---
GET /api/v1/incidencias/11 HTTP/1.1
Host: localhost:8080

--- Respuesta ---
HTTP/1.1 200 OK
Server: BaseHTTP/0.6 Python/3.13.14
Date: Tue, 17 Nov 2026 19:52:03 GMT
Content-Type: application/json
Content-Length: 114

{"id": 11, "titulo": "Cambio de puesto (recepción)", "prioridad": "baja", "estado": "abierta", "tecnico": "ivan"}

Si sale 404, la ruta no es la de tu incidencia. Si antes de la respuesta sale «Aviso: no hay línea en blanco», falta la segunda Enter del final: enviar.py la añade por ti para que veas la respuesta, pero el fichero no es una petición completa. Corrígelo y vuelve a enviarlo. Si sale 501 Unsupported method, el fichero tiene BOM: vuelve a guardarlo en UTF-8.

3Escribe la petición que crea una incidencia

code peticion-post.txt

Crea el fichero igual que el anterior, en UTF-8 sin BOM. Una incidencia nueva con un título tuyo y prioridad baja. Lleva, por este orden: la línea POST a la colección, tres cabeceras (Host, Content-Type: application/json y Content-Length), la línea en blanco y el JSON en una sola línea. Por ejemplo:

POST /api/v1/incidencias HTTP/1.1
Host: localhost:8080
Content-Type: application/json
Content-Length: 64

{"titulo": "Monitor del aula 3 sin señal", "prioridad": "baja"}

Content-Length son los bytes del JSON, no las letras: ese cuerpo tiene 63 caracteres, pero la ñ ocupa dos bytes, así que son 64. Cada tilde o ñ suma uno más. Para contarlos sin equivocarte, copia tu JSON entre las comillas simples de esta orden; responde con un número, el que va en Content-Length:

Windows · PowerShell

[Text.Encoding]::UTF8.GetByteCount('{"titulo": "Monitor del aula 3 sin señal", "prioridad": "baja"}')

macOS / Linux · Terminal

printf '%s' '{"titulo": "Monitor del aula 3 sin señal", "prioridad": "baja"}' | wc -c

Guarda el fichero y envíalo:

Windows · PowerShell

py enviar.py peticion-post.txt | Tee-Object respuesta-post.txt

macOS / Linux · Terminal

python3 enviar.py peticion-post.txt | tee respuesta-post.txt

Una respuesta válida es 201 Created con la cabecera Location, que dice dónde ha quedado la incidencia nueva:

--- Respuesta ---
HTTP/1.1 201 Created
Server: BaseHTTP/0.6 Python/3.13.14
Date: Tue, 17 Nov 2026 19:52:03 GMT
Location: /api/v1/incidencias/13
Content-Type: application/json
Content-Length: 112

{"id": 13, "titulo": "Monitor del aula 3 sin señal", "prioridad": "baja", "estado": "abierta", "tecnico": null}

Si se queda esperando cinco segundos, Content-Length dice más bytes de los que hay; si responde 400, el JSON no está bien o dice menos. Prueba a propósito un Content-Length erróneo para ver qué pasa, y deja al final en respuesta-post.txt la salida del envío bueno.

4Lo mismo con curl

Primero escribe el cuerpo del alta en un fichero, alta.json, con el mismo JSON del paso 3. Va en un fichero porque Windows PowerShell quita las comillas dobles de un JSON escrito en la propia orden; así la orden es la misma en todos los sistemas. Si tu JSON es otro, cámbialo dentro de las comillas simples:

Windows · PowerShell

New-Item alta.json -Force -Value '{"titulo": "Monitor del aula 3 sin señal", "prioridad": "baja"}'

macOS / Linux · Terminal

echo '{"titulo": "Monitor del aula 3 sin señal", "prioridad": "baja"}' > alta.json

New-Item enseña el fichero que ha creado; -Force lo sobrescribe si ya existía. Escribe el texto en UTF-8 sin marca de orden de bytes (BOM), que es lo que espera la API: no lo crees con Set-Content ni con >, que en Windows PowerShell guardan con otra codificación.

Después las dos peticiones. Cambia el 11 por tu incidencia:

Windows · PowerShell

curl.exe -v --stderr curl-get.txt http://localhost:8080/api/v1/incidencias/11
curl.exe -v --stderr curl-post.txt -H "Content-Type: application/json" --data-binary "@alta.json" http://localhost:8080/api/v1/incidencias

macOS / Linux · Terminal

curl -v --stderr curl-get.txt http://localhost:8080/api/v1/incidencias/11
curl -v --stderr curl-post.txt -H "Content-Type: application/json" --data-binary "@alta.json" http://localhost:8080/api/v1/incidencias

-v enseña la conversación entera y --stderr la guarda en el fichero; en pantalla solo ves el cuerpo de la respuesta. --data-binary "@alta.json" manda el fichero tal cual como cuerpo y, por llevar cuerpo, curl ya usa POST. En el fichero, las líneas con > son lo que envió curl y las de <, lo que respondió la API. Para verlas sin el resto:

Windows · PowerShell

Select-String -Path curl-get.txt, curl-post.txt -Pattern '^[<>] '

macOS / Linux · Terminal

grep '^[<>] ' curl-get.txt curl-post.txt

curl-get.txt tiene que contener estas líneas, con tu número:

> GET /api/v1/incidencias/11 HTTP/1.1
> Host: localhost:8080
> User-Agent: curl/8.21.0
> Accept: */*
>
< HTTP/1.1 200 OK
< Server: BaseHTTP/0.6 Python/3.13.14

Y curl-post.txt, una línea > POST /api/v1/incidencias HTTP/1.1 y otra < HTTP/1.1 201 Created.

5Compara

code comparacion.md

Tres apartados, cada uno con su título ## y dos o tres frases tuyas:

  • Qué añade curl. Las cabeceras que envía curl y no escribiste tú (míralas en las líneas >), y para qué sirve cada una.
  • Qué es igual. Por qué la respuesta es la misma con tu fichero y con curl.
  • Qué cuenta el servidor. Qué dice la cabecera Server y por qué no debería decirlo (API 4).

El esqueleto, para que veas la forma; el contenido lo escribes tú:

## Qué añade curl

Yo solo escribí Host. curl añade User-Agent: … y Accept: …, que sirven para …

## Qué es igual

## Qué cuenta el servidor

La cabecera Server dice … Eso le dice a un atacante …

El corrector marca fallo si:

  • Falta alguno de los siete ficheros de la tabla, o tiene otro nombre.
  • peticion-get.txt no es una petición HTTP válida o no lee tu incidencia.
  • peticion-post.txt no crea una incidencia con 201: método, cabeceras, Content-Length o JSON incorrectos.
  • respuesta-get.txt o respuesta-post.txt no son la salida de enviar.py con un 200 de tu incidencia y un 201 con Location.
  • curl-get.txt o curl-post.txt no son la salida de curl -v, con sus líneas > y <.
  • comparacion.md no tiene los tres apartados con título o no habla de la cabecera Server.
