Qué entregas

La carpeta fundamentos/api/e3/ con tu API funcionando. El corrector construye la imagen con tu Dockerfile, la arranca y le pasa pruebas.py e3 desde fuera, por HTTP. Lo que cambias tú:

FicheroQué lleva
main.go, main.py o main.jsLas tres rutas de lectura programadas, en los sitios marcados con E3:.
DockerfileCompleto: construye, copia incidencias.json, usa un usuario que no es root, escucha en el 8000 y arranca la API.

El resto lo deja preparar.py y se sube sin tocar: lenguaje.txt (dice go, python o node), incidencias.json, contrato.yaml, pruebas.py y los ficheros de proyecto (go.mod, requirements.txt o package.json).

1Elige lenguaje y prepara el escenario

Empieza por el que te resulte más cómodo: los otros dos llegan en el E5. Con Go, Python y Node instalados (API 2), en la terminal:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/preparar.py e3 --lenguaje go
cd fundamentos/api/e3

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/preparar.py e3 --lenguaje go
cd fundamentos/api/e3

Cambia go por python o node si eliges otro. Deja un proyecto que ya arranca y responde en /api/v1/salud, tus datos en incidencias.json, el contrato de referencia en contrato.yaml, pruebas.py y un Dockerfile a medias. Arráncalo desde fundamentos/api/e3/ con las órdenes de tu lenguaje y déjalo en marcha en esa pestaña de la terminal: mientras la API esté arrancada, esa pestaña no acepta más órdenes.

Go, en cualquier sistema:

go run .

Node, en cualquier sistema (npm install solo hace falta la primera vez):

npm install
node --watch main.js

Los dos escriben Escuchando en http://localhost:8000 cuando están listos.

Python: la primera vez crea el entorno virtual .venv e instala en él las dependencias; las siguientes, basta la última orden:

Windows · PowerShell

py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn main:app --port 8000 --reload

macOS / Linux · Terminal

python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn main:app --port 8000 --reload

Está listo cuando escribe Uvicorn running on http://127.0.0.1:8000. Se llama al Python de dentro de .venv por su ruta, así que no hace falta activar el entorno. En Debian o Ubuntu, si python3 -m venv dice que falta ensurepip, instala antes el paquete python3-venv (sudo apt install python3-venv).

Para pararla, Ctrl+C en su pestaña. Abre otra pestaña de la terminal, ve a la misma carpeta fundamentos/api/e3/ y comprueba que responde:

Windows · PowerShell

curl.exe -i http://localhost:8000/api/v1/salud

macOS / Linux · Terminal

curl -i http://localhost:8000/api/v1/salud
HTTP/1.1 200 OK
Content-Type: application/json
…

{"estado": "ok"}

2Programa las tres lecturas

Están marcadas en el código con E3:. Lo que dice el contrato:

  • GET /api/v1/incidencias devuelve {"datos": [todas, ordenadas por id], "siguiente": null}.
  • GET /api/v1/incidencias/{id} devuelve la incidencia tal cual, o 404 en JSON si no existe. También si el id no es un número.
  • GET /api/v1/incidencias/{id}/comentarios devuelve {"datos": [sus comentarios], "siguiente": null}, o 404 si la incidencia no existe.

Todas con Content-Type: application/json. Usa la función responder del esqueleto. Así se ven bien, con tus datos en lugar de estos:

Windows · PowerShell

curl.exe -i http://localhost:8000/api/v1/incidencias/1
curl.exe -i http://localhost:8000/api/v1/incidencias/abc

macOS / Linux · Terminal

curl -i http://localhost:8000/api/v1/incidencias/1
curl -i http://localhost:8000/api/v1/incidencias/abc
HTTP/1.1 200 OK
Content-Type: application/json

{"id": 1, "titulo": "No arranca el portátil (planta 3)", "prioridad": "media", "estado": "abierta", "tecnico": "noa"}

HTTP/1.1 404 Not Found
Content-Type: application/json

{… un JSON que diga que no existe …}

La incidencia tiene que salir con los mismos campos y valores que en incidencias.json: ni uno de más, ni uno cambiado. El orden de los campos y los espacios dan igual.

3Pruébalo desde fuera

Las pruebas leen tu incidencias.json para saber qué esperar, así que se lanzan desde fundamentos/api/e3/. Con la API recién arrancada (si ya la has usado, Ctrl+C y arráncala otra vez), en la otra pestaña:

Windows · PowerShell

py pruebas.py e3 http://localhost:8000

macOS / Linux · Terminal

python3 pruebas.py e3 http://localhost:8000

Está bien cuando todas salen en ✓ y la última línea dice 0 mal:

E3 · Lectura
  ✓ GET /api/v1/salud responde 200 {"estado": "ok"}
  ✓ La lista es JSON con Content-Type application/json
  …
  ✓ Los comentarios de una incidencia que no existe dan 404

8 bien, 0 mal

Si una prueba falla, repite con curl -i la petición que hace y compara con el contrato.

4Completa el Dockerfile

Los comentarios del Dockerfile dicen qué falta. Para la API que arrancaste en el paso 1 (Ctrl+C en su pestaña), porque el contenedor usa el mismo puerto, el 8000. Con Docker Desktop en marcha y desde fundamentos/api/e3/, construye la imagen, arráncala y pasa las pruebas contra el contenedor:

Windows · PowerShell

docker build -t api-incidencias:e3 .
docker image inspect api-incidencias:e3 --format "usuario: {{.Config.User}}"
docker run -d --rm --name api -p 8000:8000 api-incidencias:e3
py pruebas.py e3 http://localhost:8000
docker stop api

macOS / Linux · Terminal

docker build -t api-incidencias:e3 .
docker image inspect api-incidencias:e3 --format "usuario: {{.Config.User}}"
docker run -d --rm --name api -p 8000:8000 api-incidencias:e3
python3 pruebas.py e3 http://localhost:8000
docker stop api

La segunda orden tiene que decir un usuario, por ejemplo usuario: app. Si sale usuario: vacío o root, falta la línea USER. Las pruebas, otra vez 0 mal.

El corrector marca fallo si:

  • El Dockerfile no construye, la imagen no escucha en el 8000 o se ejecuta como root.
  • Alguna prueba de pruebas.py e3 sale en ✗ contra la imagen.
  • lenguaje.txt no dice el lenguaje del proyecto.

Súbelo con lo demás, no estorba: apunta las versiones exactas que instalaste. Ni el Dockerfile de la plantilla (copia solo package.json) ni el corrector lo usan.
