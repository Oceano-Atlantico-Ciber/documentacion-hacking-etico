1Elige lenguaje y prepara el escenario

Empieza por el que te resulte más cómodo: los otros dos llegan en el E5. Con Go, Python y Node instalados (API 2):

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/preparar.py e3 --lenguaje go
cd fundamentos/api/e3

Cambia go por python o node si eliges otro. Deja un proyecto que ya arranca y responde en /api/v1/salud, tus datos en incidencias.json, el contrato de referencia en contrato.yaml, pruebas.py y un Dockerfile a medias. Arráncalo como explica la cabecera de main.go, main.py o main.js, y comprueba:

curl -i http://localhost:8000/api/v1/salud

2Programa las tres lecturas

Están marcadas en el código con E3:. Lo que dice el contrato:

  • GET /api/v1/incidencias devuelve {"datos": [todas, ordenadas por id], "siguiente": null}.
  • GET /api/v1/incidencias/{id} devuelve la incidencia tal cual, o 404 en JSON si no existe. También si el id no es un número.
  • GET /api/v1/incidencias/{id}/comentarios devuelve {"datos": [sus comentarios], "siguiente": null}, o 404 si la incidencia no existe.

Todas con Content-Type: application/json. Usa la función responder del esqueleto.

3Pruébalo desde fuera

Con la API recién arrancada, en otra pestaña de Git Bash:

py pruebas.py e3 http://localhost:8000

Si una prueba falla, repite con curl -i la petición que hace y compara con el contrato.

4Completa el Dockerfile

Los comentarios del Dockerfile dicen qué falta. Construye, arranca y vuelve a pasar las pruebas, ahora contra el contenedor:

docker build -t api-incidencias:e3 .
docker run -d --rm --name api -p 8000:8000 api-incidencias:e3
py pruebas.py e3 http://localhost:8000
docker stop api

El corrector marca fallo si:

  • El Dockerfile no construye, la imagen no escucha en el 8000 o se ejecuta como root.
  • Alguna prueba de py pruebas.py e3 sale en ✗ contra la imagen.
  • lenguaje.txt no dice el lenguaje del proyecto.

5Sube y etiqueta

git add .
git commit -m "feat(api-e3): rutas de lectura de la API de incidencias"
git push
git tag -a entrega-fundamentos-api-e3 -m "E3 resuelto"
git push origin entrega-fundamentos-api-e3

Comprueba con git status antes del commit que no subes node_modules/ ni .venv/: el .gitignore del esqueleto ya los deja fuera.
