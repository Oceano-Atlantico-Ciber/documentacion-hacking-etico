E6 · Errores que ayudan

Haz que tus tres APIs validen lo que reciben y respondan todos los errores en el mismo formato, sin dejar escapar nada de cómo están hechas.

Teoría
API 3 · Buenas prácticas
Aprendes
A validar contra el contrato y a controlar los errores que el framework genera solo.
Buena práctica
400 frente a 422, application/problem+json, ninguna traza.
Trabajas en
fundamentos/api/e6/, con sus tres carpetas de lenguaje
Etiqueta
entrega-fundamentos-api-e6 sobre main
Plazo
El que anuncie el docente para la unidad

1Prepara el escenario

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/preparar.py e6
cd fundamentos/api/e6

Copia tu E5 a e6/ y añade casos.txt: las peticiones que tus APIs tienen que rechazar, con el código que toca a cada una.

2Antes de tocar nada, mira qué responden hoy

Con las tres APIs arrancadas como en el E5, prueba a mano unos cuantos casos y fíjate en el código, el Content-Type y el cuerpo:

curl.exe -i -X POST http://localhost:8001/api/v1/incidencias -H 'Content-Type: application/json' --data '{"titulo": "Sin cerrar"'
curl.exe -i http://localhost:8003/api/v1/no-existe

Apunta lo que delata cada una: es justo lo que tienes que cambiar.

3Valida y uniforma los errores

  • Un problema por lenguaje, como en API 3, y todos los errores pasan por él: también el 404 de una ruta que no existe y el 405.
  • 400 si el cuerpo no es JSON; 422 si es JSON pero no vale: no es un objeto, falta un campo obligatorio, sobra un campo que el contrato no tiene, un tipo no cuadra, el título está vacío o pasa de 120 caracteres, la prioridad o el estado no son de la lista, o un comentario está vacío o pasa de 500.
  • Ningún caso acaba en 500, ni lleva trazas, rutas de ficheros o nombres de funciones.

4Pruébalo en las tres

py go/pruebas.py e6 http://localhost:8001
py python/pruebas.py e6 http://localhost:8002
py node/pruebas.py e6 http://localhost:8003

Cada orden pasa también las pruebas del E3 y el E4: validar no puede romper lo que ya funcionaba. Reinicia los contenedores entre una pasada y otra.

El corrector marca fallo si:

  • Algún caso de casos.txt, u otro parecido, no da su código en application/problem+json con type, title, status y detail.
  • Algún error filtra una traza, una ruta de fichero o el nombre de una función.
  • Deja de pasar alguna prueba del E3 o el E4, o las tres APIs dejan de responder igual.
