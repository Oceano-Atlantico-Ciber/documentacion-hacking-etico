1Prepara el escenario

En la terminal, cambiando <tu-usuario> por tu usuario de GitHub:

py ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/preparar.py e8

macOS / Linux · Terminal

preparar.py copia tu E7 a e8/ y añade a cada lenguaje usuarios.json: un administrador y dos técnicos, lucia y marcos, con su clave y su token. Son datos de prueba de tu laboratorio, generados para ti; aun así, trátalos como lo que son: no los copies en ningún otro sitio. Sí van en tu repositorio de entregas, porque la imagen los necesita: es tu repositorio privado y son datos de prueba. Añade usuarios.json a la imagen en el Dockerfile de cada lenguaje, junto a incidencias.json.

Mientras programas, construye y arranca las tres como en el E7: Go en el 8001, Python en el 8002 y Node en el 8003. La primera orden para los contenedores del E7, si siguen en marcha. Desde fundamentos/api/e8/, en cualquier sistema:

docker stop e7-go e7-python e7-node
docker build -t api-e8-go go
docker build -t api-e8-python python
docker build -t api-e8-node node
docker run -d --rm --name e8-go -p 8001:8000 api-e8-go
docker run -d --rm --name e8-python -p 8002:8000 api-e8-python
docker run -d --rm --name e8-node -p 8003:8000 api-e8-node

Cada vez que cambies código, docker stop e8-go e8-python e8-node y otra vez las órdenes docker build y docker run.

2¿Quién eres?

  • POST /api/v1/sesiones con {"usuario", "clave"}: 201 y {"token": …} si son buenos; 401 si no.
  • Todas las rutas, salvo /api/v1/salud y /api/v1/sesiones, piden Authorization: Bearer <token>. Sin él o con uno que no existe: 401 con WWW-Authenticate: Bearer. Ninguna otra cabecera sirve para identificarse.
  • GET /api/v1/usuarios/yo devuelve usuario, nombre y rol.

3¿Es tuyo? ¿Puedes?

  • Un técnico solo ve, en la lista y una a una, las incidencias cuyo tecnico es él. Las demás, también sus comentarios, le dan 404. El administrador ve todas (BOLA).
  • Lo que crea un técnico queda a su nombre. Un técnico que intenta crear o reasignar una incidencia para otro recibe 403.
  • PATCH /api/v1/usuarios/yo solo cambia nombre. Si trae rol o cualquier otro campo, 422 y nada cambia (asignación masiva).
  • Borrar incidencias es solo del administrador. Un técnico recibe 403, también con las suyas (BFLA).

4¿Cuántas veces? ¿Qué dices de ti?

  • Tras cinco claves erróneas para un mismo usuario en un minuto, /api/v1/sesiones responde 429 con Retry-After en segundos a ese usuario, aunque la clave sea buena, hasta que pase el minuto.
  • Ninguna respuesta lleva X-Powered-By ni un Server que diga el lenguaje o el framework.

En Python, la cabecera server: uvicorn no la pone tu código, sino uvicorn, el servidor que lo arranca; por eso no se quita desde FastAPI. Uvicorn tiene una opción para no enviarla: búscala en API 4 y ponla en el ENTRYPOINT del Dockerfile, y también en la orden con la que la arrancas en tu equipo si pruebas ahí. En Node, X-Powered-By: Express sí se quita desde el código.

El corrector busca en controles.md cuatro de ellos: CWE-639, CWE-915, CWE-285 y CWE-307. Los otros dos apartados van igual de completos, con su CWE. Un apartado completo:

## Autorización por incidencia, BOLA (API1, CWE-639)

- **Dónde estaría el fallo:** en GET, PUT, PATCH y DELETE de /incidencias/{id}, en sus comentarios y en la lista.
- **Cuál sería:** comprobar que la incidencia existe, pero no de quién es.
- **Qué permitiría:** que un técnico lea o cambie las incidencias de otro cambiando el número de la ruta.
- **Cómo lo impide mi código:** solo devuelve la incidencia si es del técnico o si pide el administrador;
  si no, 404, igual que si no existiera. La lista filtra por técnico.

```
PS> curl.exe -i http://localhost:8001/api/v1/incidencias/1 -H "Authorization: Bearer $LUCIA"
HTTP/1.1 404 Not Found
Content-Type: application/problem+json
…
```

Para no pegar tokens en las órdenes, guárdalos antes en variables de la terminal, sacándolos de tu usuarios.json. Desde fundamentos/api/e8/, en la pestaña donde vayas a lanzar los curl:

Windows · PowerShell

$u = Get-Content go/usuarios.json -Raw | ConvertFrom-Json
$LUCIA = ($u.usuarios | Where-Object usuario -eq lucia).token
$ADMIN = ($u.usuarios | Where-Object usuario -eq admin).token
$LUCIA

macOS / Linux · Terminal

LUCIA=$(python3 -c 'import json; print(next(u["token"] for u in json.load(open("go/usuarios.json"))["usuarios"] if u["usuario"] == "lucia"))')
ADMIN=$(python3 -c 'import json; print(next(u["token"] for u in json.load(open("go/usuarios.json"))["usuarios"] if u["usuario"] == "admin"))')
echo $LUCIA

La última línea enseña el token de lucia: si sale vacía, no estás en e8/ o falta go/usuarios.json. Las variables duran lo que esa pestaña; si abres otra, repítelo. Después, -H "Authorization: Bearer $LUCIA" se escribe igual en PowerShell que en macOS o Linux. Los tokens son datos de prueba de tu laboratorio: en controles.md escribe $LUCIA o $ADMIN, no su valor.

6Pruébalo en las tres

Desde fundamentos/api/e8/, con los tres contenedores recién arrancados:

Windows · PowerShell

py go/pruebas.py e8 http://localhost:8001 http://localhost:8002 http://localhost:8003

macOS / Linux · Terminal

python3 go/pruebas.py e8 http://localhost:8001 http://localhost:8002 http://localhost:8003

A cada API le lanza primero los ataques con los tokens de los técnicos y después repite todas las pruebas anteriores con el token del administrador, igual que el corrector; al final, «Qué arreglar» agrupa los fallos por causa, con el arreglo, la orden para repetirlo y el paso de este enunciado. El bloqueo por intentos dura un minuto: reinicia los contenedores entre pasadas, con docker stop e8-go e8-python e8-node y sus tres docker run del paso 1. Está listo cuando termina en 0 mal.

El corrector marca fallo si:

  • Algún ataque funciona: sin token, con un token inventado o con X-User; ver o cambiar la incidencia de otro; crear o reasignar para otro; borrar sin ser administrador; cambiarse el rol; probar claves sin límite.
  • Alguna respuesta delata el lenguaje o el framework.
  • Con el token de administrador deja de pasar alguna prueba anterior: cerrar una puerta rompiendo la funcionalidad no cuenta.
  • controles.md no tiene las cuatro preguntas para cada control.
