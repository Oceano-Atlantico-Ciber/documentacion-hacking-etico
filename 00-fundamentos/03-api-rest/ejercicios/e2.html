Qué entregas

Un solo fichero: fundamentos/api/e2/contrato.yaml, el contrato OpenAPI 3 que te deja preparar.py, completado con todas las rutas que piden los nueve requisitos. requisitos.md se queda como está. No hay que programar nada.

1Prepara el escenario

En la terminal, cambiando <tu-usuario> por tu usuario de GitHub:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/preparar.py e2
cd fundamentos/api/e2

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/preparar.py e2
cd fundamentos/api/e2

Deja requisitos.md, con lo que necesita el equipo de sistemas, y contrato.yaml con la ruta de salud ya escrita y el principio del esquema Incidencia.

2Lee los requisitos como recursos

Antes de escribir, haz en un papel una tabla con una fila por requisito: qué método sobre qué ruta lo cumple. Primero, qué recursos hay (cosas con datos propios) y cuál cuelga de cuál. Los verbos de los requisitos («cerrar», «borrar las duplicadas») no van en las rutas: cerrar es cambiar el estado. Las dos primeras filas, para que veas la forma:

RequisitoMétodo y rutaResponde bien
1. Ver todas las incidenciasGET /api/v1/incidencias200 con la lista
2. Ver una incidencia concretaGET /api/v1/incidencias/{id}200, o 404 si no existe
3 a 9Las completas tú.

3Completa el contrato

code contrato.yaml

Escribe debajo de # Escribe aquí el resto de rutas. y completa los esquemas. Tiene que quedar:

  • Una ruta por recurso y por elemento, bajo /api/v1/, con la colección en plural.
  • Los cinco métodos (GET, POST, PUT, PATCH, DELETE) donde corresponda.
  • Para cada operación, todas sus respuestas: la buena (200, 201 o 204) y las de error (400, 404, 422…). Toda ruta con {id} declara el 404.
  • Los esquemas de los datos en components/schemas: Incidencia completo, lo que se envía al crear, lo que se envía al cambiar y Comentario.

Así queda una operación completa, la que lee una incidencia. Las demás siguen el mismo patrón:

  /api/v1/incidencias/{id}:
    parameters:
      - { name: id, in: path, required: true, schema: { type: integer } }
    get:
      summary: Ver una incidencia
      responses:
        "200":
          description: La incidencia
          content:
            application/json:
              schema: { $ref: "#/components/schemas/Incidencia" }
        "404":
          description: No existe ninguna incidencia con ese id

Pega el fichero en editor.swagger.io para ver que no tiene errores de formato y cómo queda como documentación.

4Compruébalo

Las pruebas del E2 leen tu contrato y aplican las reglas de diseño. Necesitan la librería PyYAML; la primera orden solo hace falta una vez. Las pruebas se lanzan desde la raíz de tu repositorio, no desde e2/:

Windows · PowerShell

py -m pip install pyyaml
cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/plantillas/pruebas.py e2 fundamentos/api/e2/contrato.yaml

macOS / Linux · Terminal

python3 -m pip install --user pyyaml
cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/03-api-rest/ejercicios/plantillas/pruebas.py e2 fundamentos/api/e2/contrato.yaml

En macOS o Linux, si pip responde externally-managed-environment (Python de Homebrew, Debian o Ubuntu), repite la primera orden añadiendo --break-system-packages al final: instala PyYAML solo para tu usuario. Si en lugar de las pruebas sale Falta PyYAML, la instalación no ha funcionado.

Cada regla sale con ✓ o con ✗ y el motivo. Está listo cuando la última línea dice 0 mal. Un fallo se ve así:

  ✗ Ninguna ruta lleva un verbo: la acción la dice el método  (/api/v1/incidencias/{id}/cerrar)

El corrector marca fallo si:

  • contrato.yaml no es OpenAPI 3 válido.
  • Alguna ruta no empieza por /api/v1/, lleva un verbo o nombra una colección en singular.
  • No usa los cinco métodos, o un GET lleva cuerpo.
  • Un POST que crea no responde 201 o un DELETE no responde 204.
  • Una operación no declara ningún error 4xx, o una ruta con {id} no declara el 404.

A partir del E3 se programa el contrato de referencia del curso, el mismo para todos, para que el corrector pueda probar todas las APIs igual. Compáralo con el tuyo cuando lo recibas: si has seguido las reglas, se parecerán mucho.
