E2 · Tu primera imagen

Empaqueta en una imagen un sondeo de puertos escrito en Python y úsalo contra otro contenedor.

Teoría
Docker 2 · Construir imágenes
Aprendes
A convertir un programa en una imagen que arranca igual en cualquier equipo.
Trabajas en

Etiqueta
entrega-fundamentos-docker-e2 sobre main

Qué entregas

En fundamentos/docker/e2/:

FicheroQué lleva
DockerfileLo escribes tú. Parte de python:3.12-alpine y arranca el contenedor con python sondeo.py mediante ENTRYPOINT, de modo que lo que escribas tras el nombre de la imagen llegue al sondeo como argumentos.
sondeo.txtLo que imprimió el sondeo del paso 4: exactamente tres líneas, una por puerto y en este orden: 22, 80 y 443.
sondeo.pyTal como lo deja preparar.py, sin cambios. Se sube porque tu Dockerfile lo copia.

Cada línea de sondeo.txt tiene la forma equipo:puerto estado, con el estado abierto o cerrado. El equipo es la IP de e2-diana, la que te salga a ti; por ejemplo:

172.17.0.2:22 cerrado
172.17.0.2:80 abierto
172.17.0.2:443 cerrado

1Prepara el escenario

Desde tu repositorio, con Docker Desktop en marcha:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/preparar.py e2
cd fundamentos/docker/e2

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/preparar.py e2
cd fundamentos/docker/e2

Deja sondeo.py, que dice qué puertos TCP de un equipo aceptan conexiones. No hace falta que lo cambies, ni Python en tu equipo: correrá en la imagen. Todas las órdenes que siguen se lanzan desde fundamentos/docker/e2.

2Escribe el Dockerfile

code Dockerfile

El fichero se llama exactamente Dockerfile, sin extensión. Cuatro instrucciones, en este orden: parte de python:3.12-alpine, trabaja en /app, copia sondeo.py y haz que el contenedor arranque con python sondeo.py mediante ENTRYPOINT en forma de lista (["…", "…"]), para que los argumentos de docker run se añadan detrás. La tabla de instrucciones está en Docker 2.

3Construye la imagen

docker build -t sondeo:1.0 .
docker run --rm sondeo:1.0

La construcción acaba sin errores. Sin argumentos, el sondeo muestra cómo se usa: Uso: python sondeo.py EQUIPO PUERTO [PUERTO...]. La etiqueta tiene que ser sondeo:1.0: la reutilizas en E6 y E7.

4Sondea otro contenedor

Arranca un nginx sin publicar puertos, guarda su IP en la red por defecto de Docker y sondéala. El resultado se ve en pantalla y se guarda en sondeo.txt:

Windows · PowerShell

docker run -d --name e2-diana nginx:1.27-alpine
$ip = docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' e2-diana
$ip
docker run --rm sondeo:1.0 $ip 22 80 443 | Tee-Object sondeo.txt
docker rm -f e2-diana

macOS / Linux · Terminal

docker run -d --name e2-diana nginx:1.27-alpine
ip=$(docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' e2-diana)
echo "$ip"
docker run --rm sondeo:1.0 "$ip" 22 80 443 | tee sondeo.txt
docker rm -f e2-diana

La IP es del tipo 172.17.0.2. El 80 sale abierto y los otros dos, cerrado. Si la IP sale vacía, el contenedor aún no estaba listo: vuelve a lanzar desde la línea del inspect. Por IP funciona; por el nombre e2-diana, no. El motivo, en Docker 3.

El corrector marca fallo si:

  • Falta el Dockerfile o sondeo.txt.
  • sondeo.txt no tiene las tres líneas de los puertos 22, 80 y 443, en ese orden, con el 80 abierto y los otros dos cerrados.
  • El Dockerfile no parte de python:3.12-alpine, no construye o la imagen no arranca con el sondeo.
  • Con los argumentos equipo puerto, la imagen no imprime lo mismo que python sondeo.py.

5Pruébalo en tu equipo

Primero guarda tu trabajo en un commit, desde la raíz de tu repositorio: las pruebas solo ven lo que está en commits.

cd ~/hacking-etico/entregas-<tu-usuario>
git add .
git commit -m "feat(docker-e2): imagen del sondeo de puertos"

Después, con Docker Desktop en marcha, pasa las mismas comprobaciones que el corrector. Trabajan sobre una copia de lo que ya está en commits (la etiqueta si existe, si no main) y construyen y levantan contenedores como él.

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/pruebas.py e2

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/pruebas.py e2

Cada ✗ dice qué falla y por qué. Corrige, haz commit y repite hasta que salga ✓ superado. Antes y después de comprobar se quitan los contenedores, redes y volúmenes del laboratorio de este ejercicio, para empezar como en un equipo limpio.

6Sube y etiqueta

git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E2 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e2 -m "E2 resuelto"
git push origin entrega-fundamentos-docker-e2

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. El corrector evalúa siempre lo que haya en la etiqueta.
