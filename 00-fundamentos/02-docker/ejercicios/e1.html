Qué entregas

Tres ficheros en fundamentos/docker/e1/:

FicheroQué lleva
index.htmlLa página que deja preparar.py, sin cambiar nada.
inspect.jsonLa salida de docker container inspect e1-web sacada en el paso 6, es decir, después de parar y volver a arrancar el contenedor. Empieza por [ y dentro tiene "Name": "/e1-web".
logs.txtLa salida de docker logs e1-web, sacada también en el paso 6. Tiene que haber al menos una petición a / respondida con 200 y con el tamaño de tu página.

Una línea de logs.txt que sirve tu página tiene esta forma; el número tras el 200 es lo que mide tu index.html en bytes (el tuyo será otro):

172.17.0.1 - - [12/Nov/2026:10:15:02 +0000] "GET / HTTP/1.1" 200 214 "-" "curl/8.9.1" "-"

Si en todas las líneas ese número es 615, nginx solo sirvió su página de bienvenida: no copiaste tu página antes de pedirla.

1Prepara el escenario

Desde tu repositorio, con Docker Desktop en marcha:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/preparar.py e1
cd fundamentos/docker/e1

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/preparar.py e1
cd fundamentos/docker/e1

Debe decir e1 preparado para <tu-usuario>. Deja en la carpeta index.html, una página con tu usuario. No cambies su contenido. Todas las órdenes que siguen se lanzan desde fundamentos/docker/e1.

2Descarga la imagen y arranca el contenedor

docker pull nginx:1.27-alpine
docker run -d --name e1-web -p 127.0.0.1:8080:80 nginx:1.27-alpine
docker ps

docker ps muestra una fila con el nombre e1-web, la imagen nginx:1.27-alpine, el estado Up y los puertos 127.0.0.1:8080->80/tcp. El nombre tiene que ser exactamente e1-web y el puerto, 127.0.0.1:8080. Si te equivocas, bórralo con docker rm -f e1-web y vuelve a lanzar el docker run.

3Pídele la página

Windows · PowerShell

curl.exe -i http://localhost:8080/

macOS / Linux · Terminal

curl -i http://localhost:8080/

La primera línea es HTTP/1.1 200 OK y el cuerpo es la página de bienvenida de nginx (Welcome to nginx!).

4Cambia la página por la tuya

Copia tu index.html dentro del contenedor y vuelve a pedir la página:

Windows · PowerShell

docker cp index.html e1-web:/usr/share/nginx/html/index.html
curl.exe http://localhost:8080/

macOS / Linux · Terminal

docker cp index.html e1-web:/usr/share/nginx/html/index.html
curl http://localhost:8080/

Ahora responde con tu página, la que dice Puesto de <tu-usuario>. Has cambiado la capa escribible del contenedor, no la imagen. Esta petición es la que tiene que aparecer en logs.txt.

5Páralo y vuelve a arrancarlo

Windows · PowerShell

docker stop e1-web
docker ps -a
docker start e1-web
curl.exe http://localhost:8080/

macOS / Linux · Terminal

docker stop e1-web
docker ps -a
docker start e1-web
curl http://localhost:8080/

Mientras está parado, docker ps -a lo muestra como Exited. Al arrancarlo sigue sirviendo tu página: parar no borra la capa.

6Guarda las pruebas

Con el contenedor otra vez en marcha (después del docker start), guarda lo que Docker sabe de él y su registro:

docker container inspect e1-web > inspect.json
docker logs e1-web > logs.txt

La orden es la misma en todos los sistemas. inspect.json es todo lo que Docker sabe del contenedor: busca en él "StartedAt" y "FinishedAt", y verás que arrancó después de pararse. logs.txt tiene una línea por cada petición que recibió nginx; ábrelo con code logs.txt y comprueba que hay un "GET / HTTP/1.1" 200 con un tamaño distinto de 615.

7Bórralo y comprueba

Windows · PowerShell

docker rm -f e1-web
curl.exe http://localhost:8080/

macOS / Linux · Terminal

docker rm -f e1-web
curl http://localhost:8080/

El último curl falla (no se puede conectar): el contenedor y tu cambio ya no existen. Si lanzaras otro desde la imagen, volvería la página de bienvenida. inspect.json y logs.txt siguen en tu carpeta: son lo que entregas.

El corrector marca fallo si:

  • Falta index.html, inspect.json o logs.txt.
  • index.html ha cambiado.
  • inspect.json no es la salida de docker container inspect e1-web.
  • El contenedor no se llamaba e1-web, no salía de nginx:1.27-alpine o no publicaba 127.0.0.1:8080.
  • El contenedor no llegó a pararse y volver a arrancar.
  • En logs.txt no hay ninguna petición servida con tu página.

8Pruébalo en tu equipo

Antes de subir, con Docker Desktop en marcha, pasa las mismas comprobaciones que el corrector. Trabajan sobre una copia de lo que ya está en commits (la etiqueta si existe, si no main) y construyen y levantan contenedores como él.

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/pruebas.py e1

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/pruebas.py e1

Cada ✗ dice qué falla y por qué. Corrige, haz commit y repite hasta que salga ✓ superado. Antes y después de comprobar se quitan los contenedores, redes y volúmenes del laboratorio de este ejercicio, para empezar como en un equipo limpio.

9Sube y etiqueta

git add .
git commit -m "feat(docker-e1): ciclo de vida de e1-web"
git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E1 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e1 -m "E1 resuelto"
git push origin entrega-fundamentos-docker-e1

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. Cuenta tal como esté al cerrar el plazo; si la mueves después, la entrega queda fuera de plazo.
