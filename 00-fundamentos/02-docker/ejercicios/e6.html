Qué entregas

En fundamentos/docker/e6/, dos ficheros que escribes tú:

FicheroQué lleva
levantar.shCrea la red e6-red y arranca en ella e6-web y e6-datos, con las mismas reglas que el levantar.sh de E5: las tres líneas del principio y después solo órdenes docker, una por línea.
sondeo.txtLo que imprime el sondeo del paso 4: exactamente cuatro líneas, en este orden: e6-web puerto 80, e6-web puerto 443, e6-datos puerto 5432 y e6-datos puerto 80.

Cada línea de sondeo.txt tiene la forma equipo:puerto estado; la primera, por ejemplo, es:

e6-web:80 abierto

1Prepara la carpeta

E6 no tiene ficheros de partida. Desde tu repositorio, crea la carpeta y entra en ella:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
New-Item -ItemType Directory -Force fundamentos/docker/e6 | Out-Null
cd fundamentos/docker/e6

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
mkdir -p fundamentos/docker/e6
cd fundamentos/docker/e6

Necesitas la imagen sondeo:1.0 de E2. Compruébalo con docker image ls sondeo: tiene que salir una fila con la etiqueta 1.0. Si no sale, vuelve a construirla desde fundamentos/docker/e2 con docker build -t sondeo:1.0 .. Todas las órdenes que siguen se lanzan desde fundamentos/docker/e6.

2Escribe levantar.sh

code levantar.sh

Empieza con las mismas tres líneas que en E5:

#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")"

Debajo, una orden docker por línea, que haga en este orden:

  1. Crear la red e6-red.
  2. Arrancar en segundo plano el contenedor e6-web desde nginx:1.27-alpine, en la red e6-red (--network) y publicado en 127.0.0.1:8086 (puerto 80 del contenedor).
  3. Arrancar en segundo plano el contenedor e6-datos desde postgres:16-alpine, en la red e6-red, con la variable POSTGRES_PASSWORD (sin ella Postgres se para nada más arrancar) y sin publicar ningún puerto.

Valen las mismas órdenes y opciones que en E5: completas, sin \, sin variables ni redirecciones, y sin docker rm. Esto es lo que vas a montar:

3Comprueba quién llega a quién

Lanza el script y mira qué puertos publica cada contenedor:

Windows · PowerShell

Get-Content levantar.sh | Where-Object { $_ -match '^\s*docker\s' } | ForEach-Object { Invoke-Expression $_; if ($LASTEXITCODE) { throw "falla: $_" } }
docker port e6-web
docker port e6-datos

macOS / Linux · Terminal

bash levantar.sh
docker port e6-web
docker port e6-datos

En Windows, la primera línea lanza una a una las órdenes docker del script, igual que hace el corrector, que no lo ejecuta con bash. docker port e6-web muestra 80/tcp -> 127.0.0.1:8086 y docker port e6-datos no muestra nada. Ahora pide la web por su nombre desde un contenedor dentro de la red y desde otro fuera de ella (el curl corre dentro del contenedor, así que la orden es la misma en todos los sistemas):

docker run --rm --network e6-red curlimages/curl:8.11.1 -s -o /dev/null -w '%{http_code}\n' http://e6-web/
docker run --rm curlimages/curl:8.11.1 -s -m 3 http://e6-web/

En la primera orden, -o /dev/null descarta la página y -w '%{http_code} ' imprime solo el código de estado. Dentro de la red, curl llega por el nombre e imprime 200. Fuera de ella no imprime nada y acaba con error: el nombre e6-web no existe en la red por defecto.

4Sondea desde dentro de la red

Espera a que Postgres acepte conexiones, sondea los dos contenedores con tu imagen de E2 y guarda las cuatro líneas en sondeo.txt; después quita el laboratorio:

Windows · PowerShell

do { Start-Sleep 1; docker exec e6-datos pg_isready -U postgres -h localhost } until ($LASTEXITCODE -eq 0)
docker run --rm --network e6-red sondeo:1.0 e6-web 80 443 | Tee-Object sondeo.txt
docker run --rm --network e6-red sondeo:1.0 e6-datos 5432 80 | Tee-Object -Append sondeo.txt
docker rm -f e6-web e6-datos
docker network rm e6-red

macOS / Linux · Terminal

until docker exec e6-datos pg_isready -U postgres -h localhost; do sleep 1; done
docker run --rm --network e6-red sondeo:1.0 e6-web 80 443 | tee sondeo.txt
docker run --rm --network e6-red sondeo:1.0 e6-datos 5432 80 | tee -a sondeo.txt
docker rm -f e6-web e6-datos
docker network rm e6-red

Abre sondeo.txt con code sondeo.txt: tiene cuatro líneas, con e6-web:80 y e6-datos:5432 abiertos y los otros dos cerrados. El 5432 de la base de datos está abierto para quien esté en la red, aunque no se haya publicado: es lo que verá un escáner de puertos como nmap más adelante, en la miniauditoría. Si quieres volver a lanzar levantar.sh, quita antes los contenedores y la red con esas dos últimas órdenes: docker network create falla si la red ya existe.

Qué mira el corrector

El corrector marca fallo si:

  • Falta levantar.sh o sondeo.txt.
  • sondeo.txt no tiene las cuatro líneas, en el orden pedido, con 80 y 5432 abiertos.
  • levantar.sh tiene algo que no es una orden docker de las admitidas en E5, o falla en un equipo limpio.
  • levantar.sh no crea e6-web o e6-datos, o alguno no sigue en marcha unos segundos después.
  • e6-web o e6-datos no salen de las imágenes indicadas, o no están en e6-red.
  • La web no publica en 127.0.0.1:8086, o la base de datos publica algún puerto.

5Pruébalo en tu equipo

Primero guarda tu trabajo en un commit, desde la raíz de tu repositorio: las pruebas solo ven lo que está en commits.

cd ~/hacking-etico/entregas-<tu-usuario>
git add .
git commit -m "feat(docker-e6): red propia y puertos solo donde hacen falta"

Después, con Docker Desktop en marcha, pasa las mismas comprobaciones que el corrector. Trabajan sobre una copia de lo que ya está en commits (la etiqueta, si existe; si no, main) y construyen y levantan contenedores como él.

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/pruebas.py e6

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/pruebas.py e6

Cada ✗ dice qué falla y por qué. Corrige, haz commit y repite hasta que salga ✓ superado. Antes y después de comprobar, se quitan los contenedores, redes y volúmenes del laboratorio de este ejercicio, para empezar como en un equipo limpio.

6Sube y etiqueta

git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E6 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e6 -m "E6 resuelto"
git push origin entrega-fundamentos-docker-e6

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. El corrector evalúa siempre lo que haya en la etiqueta.
