E8 · Auditar un compose

El panel de administración de la empresa se despliega con un compose que abre todas las puertas. Audítalo, ciérralas y documenta cada fallo.

Teoría
Docker 4 · Compose y seguridad
Aprendes
A leer un compose como un auditor: cada línea peligrosa, qué permite y cómo se cierra.
Trabajas en
fundamentos/docker/e8/
Etiqueta

Qué entregas

En fundamentos/docker/e8/:

FicheroQué lleva
docker-compose.ymlEl de preparar.py, corregido. Siguen los servicios web y panel: el panel responde en 127.0.0.1:8000 y la web, en 127.0.0.1:8088. La base de datos, datos, puede seguir, pero sin publicar ningún puerto.

.env no se sube. informe.md empieza así (la fila es un ejemplo de la forma; las tuyas, las que encuentres):

| Línea original | Riesgo | Corrección |

1Prepara el escenario

Desde tu repositorio, con Docker Desktop en marcha:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/preparar.py e8
cd fundamentos/docker/e8

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/preparar.py e8
cd fundamentos/docker/e8

Deja docker-compose.yml, la carpeta panel/ con su Dockerfile y panel.py, y web/. Todas las órdenes que siguen se lanzan desde fundamentos/docker/e8.

2Levántalo tal cual y mira lo que ve cualquiera

Levanta el compose sin tocar nada, pide el propio compose a la web y vuelve a bajarlo:

Windows · PowerShell

docker compose up -d --build
curl.exe http://localhost/docker-compose.yml
docker compose down

macOS / Linux · Terminal

docker compose up -d --build
curl http://localhost/docker-compose.yml
docker compose down

El curl imprime el docker-compose.yml entero, con admin123 dentro. Cualquiera que llegue a tu puerto 80, también desde la wifi del aula, lee el propio compose con sus contraseñas. Es tu primer hallazgo. Si up dice que el puerto 80 ya está en uso, otro programa de tu equipo lo ocupa: sáltate el curl y anota el hallazgo leyendo el compose.

3Pasa Trivy por la carpeta

Trivy revisa la configuración de la carpeta, que se monta en solo lectura en /work. Si al principio salen líneas ERROR [rego], son avisos internos de Trivy y no cuentan: lo que importa es el resumen Failures y cada aviso AVD-… que lista debajo.

Windows · PowerShell

docker run --rm -v "${PWD}:/work:ro" aquasec/trivy:0.58.0 config --severity HIGH,CRITICAL /work

macOS / Linux · Terminal

docker run --rm -v "$PWD:/work:ro" aquasec/trivy:0.58.0 config --severity HIGH,CRITICAL /work

Sale una tabla por fichero con sus avisos; en panel/Dockerfile hay al menos uno alto. Cada aviso tiene un identificador, como AVD-DS-0002, y una línea que explica qué falla. Anótalos para el informe.

4Corrige

code docker-compose.yml
code panel/Dockerfile

Revisa el compose y el Dockerfile con la lista de Docker 4 · Puertas que abre un compose. El panel y la web tienen que seguir funcionando en 127.0.0.1:8000 y 127.0.0.1:8088. Las contraseñas pasan a .env: en el compose quedan como ${NOMBRE} o ${NOMBRE:?mensaje}, sin valor escrito. Crea .env.ejemplo con una línea NOMBRE= por variable:

code .env.ejemplo

Guarda el fichero. Después, cópialo a .env y pon allí los valores:

Windows · PowerShell

Copy-Item .env.ejemplo .env
code .env

macOS / Linux · Terminal

cp .env.ejemplo .env
code .env

En .env usa solo letras y números en los valores. .env no aparece en git status.

5Documenta

code informe.md

Una tabla con una fila por fallo, con la forma de «Qué entregas»: línea original, qué riesgo tenía y cómo lo has corregido. Entre el compose y el Dockerfile hay al menos diez. Ningún valor de .env en el informe.

6Comprueba antes de subir

Pasa otra vez Trivy, levanta el compose corregido, pide las dos páginas, mira con qué usuario corre el panel y bájalo:

Windows · PowerShell

docker run --rm -v "${PWD}:/work:ro" aquasec/trivy:0.58.0 config --severity HIGH,CRITICAL /work
docker compose up -d --build
curl.exe http://localhost:8000/
curl.exe -i http://localhost:8088/docker-compose.yml
docker compose exec panel id
docker compose down

macOS / Linux · Terminal

docker run --rm -v "$PWD:/work:ro" aquasec/trivy:0.58.0 config --severity HIGH,CRITICAL /work
docker compose up -d --build
curl http://localhost:8000/
curl -i http://localhost:8088/docker-compose.yml
docker compose exec panel id
docker compose down

Trivy no da ningún aviso, el panel responde panel de administración: acceso restringido, la web ya no sirve el compose (HTTP/1.1 404 Not Found) e id muestra un uid distinto de 0: el panel no corre como root. Deja el compose bajado antes de pasar las pruebas: usan los mismos puertos.

Qué mira el corrector

El corrector marca fallo si:

  • Falta docker-compose.yml, panel/Dockerfile, .env.ejemplo o informe.md.
  • .env está en el repositorio.
  • informe.md tiene menos de diez filas.
  • Trivy da avisos altos o críticos.
  • docker compose config falla con un .env hecho con las variables de .env.ejemplo.
  • Queda privileged, el socket de Docker u otra puerta abierta sobre el equipo.
  • Alguna imagen no tiene versión fija, o algún puerto se publica fuera de 127.0.0.1.
  • La base de datos publica algún puerto, aunque sea en 127.0.0.1.
  • Alguna carpeta se monta con escritura.
  • Alguna contraseña sigue escrita en el compose: toda variable con PASSWORD, SECRET, TOKEN, CLAVE o KEY en el nombre tiene que salir de .env.
  • Faltan los servicios web o panel, o docker compose up falla.
  • El panel no arranca en 127.0.0.1:8000 o corre como root.
  • La web no responde en 127.0.0.1:8088 o sigue sirviendo el compose.

7Pruébalo en tu equipo

Primero guarda tu trabajo en un commit, desde la raíz de tu repositorio: las pruebas solo ven lo que está en commits.

cd ~/hacking-etico/entregas-<tu-usuario>
git add .
git commit -m "fix(docker-e8): panel sin puertas abiertas"

Después, con Docker Desktop en marcha, pasa las mismas comprobaciones que el corrector. Trabajan sobre una copia de lo que ya está en commits (la etiqueta, si existe; si no, main) y construyen y levantan contenedores como él.

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/pruebas.py e8

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/pruebas.py e8

Cada ✗ dice qué falla y por qué. Corrige, haz commit y repite hasta que salga ✓ superado. Antes y después de comprobar, se quitan los contenedores, redes y volúmenes del laboratorio de este ejercicio, para empezar como en un equipo limpio.

8Sube y etiqueta

git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E8 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e8 -m "E8 resuelto"
git push origin entrega-fundamentos-docker-e8

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. El corrector evalúa siempre lo que haya en la etiqueta.
