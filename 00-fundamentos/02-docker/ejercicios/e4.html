E4 · El secreto de la capa

Te pasan una imagen ya construida. Alguien metió en ella la clave de una API y la «borró». Recupérala como haría un atacante y reconstruye la imagen sin ella.

Teoría

Aprendes

Qué entregas

En fundamentos/docker/e4/:

FicheroQué lleva
hallazgo.txtUna línea con la clave que encontraste, ocultada: oa-, sus 8 primeros caracteres y …. Nunca la clave completa.
DockerfileEl de preparar.py, cambiado para que la clave llegue solo como secreto de construcción (RUN --mount=type=secret con el id api): sin COPY api.key, sin ARG ni ENV con la clave.
.dockerignoreLo escribes tú, con api.key, *.tar y capas/, uno por línea.
informe.py y .gitignoreTal como los deja preparar.py, sin cambios.

Una línea correcta de hallazgo.txt (con tu clave, no con esta):

oa-3f9c1a2b…

No se suben api.key, e4.tar ni capas/. Si la clave completa aparece en cualquier fichero de tu repositorio, el ejercicio falla.

1Prepara el escenario

Desde tu repositorio, con Docker Desktop en marcha:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/preparar.py e4
cd fundamentos/docker/e4

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/preparar.py e4
cd fundamentos/docker/e4

Construye la imagen e4-informe:1.0 con una clave distinta para cada alumno, y borra la clave de tu carpeta: solo queda dentro de la imagen. Deja también el Dockerfile que se usó, informe.py y un .gitignore. Todas las órdenes que siguen se lanzan desde fundamentos/docker/e4 y en la misma ventana: el paso 5 usa lo que guarda el paso 3.

2Comprueba que «no está»

docker run --rm e4-informe:1.0 ls -a /app
docker history e4-informe:1.0

En el contenedor solo está informe.py: no hay ninguna clave. Pero el historial tiene una capa COPY api.key . muy pequeña, de bytes o de pocos kB.

3Extrae las capas y encuentra la clave

Guarda la imagen en un .tar, ábrelo en capas/ y busca en cada capa los ficheros que se llaman api.key:

Windows · PowerShell

docker save e4-informe:1.0 -o e4.tar
New-Item -ItemType Directory -Force capas | Out-Null
tar -xf e4.tar -C capas
foreach ($c in Get-ChildItem capas/blobs/sha256) { tar -tf $c.FullName 2>$null | Select-String api.key | ForEach-Object { "$($c.Name)  $_" } }

macOS / Linux · Terminal

docker save e4-informe:1.0 -o e4.tar
mkdir -p capas
tar -xf e4.tar -C capas
for c in capas/blobs/sha256/*; do tar -tf "$c" 2>/dev/null | grep api.key | sed "s|^|$(basename "$c")  |"; done

Salen dos capas: una con app/api.key, la que la copió, y otra con app/.wh.api.key, la marca de «borrado» que dejó rm. Quédate con la primera y lee de ella la clave:

Windows · PowerShell

$capa = Get-ChildItem capas/blobs/sha256 | Where-Object { (tar -tf $_.FullName 2>$null) -contains 'app/api.key' } | Select-Object -First 1
tar -xOf $capa.FullName app/api.key

macOS / Linux · Terminal

capa=$(for c in capas/blobs/sha256/*; do tar -tf "$c" 2>/dev/null | grep -qx 'app/api.key' && echo "$c"; done | head -n 1)
tar -xOf "$capa" app/api.key

Sale una línea como oa- seguido de 32 caracteres hexadecimales: es la clave. e4.tar y capas/ no se suben: el .gitignore de la carpeta ya los excluye.

4Redacta el hallazgo sin filtrar la clave

code hallazgo.txt

Escribe una línea con la clave ocultada, como en un informe de auditoría: oa-, sus 8 primeros caracteres y … (por ejemplo, oa-3f9c1a2b…). Guarda. La clave completa no debe estar en ningún fichero de tu repositorio.

5Reconstruye sin el secreto

Guarda la clave que encontraste en api.key, en la carpeta del ejercicio. Tu .gitignore excluye *.key, así que no se subirá:

Windows · PowerShell

tar -xOf $capa.FullName app/api.key | Set-Content -Encoding ascii api.key

macOS / Linux · Terminal

tar -xOf "$capa" app/api.key > api.key

En Windows PowerShell, > guarda en UTF-16 y informe.py no podría leer la clave: por eso se usa Set-Content -Encoding ascii. Si has cerrado la ventana desde el paso 3, vuelve a lanzar la línea que guarda $capa.

Después cambia el Dockerfile con code Dockerfile: quita COPY api.key . y el rm, y haz que la línea RUN que ejecuta informe.py --comprobar monte el secreto con id api, que dentro de la construcción aparece en /run/secrets/api. Cómo, en Docker 2 · Un secreto en una capa. Escribe también el .dockerignore:

code .dockerignore

Con tres líneas: api.key, *.tar y capas/. Construye sin caché, para ver la salida de cada paso:

docker build --progress=plain --no-cache --secret id=api,src=api.key -t e4-informe:2.0 .

La construcción acaba sin errores y, en el paso del RUN, aparece una línea con clave de la API válida.

6Comprueba antes de subir

Abre la imagen nueva igual que la vieja y busca otra vez ficheros api.key; después borra lo que has sacado:

Windows · PowerShell

docker save e4-informe:2.0 -o e4-2.tar
New-Item -ItemType Directory -Force capas2 | Out-Null
tar -xf e4-2.tar -C capas2
foreach ($c in Get-ChildItem capas2/blobs/sha256) { tar -tf $c.FullName 2>$null | Select-String api.key }
Remove-Item -Recurse -Force capas2, e4-2.tar

macOS / Linux · Terminal

docker save e4-informe:2.0 -o e4-2.tar
mkdir -p capas2
tar -xf e4-2.tar -C capas2
for c in capas2/blobs/sha256/*; do tar -tf "$c" 2>/dev/null | grep api.key; done
rm -r capas2 e4-2.tar

El bucle no muestra nada: ninguna capa contiene api.key. Comprueba también qué vas a subir:

git status

Aparecen hallazgo.txt, .dockerignore y los cambios del Dockerfile; no aparecen api.key, e4.tar ni capas/.

El corrector marca fallo si:

  • Falta Dockerfile, hallazgo.txt o .dockerignore.
  • hallazgo.txt no tiene tu clave ocultada (oa- y sus 8 primeros caracteres), o tiene la clave completa.
  • Algún fichero de tu repositorio contiene la clave completa.
  • Con tu clave como secreto api, el Dockerfile no construye, o la construcción no dice clave de la API válida.
  • Alguna capa de la imagen resultante contiene la clave.

Cada ✗ dice qué falla y por qué. Corrige, haz commit y repite hasta que salga ✓ superado. Antes y después de comprobar se quitan los contenedores, redes y volúmenes del laboratorio de este ejercicio, para empezar como en un equipo limpio.

8Sube y etiqueta

git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E4 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e4 -m "E4 resuelto"
git push origin entrega-fundamentos-docker-e4

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. Cuenta tal como esté al cerrar el plazo; si la mueves después, la entrega queda fuera de plazo.
