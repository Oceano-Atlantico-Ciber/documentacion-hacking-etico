Desde tu repositorio, con Docker Desktop en marcha:

macOS / Linux · Terminal

Deja web/index.html, la página de la empresa con tu usuario. Todas las órdenes que siguen se lanzan desde fundamentos/docker/e5.

2Escribe levantar.sh

code levantar.sh

Empieza exactamente con estas tres líneas (la primera dice que es un script de bash, la segunda lo para en el primer error y la tercera lo lleva a su carpeta):

#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")"

Debajo, una orden docker por línea, que haga en este orden:

  1. Crear el volumen e5-datos.
  2. Arrancar en segundo plano (-d) el contenedor e5-db desde postgres:16-alpine, con la variable POSTGRES_PASSWORD (-e) y el volumen e5-datos montado en /var/lib/postgresql/data.
  3. Arrancar en segundo plano el contenedor e5-web desde nginx:1.27-alpine, publicado en 127.0.0.1:8085 (puerto 80 del contenedor) y con la carpeta ./web montada en solo lectura en /usr/share/nginx/html.

La carpeta se monta con ruta relativa, -v ./web:/usr/share/nginx/html:ro, sin $(pwd). La contraseña puede ir escrita en el script porque es de usar y tirar. Los valores de -e solo pueden llevar letras, números y guiones (por ejemplo, -e POSTGRES_PASSWORD=clave-de-prueba-5): nada de espacios, comillas, $ ni otros símbolos. En E7 la sacarás a un .env.

El corrector no ejecuta tu script con bash: lo lee y lanza una a una sus órdenes docker. Por eso solo admite, además de esas tres líneas y de comentarios que empiecen por #, órdenes docker volume create, docker network create, docker run, docker pull, docker rm y docker stop, una por línea y completa: sin \ para partirla, sin variables, sin $(pwd), sin redirecciones ni || true. En docker run valen las opciones -d, --name, -p, -v, -e, --network, --rm y --restart, y la imagen tiene que ser postgres:16-alpine o nginx:1.27-alpine. No pongas en el script el docker rm de tus contenedores: el corrector lo lanza en un equipo limpio, y tú los borras a mano antes de volver a lanzarlo, como dicen los pasos. Es lo que haría cualquiera antes de ejecutar un script ajeno: leerlo.

3Arranca y guarda un dato

Lanza el script, espera a que Postgres acepte conexiones (la primera vez tarda unos segundos en crear la base de datos) y guarda una fila. Cambia <tu-usuario> por tu usuario de GitHub:

Windows · PowerShell

Get-Content levantar.sh | Where-Object { $_ -match '^\s*docker\s' } | ForEach-Object { Invoke-Expression $_; if ($LASTEXITCODE) { throw "falla: $_" } }
do { Start-Sleep 1; docker exec e5-db pg_isready -U postgres -h localhost } until ($LASTEXITCODE -eq 0)
docker exec e5-db psql -U postgres -c "CREATE TABLE hallazgos (id serial PRIMARY KEY, texto text NOT NULL)"
docker exec e5-db psql -U postgres -c "INSERT INTO hallazgos (texto) VALUES ('primer hallazgo de <tu-usuario>')"

macOS / Linux · Terminal

bash levantar.sh
until docker exec e5-db pg_isready -U postgres -h localhost; do sleep 1; done
docker exec e5-db psql -U postgres -c "CREATE TABLE hallazgos (id serial PRIMARY KEY, texto text NOT NULL)"
docker exec e5-db psql -U postgres -c "INSERT INTO hallazgos (texto) VALUES ('primer hallazgo de <tu-usuario>')"

En Windows, la primera línea lee levantar.sh y lanza una a una sus órdenes docker, igual que hace el corrector, que no lo ejecuta con bash; si una falla, se para y dice cuál. Mientras Postgres arranca verás no response; cuando sale accepting connections, sigue. Las dos órdenes de psql responden CREATE TABLE e INSERT 0 1.

4Borra los contenedores y recréalos

Borra los dos contenedores (el volumen se queda), vuelve a lanzar el script y consulta la tabla guardando la salida en consulta.txt:

Windows · PowerShell

docker rm -f e5-db e5-web
Get-Content levantar.sh | Where-Object { $_ -match '^\s*docker\s' } | ForEach-Object { Invoke-Expression $_; if ($LASTEXITCODE) { throw "falla: $_" } }
do { Start-Sleep 1; docker exec e5-db pg_isready -U postgres -h localhost } until ($LASTEXITCODE -eq 0)
docker exec e5-db psql -U postgres -c "SELECT texto FROM hallazgos" | Tee-Object consulta.txt

macOS / Linux · Terminal

docker rm -f e5-db e5-web
bash levantar.sh
until docker exec e5-db pg_isready -U postgres -h localhost; do sleep 1; done
docker exec e5-db psql -U postgres -c "SELECT texto FROM hallazgos" | tee consulta.txt

El contenedor es nuevo, pero el dato sigue: estaba en el volumen. La consulta muestra tu fila y (1 row), como en «Qué entregas». docker volume create no falla si el volumen ya existe. Si sale relation "hallazgos" does not exist, el volumen no estaba montado en /var/lib/postgresql/data: corrige el script, borra los contenedores y el volumen (docker volume rm e5-datos) y repite desde el paso 3.

5Comprueba la web

Pide la página e intenta escribir en la carpeta servida desde dentro del contenedor:

Windows · PowerShell

curl.exe http://localhost:8085/
docker exec e5-web sh -c 'echo prueba > /usr/share/nginx/html/prueba.html'

macOS / Linux · Terminal

curl http://localhost:8085/
docker exec e5-web sh -c 'echo prueba > /usr/share/nginx/html/prueba.html'

La web sirve tu página (Portal de la empresa, con tu usuario), y el contenedor no puede escribir en tu carpeta: sale Read-only file system. Para acabar, quita los contenedores:

docker rm -f e5-db e5-web

El corrector marca fallo si:

  • Falta levantar.sh, consulta.txt o web/index.html.
  • consulta.txt no muestra tu fila (primer hallazgo de <tu-usuario> y (1 row)).
  • levantar.sh tiene algo que no es una orden docker de las admitidas, o falla en un equipo limpio.
  • levantar.sh no crea e5-db y e5-web, alguno no sigue en marcha unos segundos después o no sale de su imagen (postgres:16-alpine y nginx:1.27-alpine).
  • Los datos de Postgres no están en el volumen e5-datos, o la web no monta ./web en solo lectura en /usr/share/nginx/html.
  • La web no responde en 127.0.0.1:8085 con tu página.
