E7 · Tu primer compose

Qué entregas

En fundamentos/docker/e7/:

FicheroQué lleva
docker-compose.ymlLo escribes tú: el proyecto e7-lab con la red, el volumen y los cuatro servicios de la tabla del paso 2.
.env.ejemploUna sola línea, la variable sin valor: POSTGRES_PASSWORD=. Sirve para que otro sepa qué variable hace falta.

.env no se sube: lleva tu contraseña y tu .gitignore ya lo excluye. El corrector usa su propio .env. El sondeo se construye desde ../e2, así que tu E2 tiene que estar en el repositorio. Las claves de primer nivel del compose son estas; lo de dentro de cada una lo escribes tú:

name: …
services:
  web:
    …
  datos:
    …
  sondeo:
    …
  curl:
    …
networks:
  …
volumes:
  …

1Prepara la carpeta

E7 no tiene ficheros de partida: reutiliza la web de E5. Desde tu repositorio, crea la carpeta, copia en ella ../e5/web y abre el compose:

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
New-Item -ItemType Directory -Force fundamentos/docker/e7 | Out-Null
cd fundamentos/docker/e7
Copy-Item -Recurse ../e5/web .
code docker-compose.yml

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
mkdir -p fundamentos/docker/e7
cd fundamentos/docker/e7
cp -r ../e5/web .
code docker-compose.yml

Ahora tienes web/index.html dentro de fundamentos/docker/e7. Todas las órdenes que siguen se lanzan desde esa carpeta.

2Escribe el compose

Proyecto e7-lab (clave name), una red lab, un volumen datos y exactamente cuatro servicios, todos en la red lab y en ninguna otra:

ServicioQué es
webnginx:1.27-alpine, publicado en 127.0.0.1:8087 (puerto 80 del contenedor), con ./web montada en solo lectura en /usr/share/nginx/html. Sin perfil.
datospostgres:16-alpine con el volumen datos en /var/lib/postgresql/data, sin puertos publicados. POSTGRES_PASSWORD sale de ${POSTGRES_PASSWORD:?falta en .env}. Sin perfil.
sondeoSe construye desde ../e2 (build) con la imagen sondeo:1.0 (image). En el perfil herramientas.
curlcurlimages/curl:8.11.1. En el perfil herramientas.

Cada clave equivale a una opción de docker run: la tabla está en Docker 4. No añadas montajes, puertos ni redes que no estén en la tabla.

3La contraseña, en .env

Crea .env.ejemplo con la variable vacía, cópialo a .env y abre .env:

Windows · PowerShell

Set-Content .env.ejemplo 'POSTGRES_PASSWORD='
Copy-Item .env.ejemplo .env
code .env

macOS / Linux · Terminal

echo 'POSTGRES_PASSWORD=' > .env.ejemplo
cp .env.ejemplo .env
code .env

En .env, escribe una contraseña detrás del = (solo letras y números) y guarda. .env.ejemplo se sube vacío; .env no aparece en git status.

4Levántalo y pruébalo

Primero, que el compose se entienda:

Windows · PowerShell

docker compose config -q
if ($LASTEXITCODE -eq 0) { "correcto" }

macOS / Linux · Terminal

docker compose config -q && echo correcto

Tiene que salir correcto. Comprueba también que sin contraseña se niega; esta orden usa .env.ejemplo, vacío, en lugar de tu .env, y es igual en todos los sistemas:

docker compose --env-file .env.ejemplo config -q

Falla con un error que acaba en tu mensaje, falta en .env. Ahora levanta el laboratorio y usa las herramientas (las órdenes son las mismas en todos los sistemas):

docker compose up -d
docker compose ps
docker compose run --rm curl -s http://web/
docker compose run --rm sondeo datos 5432
docker compose down

up solo levanta web y datos, y ps muestra esos dos; las herramientas del perfil se lanzan con run. curl imprime tu página y el sondeo imprime datos:5432 abierto; si sale cerrado, Postgres aún estaba arrancando: espera unos segundos y repite esa línea.

El corrector marca fallo si:

  • Falta docker-compose.yml, .env.ejemplo o web/index.html.
  • .env está en el repositorio.
  • docker compose config no falla sin .env, o falla con un .env completo.
  • El compose abre alguna puerta sobre el equipo: privileged, el socket de Docker, carpetas o construcciones de fuera de tu repositorio…
  • El proyecto no se llama e7-lab, o sus servicios no son exactamente web, datos, sondeo y curl.
  • Algún servicio no cumple la tabla: imagen, puerto, montaje, red o perfil.
  • POSTGRES_PASSWORD de datos no sale de .env, o sondeo no se construye desde ../e2.
  • docker compose up falla, o con up, curl no recibe tu página o el sondeo no ve el 5432 de datos.

5Pruébalo en tu equipo

Primero guarda tu trabajo en un commit, desde la raíz de tu repositorio: las pruebas solo ven lo que está en commits.

cd ~/hacking-etico/entregas-<tu-usuario>
git add .
git commit -m "feat(docker-e7): el laboratorio en un compose"

Después, con Docker Desktop en marcha, pasa las mismas comprobaciones que el corrector. Trabajan sobre una copia de lo que ya está en commits (la etiqueta si existe, si no main) y construyen y levantan contenedores como él.

Windows · PowerShell

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/pruebas.py e7

macOS / Linux · Terminal

cd ~/hacking-etico/entregas-<tu-usuario>
python3 ../documentacion-hacking-etico/00-fundamentos/02-docker/ejercicios/pruebas.py e7

Cada ✗ dice qué falla y por qué. Corrige, haz commit y repite hasta que salga ✓ superado. Antes y después de comprobar se quitan los contenedores, redes y volúmenes del laboratorio de este ejercicio, para empezar como en un equipo limpio.

6Sube y etiqueta

git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E7 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e7 -m "E7 resuelto"
git push origin entrega-fundamentos-docker-e7

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. El corrector evalúa siempre lo que haya en la etiqueta.
