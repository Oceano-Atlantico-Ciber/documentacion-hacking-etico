E5 · Un laboratorio completo

Escribe desde cero un laboratorio pequeño: una red, un servidor web que se ve desde fuera y una base de datos que solo ve el servidor. Es un ejemplo para practicar, no el laboratorio de ningún bloque.

Teoría
IaC 3 · Redes y servidores
Aprendes
VPC, subredes, grupos de seguridad que se refieren a otros, EC2 con user_data y RDS privada.
Trabajas en
fundamentos/iac/e5/
Etiqueta
entrega-fundamentos-iac-e5 sobre main

Qué entregas

En fundamentos/iac/e5/ de main, main.tf con el laboratorio (puedes repartirlo en varios .tf si prefieres), y proveedor.tf y LEEME.md tal como los deja preparar.py. El laboratorio tiene la forma de IaC 3 · La forma de un laboratorio:

PiezaRecursosCómo debe quedar
Redaws_vpc, tres aws_subnetUna VPC con etiqueta Name; una subred pública y dos privadas en dos zonas (eu-west-1a y eu-west-1b).
Servidor webaws_security_group, aws_instanceUno solo, en la subred pública. Su user_data escribe tu página en /usr/share/nginx/html/index.html. Su grupo abre el 80 a 0.0.0.0/0 y ningún otro puerto a todo el mundo.
Base de datosrandom_password, aws_security_group, aws_db_subnet_group, aws_db_instancePostgreSQL en las dos subredes privadas, publicly_accessible = false. Su grupo solo admite el 5432 desde el grupo del servidor web, sin rangos de IP (cidr_blocks). La contraseña la genera random_password: no se escribe en el código ni en el user_data.
SalidaoutputLa IP del servidor web.

El corrector aplica tu código en una cuenta vacía, revisa con la CLI lo que ha quedado y después lo destruye. La etiqueta anotada entrega-fundamentos-iac-e5 va sobre main, subida a GitHub.

1Prepara el ejercicio

Abre la terminal de VS Code (Terminal → New Terminal; en Windows es PowerShell). Ve a tu repositorio, trae la última versión del material y vuelve a main. Cambia <tu-usuario> por tu usuario de GitHub:

cd ~/hacking-etico/entregas-<tu-usuario>
git -C ../documentacion-hacking-etico pull
git switch main

Crea el punto de partida:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/preparar.py e5

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/preparar.py e5
e5 preparado para <tu-usuario> en fundamentos/iac/e5/. Sigue el enunciado.

preparar.py ha dejado en e5/ dos ficheros: proveedor.tf, que apunta a tu Floci, y un LEEME.md con la página que debe servir tu servidor web. Entra y léelo:

cd fundamentos/iac/e5
code LEEME.md

code LEEME.md lo abre en VS Code: léelo ahí y copia de ahí tus nombres.

# E5 · Un laboratorio completo

La página que tiene que servir tu servidor web, escrita por user_data en /usr/share/nginx/html/index.html:

    Laboratorio de <tu-usuario> · 5e6f7a8b
…

Esa línea, Laboratorio de … · …, es tu página. Cópiala tal cual, con el punto medio (·): el corrector la busca exacta.

2Escribe el laboratorio

code main.tf

Escribe los recursos de la tabla de Qué entregas. Los ejemplos de IaC 3 son casi el laboratorio entero: la VPC y las tres subredes, los grupos web y db, el servidor, la contraseña, el grupo de subredes y la base de datos, y la salida ip_web. Al juntarlos, cuida estos detalles, que son los que el corrector mira:

  • Cada grupo de seguridad lleva vpc_id = aws_vpc.lab.id, y el servidor, subnet_id de la subred pública: si no, acaban en la VPC por defecto y el corrector no los encuentra en la tuya.
  • El user_data escribe tu página, no «Hola». Pon la línea exacta de tu LEEME.md: el número del final no es tu huella del E1, es otro. 
      user_data = <<-SH
    #!/bin/sh
    echo "<la línea de tu LEEME.md>" > /usr/share/nginx/html/index.html
  SH
  • El grupo web abre a 0.0.0.0/0 solo la web: el 80 (el 443 también se admitiría). Nada de 22 abierto «para administrar».
  • El grupo db admite el 5432 con security_groups = [aws_security_group.web.id] y sin rangos de IP (cidr_blocks).
  • El grupo de subredes de la base de datos lleva las dos subredes privadas, una en cada zona.
  • Un solo servidor EC2 en el laboratorio: el corrector toma el primero como servidor web.

Guarda. No toques proveedor.tf.

3Despliega y revisa

Con tu Floci en marcha, desde fundamentos/iac/e5/:

terraform init
terraform fmt
terraform validate

init descarga dos proveedores, hashicorp/aws y hashicorp/random (el de random_password). validate debe decir Success! The configuration is valid.; si no, te dice el fichero y la línea del error. Despliega (escribe yes cuando lo pida) y mira la salida:

terraform apply
terraform output
Apply complete! Resources: 10 added, 0 changed, 0 destroyed.
…
ip_web = "10.0.1.…"

El número de recursos puede ser otro si has repartido distinto. Ahora revisa con la CLI lo que el corrector va a mirar. La primera orden da el VpcId de cada VPC: la tuya es la que tiene IsDefault en false. Pon su VpcId en la segunda en lugar de <tu-vpc>:

aws ec2 describe-vpcs --query "Vpcs[].[VpcId,CidrBlock,IsDefault]"
aws ec2 describe-security-groups --filters "Name=vpc-id,Values=<tu-vpc>" --query "SecurityGroups[].[GroupName,IpPermissions]"
aws rds describe-db-instances --query "DBInstances[].[DBInstanceIdentifier,PubliclyAccessible]"

Además del grupo default, que AWS crea en cada VPC, en tu VPC están los tuyos: web tiene una sola regla, el 80 con "CidrIp": "0.0.0.0/0"; db tiene el 5432 con UserIdGroupPairs (el grupo web) y sin IpRanges. La base de datos sale con false. Los servidores y la base de datos están simulados en Floci: existen en la API con su configuración, que es lo que revisas, pero no arrancan.

4Destruye

Un laboratorio bien escrito se borra entero con una orden:

terraform destroy
aws ec2 describe-vpcs --query "Vpcs[].[VpcId,IsDefault]"

destroy enseña lo que va a borrar y pide yes; termina en Destroy complete!. Después solo queda la VPC por defecto (true).

El corrector marca fallo si:

  • Falta proveedor.tf, o terraform init o apply fallan.
  • apply no crea exactamente una VPC, aparte de la de por defecto.
  • La VPC tiene menos de tres subredes, o no hay ningún servidor EC2 dentro.
  • El user_data del servidor no escribe tu página, tal cual la da LEEME.md.
  • El grupo del servidor no abre el 80 a 0.0.0.0/0, o abre a 0.0.0.0/0 algún puerto que no sea el 80 o el 443.
  • No hay ninguna base de datos RDS en la VPC.
  • La base de datos es accesible desde fuera (publicly_accessible), o su grupo admite rangos de IP (cidr_blocks), u otro grupo que no es el del servidor, o no deja entrar al servidor.
  • Las salidas no dan la IP del servidor web.
  • terraform destroy falla, o después queda alguna VPC.

5Haz commit y pruébalo

Primero, haz commit. Vuelve a la carpeta del repositorio y mira qué vas a añadir:

cd ~/hacking-etico/entregas-<tu-usuario>
git status --short -uall fundamentos/iac/e5
?? fundamentos/iac/e5/LEEME.md
?? fundamentos/iac/e5/main.tf
?? fundamentos/iac/e5/proveedor.tf

No debe salir ningún terraform.tfstate ni nada de .terraform/: el .gitignore de fundamentos/iac/ los deja fuera, porque el estado puede guardar secretos.

git add fundamentos/iac/e5
git commit -m "feat(iac-e5): laboratorio con web y base de datos privada"

pruebas.py evalúa tu etiqueta entrega-fundamentos-iac-e5, o la rama main si aún no la tienes, con las mismas comprobaciones que el corrector. Solo cuentan los commits: lo que no esté en un commit no se evalúa. Trabaja en una Floci aparte y vacía, así que no toca tu repositorio ni tu Floci.

Necesita Docker Desktop en marcha. Desde la carpeta de tu repositorio:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/pruebas.py e5

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/pruebas.py e5

Este ejercicio crea y destruye un laboratorio entero: cada pruebas.py tarda entre 4 y 8 minutos. Déjalo terminar.

Antes de subir, un ejercicio bien hecho se ve así:

E5 · main, todavía sin etiqueta (provisional) · 7a8b9c0 · comprobando…
  ✓ superado
  ! main aún no está en GitHub: el corrector no lo verá hasta que lo subas
  • ✓ superado: pasa todas las comprobaciones.
  • ✗ es un fallo: el corrector también lo marcará. La línea dice qué ha encontrado y por qué no vale. Corrígelo, haz commit y vuelve a lanzar pruebas.py.
  • ! es un aviso: tu trabajo puede estar bien, pero el corrector evalúa lo que hay en GitHub, no tu equipo, y algo no coincide: «aún no está en GitHub» o «en GitHub … apunta a …, no a tu …». Antes de subir es normal: desaparece al subir en el paso siguiente. Los SHA de tus líneas serán otros.
  • sin empezar: no hay etiqueta ni fundamentos/iac/e5/ en main: falta preparar el ejercicio o hacer su commit.

6Sube y etiqueta

Sube tu trabajo a GitHub:

git push

Vuelve a lanzar pruebas.py (paso anterior). Cuando diga ✓ superado y no quede ningún aviso !, crea la etiqueta anotada sobre main y súbela:

git tag -a entrega-fundamentos-iac-e5 main -m "E5 resuelto"
git push origin entrega-fundamentos-iac-e5

Lanza pruebas.py otra vez. Ahora evalúa la etiqueta:

E5 · etiqueta entrega-fundamentos-iac-e5 · 7a8b9c0 · comprobando…
  ✓ superado

En GitHub, el resultado del corrector está en la portada de tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector iac. Hay una fila por ejercicio. Se actualiza cuando el docente lanza la corrección, no en cada push.

Si hay que corregir algo después de etiquetar

  • Si has cambiado ficheros: corrige en fundamentos/iac/e5/, haz commit y súbelo con git push. Después mueve la etiqueta al commit nuevo con las dos órdenes de abajo. Hasta que la muevas, pruebas.py sigue evaluando la etiqueta antigua.
  • Si solo falla la etiqueta, porque pruebas.py marca ✗ la etiqueta no es anotada o avisa de que en GitHub apunta a otro commit: muévela, sin hacer ningún commit.

Para mover la etiqueta, -f la reemplaza en tu equipo y git push -f, en GitHub (Git 3 · Mover una etiqueta):

git tag -fa entrega-fundamentos-iac-e5 main -m "E5 resuelto"
git push -f origin entrega-fundamentos-iac-e5

Si pruebas.py dice que en GitHub ya existe la etiqueta y no la tienes aquí, la creaste en otro equipo: tráetela con git fetch --tags.
