Qué entregas

En fundamentos/iac/e3/ de main:

FicheroQué es
main.tfTres recursos (aws_s3_bucket, aws_iam_user y aws_iam_user_policy) que describen lo que creaste en el E1, y un bloque import por cada uno.
proveedor.tfEl que deja preparar.py, sin cambiar.

El corrector lanza tu e1/ordenes.sh en una cuenta vacía, como en el E1, y después tu Terraform. El primer plan tiene que decir:

Plan: 3 to import, 0 to add, 0 to change, 0 to destroy.

Después de apply, un segundo plan no tiene que cambiar nada. La etiqueta anotada entrega-fundamentos-iac-e3 va sobre main, subida a GitHub.

1Prepara el ejercicio

Abre la terminal de VS Code (Terminal → New Terminal; en Windows es PowerShell). Ve a tu repositorio, trae la última versión del material y vuelve a main. Cambia <tu-usuario> por tu usuario de GitHub:

cd ~/hacking-etico/entregas-<tu-usuario>
git -C ../documentacion-hacking-etico pull
git switch main

Crea el punto de partida:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/preparar.py e3

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/preparar.py e3
e3 preparado para <tu-usuario> en fundamentos/iac/e3/. Sigue el enunciado.

Deja proveedor.tf, que apunta a tu Floci, y un LEEME.md con los tres recursos que tienes que adoptar. Entra en la carpeta y léelo:

cd fundamentos/iac/e3
code LEEME.md

code LEEME.md lo abre en VS Code. Léelo y copia de ahí, no de la terminal: PowerShell de Windows muestra mal los acentos y el punto medio (Â·) de un fichero UTF-8.

Tu Floci tiene que seguir teniendo lo del E1. Con Floci en marcha (si no, docker compose up -d en fundamentos/iac/), compruébalo:

aws s3 ls
aws iam list-users --query "Users[].UserName"

Tienen que salir e1-notas-<huella> y lector-<huella> (y, si hiciste el E2, también los de la empresa). Si no salen, porque hiciste docker compose down -v, vuelve a crearlos: entra en e1/ (cd ../e1), copia y lanza una a una las cuatro líneas de tu ordenes.sh, y vuelve (cd ../e3).

2Escribe los recursos

code main.tf

Escribe los tres recursos tal como los creaste en el E1, con tu huella en lugar de <huella>. La política es la de tu e1/politica.json, escrita con jsonencode y con una referencia al bucket en vez de repetir su nombre (IaC 2 · Un fichero de Terraform). Si tu politica.json tiene más acciones o sentencias, ponlas igual aquí:

resource "aws_s3_bucket" "notas" {
  bucket = "e1-notas-<huella>"
}

resource "aws_iam_user" "lector" {
  name = "lector-<huella>"
}

resource "aws_iam_user_policy" "lectura" {
  name = "lectura-notas"
  user = aws_iam_user.lector.name
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      { Effect = "Allow", Action = "s3:GetObject", Resource = "${aws_s3_bucket.notas.arn}/*" },
    ]
  })
}

Debajo, un bloque import por recurso: to es el recurso del código y id, cómo encontrarlo en la cuenta. Los id están en tu LEEME.md (IaC 2 · Adoptar lo que ya existe):

import {
  to = aws_s3_bucket.notas
  id = "e1-notas-<huella>"
}

import {
  to = aws_iam_user.lector
  id = "lector-<huella>"
}

import {
  to = aws_iam_user_policy.lectura
  id = "lector-<huella>:lectura-notas"
}

Guarda. No toques proveedor.tf.

3Ajusta hasta que el plan solo importe

Desde fundamentos/iac/e3/:

terraform init
terraform fmt
terraform plan

init descarga el proveedor (la primera vez tarda); fmt ordena el formato de tus .tf y escribe el nombre de los que ha cambiado. El plan describe cada recurso y termina así:

  # aws_iam_user.lector will be imported
…
  # aws_iam_user_policy.lectura will be imported
…
  # aws_s3_bucket.notas will be imported
…
Plan: 3 to import, 0 to add, 0 to change, 0 to destroy.

Si no sale eso:

  • to change: el plan marca con ~ el atributo de tu código que no coincide con la cuenta (por ejemplo, la política). Corrígelo en el código, no en la cuenta, y repite terraform plan.
  • to add, o un error Cannot import non-existent remote object: algún import no encuentra su recurso. Revisa su id y que lo del E1 sigue en tu Floci (paso 1).
  • Un error con un número de línea: falta una llave, unas comillas o una coma. terraform validate te dice dónde.

4Aplica y comprueba

terraform apply

Enseña el mismo plan y pregunta Enter a value:. Escribe yes y pulsa Intro:

Apply complete! Resources: 3 imported, 0 added, 0 changed, 0 destroyed.
terraform plan
No changes. Your infrastructure matches the configuration.

El código y la cuenta coinciden. El terraform.tfstate que aparece en la carpeta no se sube: el .gitignore de la unidad ya lo deja fuera.

El corrector marca fallo si:

  • Falta main.tf o proveedor.tf.
  • En los .tf falta un resource aws_s3_bucket, aws_iam_user o aws_iam_user_policy, o no hay ningún bloque import.
  • Tu e1/ordenes.sh falla en una cuenta nueva (lo comprueba igual que en el E1).
  • terraform init o terraform plan fallan.
  • El primer plan no importa nada (no dice … to import), o además añade, cambia o destruye algo: tiene que ser 0 to add, 0 to change, 0 to destroy.
  • terraform apply falla, o después el plan todavía quiere cambiar algo.

5Pruébalo en tu equipo

Primero, haz commit. Vuelve a la carpeta del repositorio y mira qué vas a añadir:

cd ~/hacking-etico/entregas-<tu-usuario>
git status --short -uall fundamentos/iac/e3
?? fundamentos/iac/e3/LEEME.md
?? fundamentos/iac/e3/main.tf
?? fundamentos/iac/e3/proveedor.tf

No tiene que salir ningún terraform.tfstate ni nada de .terraform/: el .gitignore de fundamentos/iac/ los deja fuera, porque el estado puede guardar secretos.

git add fundamentos/iac/e3
git commit -m "feat(iac-e3): bucket y lector adoptados con import"

pruebas.py pasa las mismas comprobaciones que el corrector, con el mismo código. Evalúa la etiqueta entrega-fundamentos-iac-e3 si ya la tienes y, si no, la rama main. Solo mira commits: lo que no esté en un commit no cuenta. Trabaja sobre una copia y en una Floci nueva y vacía (el contenedor iac-comprobar-floci), así que no cambia nada de tu repositorio ni de tu Floci. Necesita Docker Desktop en marcha. Desde la carpeta de tu repositorio:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/pruebas.py e3

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/pruebas.py e3

Antes de subir, un ejercicio bien hecho se ve así:

E3 · main, todavía sin etiqueta (provisional) · 7a8b9c0 · comprobando…
  ✓ superado
  ! main aún no está en GitHub: el corrector no lo verá hasta que lo subas
  • ✓ superado: pasa todas las comprobaciones.
  • ✗ es un fallo: el corrector también lo marcará. La línea dice qué ha encontrado y por qué no vale. Corrígelo, haz commit y vuelve a lanzar pruebas.py.
  • ! es un aviso: tu trabajo puede estar bien, pero el corrector evalúa lo que hay en GitHub, no tu equipo, y algo no coincide: «aún no está en GitHub» o «en GitHub … apunta a …, no a tu …». Antes de subir es normal: desaparece al subir en el paso siguiente. Los SHA de tus líneas serán otros.
  • sin empezar: no hay etiqueta ni fundamentos/iac/e3/ en main: falta preparar el ejercicio o hacer su commit.

6Sube y etiqueta

Sube tu trabajo a GitHub:

git push

Vuelve a lanzar pruebas.py (paso anterior). Cuando diga ✓ superado y no quede ningún aviso !, crea la etiqueta anotada sobre main y súbela:

git tag -a entrega-fundamentos-iac-e3 main -m "E3 resuelto"
git push origin entrega-fundamentos-iac-e3

Lanza pruebas.py otra vez. Ahora evalúa la etiqueta:

E3 · etiqueta entrega-fundamentos-iac-e3 · 7a8b9c0 · comprobando…
  ✓ superado

No hay fecha límite: entrega cada ejercicio cuando lo tengas. El progreso de cada alumno se ve en la tabla pública de entregas.

En GitHub, el resultado del corrector está en la portada de tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector iac. Hay una fila por ejercicio. Se actualiza cuando el docente lanza la corrección, no en cada push.

Si hay que corregir algo después de etiquetar

Corrige en fundamentos/iac/e3/, haz commit y súbelo con git push. Después mueve la etiqueta al commit nuevo: -f la reemplaza en tu equipo y git push -f, en GitHub (Git 3 · Mover una etiqueta). Hasta que la muevas, pruebas.py sigue evaluando la etiqueta antigua. Haz solo esto, sin commits, si pruebas.py marca ✗ la etiqueta no es anotada o avisa de que en GitHub apunta a otro commit:

git tag -fa entrega-fundamentos-iac-e3 main -m "E3 resuelto"
git push -f origin entrega-fundamentos-iac-e3

Si pruebas.py dice que en GitHub ya existe la etiqueta y no la tienes aquí, la creaste en otro equipo: tráetela con git fetch --tags.
