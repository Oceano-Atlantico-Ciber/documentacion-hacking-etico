E6 · Un módulo, dos laboratorios

Convierte tu E5 en un módulo y levanta con él dos laboratorios iguales, cada uno en su red. Es la forma en que se reparten los laboratorios a un grupo: una pieza probada, muchas copias.

Teoría
IaC 3 · Módulos
Aprendes
Módulos, variables de entrada y salidas de un módulo.
Trabajas en
fundamentos/iac/e6/
Etiqueta
entrega-fundamentos-iac-e6 sobre main

1Prepara el ejercicio

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/preparar.py e6
cd fundamentos/iac/e6

Copia tu E5 como punto de partida.

2Mueve el laboratorio a un módulo

Pasa los recursos a modulos/lab/, con variables.tf para lo que cambia de un laboratorio a otro (al menos el nombre y el rango de la VPC; las subredes se calculan con cidrsubnet) y outputs.tf con lo que necesita quien lo usa. proveedor.tf se queda en la raíz.

3Úsalo dos veces

En main.tf de la raíz, dos bloques module con nombres y rangos distintos, y una salida con la IP del servidor de cada uno. La raíz no crea ningún recurso por su cuenta.

terraform init
terraform apply
terraform output
aws ec2 describe-vpcs --query "Vpcs[].[CidrBlock,Tags]"
terraform destroy

El corrector marca fallo si:

  • No hay ningún módulo en modulos/, o la raíz no lo usa dos veces, o crea VPC, servidores o bases de datos fuera del módulo.
  • No hay dos VPC, o no tienen etiquetas Name distintas, o comparten rango.
  • Algún laboratorio no cumple lo del E5: tres subredes, servidor con el 80 abierto y nada más, base de datos privada que solo admite al servidor.
  • destroy falla.

4Pruébalo en tu equipo

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/pruebas.py e6

5Sube y etiqueta

git add fundamentos/iac
git commit -m "feat(iac-e6): módulo lab usado dos veces"
git push

Cuando la fila de E6 de Corrector iac salga sin fallos:

git tag -a entrega-fundamentos-iac-e6 -m "E6 resuelto"
git push origin entrega-fundamentos-iac-e6
