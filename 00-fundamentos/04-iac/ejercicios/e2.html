1Prepara el ejercicio

Abre la terminal de VS Code (Terminal → New Terminal; en Windows es PowerShell). Ve a tu repositorio, trae la última versión del material y vuelve a main. Cambia <tu-usuario> por tu usuario de GitHub:

cd ~/hacking-etico/entregas-<tu-usuario>
git -C ../documentacion-hacking-etico pull
git switch main

Crea el punto de partida:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/preparar.py e2

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/preparar.py e2
e2 preparado para <tu-usuario> en fundamentos/iac/e2/. Sigue el enunciado.

preparar.py ha dejado en fundamentos/iac/e2/empresa/ el Terraform de la cuenta (empresa.tf) y su proveedor.tf. Los nombres llevan tu huella, ocho caracteres que salen de tu usuario de GitHub. Es la base de este ejercicio, del E7 y del E8. Todavía no lo leas: en este ejercicio miras la cuenta desde fuera, con la CLI, como si no tuvieras el código.

2Despliega la empresa en tu nube

Tu Floci debe estar en marcha. Si reiniciaste el equipo o la paraste, levántala otra vez (desde la carpeta de tu repositorio, con Docker Desktop abierto):

cd fundamentos/iac
docker compose up -d
cd ../..

Despliega la cuenta con Terraform. Desde la carpeta de tu repositorio:

cd fundamentos/iac/e2/empresa
terraform init
terraform apply

init descarga el proveedor de AWS y termina en Terraform has been successfully initialized!. apply enseña lo que va a crear, termina en Plan: 13 to add, 0 to change, 0 to destroy. y pregunta Enter a value:. Escribe yes y pulsa Intro:

Apply complete! Resources: 13 added, 0 changed, 0 destroyed.

Outputs:

becario_clave = "…"
becario_secreto = <sensitive>

En IaC 2 verás qué ha hecho Terraform; aquí solo lo usas para tener la cuenta. No borres el terraform.tfstate que aparece en empresa/: en el E7 lo reutilizas.

3Recorre la cuenta

Lanza estas órdenes una a una, desde cualquier carpeta, y lee cada respuesta. Donde pone <bucket>, <usuario>, <política> o <id-del-servidor>, escribe el nombre que te haya dado la respuesta anterior, sin los < >. Repite la orden con cada bucket y con cada usuario:

aws s3 ls
aws s3 ls s3://<bucket>

Los tres buckets de la empresa y lo que guarda cada uno. Como la Floci es la misma de toda la unidad, también sale e1-notas-… del E1: no es de la empresa; puedes nombrarlo aparte o dejarlo fuera. Si aws s3 ls no devuelve nada, ese bucket está vacío: anótalo así.

aws iam list-users --query "Users[].UserName"
aws iam list-user-policies --user-name <usuario>
aws iam get-user-policy --user-name <usuario> --policy-name <política>
aws iam list-access-keys --user-name <usuario>

Los dos usuarios de la empresa (el lector-… es tuyo, del E1), el nombre de su política en línea, lo que dice (Action y Resource de cada sentencia) y si tienen claves de acceso.

aws ec2 describe-security-groups --query "SecurityGroups[].[GroupName,IpPermissions]"
aws ec2 describe-instances --query "Reservations[].Instances[].[InstanceId,Tags]"
aws ec2 describe-instance-attribute --instance-id <id-del-servidor> --attribute userData

Los grupos de seguridad con sus reglas de entrada: FromPort es el puerto y CidrIp, desde dónde se admite (0.0.0.0/0 es todo internet). El grupo default lo tiene toda cuenta: céntrate en el de la empresa. Y los servidores, con su etiqueta Name. La última orden, con el InstanceId que da la anterior, enseña el script de arranque del servidor (user_data) codificado en base64, una forma de escribir cualquier dato solo con letras, números y algún signo. Un atacante lo descodificaría buscando contraseñas. Hazlo tú: copia el texto de Value y cambia <value> por él, dentro de las comillas:

Windows · PowerShell

[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String("<value>"))

macOS / Linux · Terminal

echo "<value>" | base64 -d

Sale el script tal como lo escribió el equipo anterior. Apunta lo que veas en él para tu inventario.

4Escribe el inventario

cd ..
code inventario.md

Con la forma de Qué entregas: por servicio, qué hay, con el nombre exacto de cada recurso. Cada bucket y lo que guarda; cada usuario con su política y lo que permite; el grupo de seguridad con sus puertos abiertos y a quién (escribe los números de puerto y los rangos tal como salen, por ejemplo 0.0.0.0/0); y el servidor. Termina con una lista de al menos tres cosas que un atacante miraría primero en esta cuenta, y por qué. Guarda.

El corrector marca fallo si:

  • Falta inventario.md.
  • No aparecen, con su nombre exacto, todos los recursos: los tres buckets (copias-…, informes-…, secretos-…), los dos usuarios (operaciones-…, becario-…) y el grupo de seguridad web-… (el servidor se llama igual).
  • No dice qué puertos abre el grupo de seguridad y a quién: deben aparecer el rango 0.0.0.0/0 y el puerto 22.
  • No habla de lo que miraría un atacante (con esa palabra), o no tiene una lista con al menos tres puntos (líneas que empiezan por - o *, o numeradas: 1., 2.…).

5Haz commit y pruébalo

Primero, haz commit. Vuelve a la carpeta del repositorio y mira qué vas a añadir:

cd ~/hacking-etico/entregas-<tu-usuario>
git status --short -uall fundamentos/iac/e2
?? fundamentos/iac/e2/empresa/empresa.tf
?? fundamentos/iac/e2/empresa/proveedor.tf
?? fundamentos/iac/e2/inventario.md

No debe salir ningún terraform.tfstate ni nada de .terraform/: el .gitignore de fundamentos/iac/ los deja fuera, porque el estado puede guardar secretos.

git add fundamentos/iac/e2
git commit -m "docs(iac-e2): inventario de la cuenta de la empresa"

pruebas.py evalúa tu etiqueta entrega-fundamentos-iac-e2, o la rama main si aún no la tienes, con las mismas comprobaciones que el corrector. Solo cuentan los commits: lo que no esté en un commit no se evalúa. Trabaja en una Floci aparte y vacía, así que no toca tu repositorio ni tu Floci.

Necesita Docker Desktop en marcha. Desde la carpeta de tu repositorio:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/pruebas.py e2

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/pruebas.py e2

En este ejercicio el corrector solo lee inventario.md, pero pruebas.py necesita Docker igualmente.

Antes de subir, un ejercicio bien hecho se ve así:

E2 · main, todavía sin etiqueta (provisional) · 7a8b9c0 · comprobando…
  ✓ superado
  ! main aún no está en GitHub: el corrector no lo verá hasta que lo subas
  • ✓ superado: pasa todas las comprobaciones.
  • ✗ es un fallo: el corrector también lo marcará. La línea dice qué ha encontrado y por qué no vale. Corrígelo, haz commit y vuelve a lanzar pruebas.py.
  • ! es un aviso: tu trabajo puede estar bien, pero el corrector evalúa lo que hay en GitHub, no tu equipo, y algo no coincide: «aún no está en GitHub» o «en GitHub … apunta a …, no a tu …». Antes de subir es normal: desaparece al subir en el paso siguiente. Los SHA de tus líneas serán otros.
  • sin empezar: no hay etiqueta ni fundamentos/iac/e2/ en main: falta preparar el ejercicio o hacer su commit.

6Sube y etiqueta

Sube tu trabajo a GitHub:

git push

Vuelve a lanzar pruebas.py (paso anterior). Cuando diga ✓ superado y no quede ningún aviso !, crea la etiqueta anotada sobre main y súbela:

git tag -a entrega-fundamentos-iac-e2 main -m "E2 resuelto"
git push origin entrega-fundamentos-iac-e2

Lanza pruebas.py otra vez. Ahora evalúa la etiqueta:

E2 · etiqueta entrega-fundamentos-iac-e2 · 7a8b9c0 · comprobando…
  ✓ superado

En GitHub, el resultado del corrector está en la portada de tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector iac. Hay una fila por ejercicio. Se actualiza cuando el docente lanza la corrección, no en cada push.

Si hay que corregir algo después de etiquetar

  • Si has cambiado ficheros: corrige en fundamentos/iac/e2/, haz commit y súbelo con git push. Después mueve la etiqueta al commit nuevo con las dos órdenes de abajo. Hasta que la muevas, pruebas.py sigue evaluando la etiqueta antigua.
  • Si solo falla la etiqueta, porque pruebas.py marca ✗ la etiqueta no es anotada o avisa de que en GitHub apunta a otro commit: muévela, sin hacer ningún commit.

Para mover la etiqueta, -f la reemplaza en tu equipo y git push -f, en GitHub (Git 3 · Mover una etiqueta):

git tag -fa entrega-fundamentos-iac-e2 main -m "E2 resuelto"
git push -f origin entrega-fundamentos-iac-e2

Si pruebas.py dice que en GitHub ya existe la etiqueta y no la tienes aquí, la creaste en otro equipo: tráetela con git fetch --tags.
