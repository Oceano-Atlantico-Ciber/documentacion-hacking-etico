E1 · A mano, una vez

Crea con la CLI de AWS un bucket con un fichero y un usuario que solo pueda leerlo. Apunta las órdenes en un fichero: en el E3 ese mismo trabajo pasará a Terraform.

Qué entregas

En fundamentos/iac/e1/ de main:

FicheroQué es
notas.txtEl que deja preparar.py, sin cambiar.
politica.jsonLa política del lector: solo leer los ficheros de tu bucket.
ordenes.shLas cuatro órdenes aws que crean todo, una por línea, con tus nombres escritos tal cual.
LEEME.mdEl que deja preparar.py, con tus nombres.

Junto a e1/, en fundamentos/iac/, van también el docker-compose.yml y el .gitignore que deja preparar.py. Así queda ordenes.sh (tu huella será otra):

aws s3 mb s3://e1-notas-1a2b3c4d
aws s3 cp notas.txt s3://e1-notas-1a2b3c4d/notas.txt
aws iam create-user --user-name lector-1a2b3c4d
aws iam put-user-policy --user-name lector-1a2b3c4d --policy-name lectura-notas --policy-document file://politica.json

ordenes.sh es un fichero de texto con órdenes, no un programa que tengas que ejecutar: las lanzas tú a mano en los pasos 2 y 3, y el corrector las lee una a una y las repite en una cuenta vacía, desde e1/. Después comprueba la cuenta con la clave del lector. La etiqueta anotada entrega-fundamentos-iac-e1 va sobre main, subida a GitHub.

1Prepara el ejercicio y levanta tu nube

Antes, instala y configura la CLI de AWS y Terraform como dice IaC 1 · Prepara tu equipo (si aws sale como «no se reconoce», cierra VS Code entero y vuelve a abrirlo), y abre Docker Desktop. Abre la terminal de VS Code (Terminal → New Terminal; en Windows es PowerShell). Ve a tu repositorio, trae la última versión del material y vuelve a main. Cambia <tu-usuario> por tu usuario de GitHub:

cd ~/hacking-etico/entregas-<tu-usuario>
git -C ../documentacion-hacking-etico pull
git switch main

Crea el punto de partida:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/preparar.py e1

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/preparar.py e1
e1 preparado para <tu-usuario> en fundamentos/iac/e1/. Sigue el enunciado.

Levanta la Floci de la unidad, comprueba que responde y entra en la carpeta del ejercicio:

cd fundamentos/iac
docker compose up -d
aws sts get-caller-identity
cd e1
code LEEME.md

code LEEME.md lo abre en VS Code: léelo ahí y copia de ahí tus nombres.

La primera vez, docker compose up -d descarga la imagen de Floci. aws sts get-caller-identity debe responder un JSON con "Account"; si dice Could not connect to the endpoint URL, espera unos segundos y repite. LEEME.md tiene tus nombres:

# E1 · A mano, una vez

Tus nombres para este ejercicio:

- Bucket: e1-notas-1a2b3c4d
- Fichero que hay que subir: notas.txt (ya está en esta carpeta; no lo cambies)
- Usuario: lector-1a2b3c4d, con una política en línea llamada lectura-notas
…

1a2b3c4d es tu huella: sale de tu usuario de GitHub y cada alumno tiene la suya. En todas las órdenes de abajo, cambia <huella> por la tuya, sin los < >. No cambies notas.txt: el corrector compara lo que subes con el que te ha generado.

2Crea el bucket y sube el fichero

Desde fundamentos/iac/e1/:

aws s3 mb s3://e1-notas-<huella>
aws s3 cp notas.txt s3://e1-notas-<huella>/notas.txt
aws s3 ls s3://e1-notas-<huella>
make_bucket: e1-notas-1a2b3c4d
Completed 62 Bytes/62 Bytes (…) with 1 file(s) remaining
upload: ./notas.txt to s3://e1-notas-1a2b3c4d/notas.txt
2026-11-19 10:00:00         62 notas.txt

La fecha y el tamaño serán otros, y en Windows la ruta del fichero sale como .\notas.txt. La última orden solo mira: no va en ordenes.sh.

3Crea el lector y su política

El lector solo debe poder leer los ficheros de tu bucket: ni borrarlos, ni escribir, ni tocar IAM. Para eso basta s3:GetObject sobre arn:aws:s3:::e1-notas-<huella>/* (el /* son los objetos de dentro del bucket; mira IaC 1 · Políticas de IAM). Crea el fichero en VS Code:

code politica.json

Escribe esto, con tu huella, y guarda (Ctrl+S; en macOS, Cmd+S):

{
  "Version": "2012-10-17",
  "Statement": [
    { "Effect": "Allow", "Action": "s3:GetObject", "Resource": "arn:aws:s3:::e1-notas-<huella>/*" }
  ]
}

Crea el usuario y dale la política:

aws iam create-user --user-name lector-<huella>
aws iam put-user-policy --user-name lector-<huella> --policy-name lectura-notas --policy-document file://politica.json

create-user responde un JSON con el usuario ("UserName": "lector-1a2b3c4d" y su "Arn"); put-user-policy no escribe nada si ha ido bien. Si dice MalformedPolicyDocument, a politica.json le falta una coma, una llave o unas comillas.

4Compruébalo como el lector

Crea una clave para el lector y guárdala en un perfil aparte, lector. Esta clave es solo para probar: no va en ordenes.sh ni en ningún fichero.

aws iam create-access-key --user-name lector-<huella>
{
    "AccessKey": {
        "UserName": "lector-1a2b3c4d",
        "AccessKeyId": "AKIA…",
        "Status": "Active",
        "SecretAccessKey": "…",
        …

Copia los dos valores en estas órdenes, en el lugar de <AccessKeyId> y <SecretAccessKey>:

aws configure set aws_access_key_id <AccessKeyId> --profile lector
aws configure set aws_secret_access_key <SecretAccessKey> --profile lector
aws configure set region eu-west-1 --profile lector
aws configure set endpoint_url http://localhost:4566 --profile lector

Ahora, como el lector, lee el fichero, intenta borrarlo e intenta listar los usuarios:

aws s3 cp s3://e1-notas-<huella>/notas.txt - --profile lector
aws s3 rm s3://e1-notas-<huella>/notas.txt --profile lector
aws iam list-users --profile lector
Notas de la auditoría de <tu-usuario>
Referencia: …
delete failed: s3://e1-notas-1a2b3c4d/notas.txt An error occurred (AccessDenied) when calling the DeleteObject operation: …
aws: [ERROR]: An error occurred (AccessDenied) when calling the ListUsers operation: …

En la primera orden, el - del final significa «a la pantalla»: en vez de copiar notas.txt a un fichero, lo escribe en la terminal. La lectura enseña el fichero; las otras dos acaban en AccessDenied. Si sale otra cosa:

  • La lectura da AccessDenied: revisa el Resource de politica.json (tu huella, y el /* del final). Corrige el fichero y repite el put-user-policy del paso 3: sustituye la política.
  • El borrado o el listado funcionan: tu política da de más. Corrígela igual. Si se ha llegado a borrar notas.txt, vuelve a subirlo con el aws s3 cp del paso 2.

5Apunta lo que has hecho

code ordenes.sh

Escribe las cuatro órdenes que crean todo, en el orden en que las lanzaste: las dos primeras del paso 2 y las dos del paso 3. Queda como en Qué entregas, con tu huella. Guarda.

  • Una orden por línea, empezando por aws. Las líneas en blanco y las que empiezan por # (comentarios) se saltan.
  • Los nombres, escritos tal cual: nada de <huella>, ni variables ($…), ni redirecciones (>, |).
  • Los ficheros, con su nombre a secas (notas.txt, file://politica.json): el corrector lanza las órdenes desde e1/, con los ficheros de tu commit.
  • Nada del paso 4: ni create-access-key, ni configure, ni las pruebas. El corrector quita --profile, así que aws s3 rm … --profile lector borraría tu fichero como administrador.

El corrector marca fallo si:

  • Falta ordenes.sh, o no tiene ninguna orden aws.
  • Alguna línea no es una orden aws de s3, s3api, iam o sts; lleva variables o caracteres de la shell ($ ; | & ` < >) o comillas sin cerrar; o usa un fichero de fuera de e1/.
  • Alguna orden falla en una cuenta nueva: por ejemplo, porque politica.json no está en el commit.
  • No existe s3://e1-notas-<huella>/notas.txt, o su contenido no es el de notas.txt que te dio preparar.py.
  • No existe el usuario lector-<huella>, o no tiene una política en línea llamada lectura-notas.
  • Con una clave suya, el lector no puede leer notas.txt, o puede borrarlo, o puede listar los usuarios de IAM.

6Haz commit y pruébalo

Primero, haz commit. Vuelve a la carpeta del repositorio y mira qué vas a añadir:

cd ~/hacking-etico/entregas-<tu-usuario>
git status --short -uall fundamentos/iac
?? fundamentos/iac/.gitignore
?? fundamentos/iac/docker-compose.yml
?? fundamentos/iac/e1/LEEME.md
?? fundamentos/iac/e1/notas.txt
?? fundamentos/iac/e1/ordenes.sh
?? fundamentos/iac/e1/politica.json
git add fundamentos/iac
git commit -m "feat(iac-e1): bucket y lector creados a mano"

En Windows, git add puede avisar LF will be replaced by CRLF: no es un error, puedes ignorarlo.

pruebas.py evalúa tu etiqueta entrega-fundamentos-iac-e1, o la rama main si aún no la tienes, con las mismas comprobaciones que el corrector. Solo cuentan los commits: lo que no esté en un commit no se evalúa. Trabaja en una Floci aparte y vacía, así que no toca tu repositorio ni tu Floci.

Necesita Docker Desktop en marcha. Desde la carpeta de tu repositorio:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/pruebas.py e1

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/pruebas.py e1

La primera vez descarga las imágenes de Floci, la CLI de AWS y Terraform, y tarda unos minutos. Antes de subir, un ejercicio bien hecho se ve así:

E1 · main, todavía sin etiqueta (provisional) · 7a8b9c0 · comprobando…
  ✓ superado
  ! main aún no está en GitHub: el corrector no lo verá hasta que lo subas
  • ✓ superado: pasa todas las comprobaciones.
  • ✗ es un fallo: el corrector también lo marcará. La línea dice qué ha encontrado y por qué no vale. Corrígelo, haz commit y vuelve a lanzar pruebas.py.
  • ! es un aviso: tu trabajo puede estar bien, pero el corrector evalúa lo que hay en GitHub, no tu equipo, y algo no coincide: «aún no está en GitHub» o «en GitHub … apunta a …, no a tu …». Antes de subir es normal: desaparece al subir en el paso siguiente. Los SHA de tus líneas serán otros.
  • sin empezar: no hay etiqueta ni fundamentos/iac/e1/ en main: falta preparar el ejercicio o hacer su commit.

7Sube y etiqueta

Sube tu trabajo a GitHub:

git push

Vuelve a lanzar pruebas.py (paso anterior). Cuando diga ✓ superado y no quede ningún aviso !, crea la etiqueta anotada sobre main y súbela:

git tag -a entrega-fundamentos-iac-e1 main -m "E1 resuelto"
git push origin entrega-fundamentos-iac-e1

Lanza pruebas.py otra vez. Ahora evalúa la etiqueta:

E1 · etiqueta entrega-fundamentos-iac-e1 · 7a8b9c0 · comprobando…
  ✓ superado

En GitHub, el resultado del corrector está en la portada de tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector iac. Hay una fila por ejercicio. Se actualiza cuando el docente lanza la corrección, no en cada push.

Si hay que corregir algo después de etiquetar

  • Si has cambiado ficheros: corrige en fundamentos/iac/e1/, haz commit y súbelo con git push. Después mueve la etiqueta al commit nuevo con las dos órdenes de abajo. Hasta que la muevas, pruebas.py sigue evaluando la etiqueta antigua.
  • Si solo falla la etiqueta, porque pruebas.py marca ✗ la etiqueta no es anotada o avisa de que en GitHub apunta a otro commit: muévela, sin hacer ningún commit.

Para mover la etiqueta, -f la reemplaza en tu equipo y git push -f, en GitHub (Git 3 · Mover una etiqueta):

git tag -fa entrega-fundamentos-iac-e1 main -m "E1 resuelto"
git push -f origin entrega-fundamentos-iac-e1

Si pruebas.py dice que en GitHub ya existe la etiqueta y no la tienes aquí, la creaste en otro equipo: tráetela con git fetch --tags.

El E3 y el E4 vuelven a lanzar tu ordenes.sh: si lo cambias más adelante, repasa también esos dos.
