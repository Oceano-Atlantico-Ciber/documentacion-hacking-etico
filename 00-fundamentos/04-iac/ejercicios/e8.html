2Corrige

code empresa.tf

Lo que cada uno necesita para su trabajo, y nada más. Haz en empresa.tf las correcciones de tu auditoría:

  • El becario lee los informes, y ya. En su política (aws_iam_user_policy.becario), borra entera la sentencia AjustarseLosPermisos, desde su { hasta su },, y deja LeerInformes como está.
  • Operaciones administra el servidor web: solo acciones de EC2. En su política (aws_iam_user_policy.operaciones), cambia Action = "*" por Action = "ec2:*". Así no toca IAM ni los datos de dirección.
  • La clave del becario se filtró: se revoca. Borra el recurso aws_iam_access_key.becario y las dos salidas que la enseñan, becario_clave y becario_secreto.
  • No borres ningún usuario ni ningún bucket.

Guarda, y desde fundamentos/iac/e8/empresa/:

terraform plan

…

Plan: 0 to add, 2 to change, 1 to destroy.

3Comprueba el arreglo

Repite las simulaciones del E7, con los mismos ARN (si no los tienes, aws iam get-user --user-name … --query User.Arn). Lo que antes era allowed ahora es implicitDeny, y lo que necesitan para su trabajo sigue allowed:

aws iam simulate-principal-policy --policy-source-arn <ARN del becario> --action-names iam:PutUserPolicy iam:AttachUserPolicy iam:CreateAccessKey --resource-arns <ARN del becario>
aws iam simulate-principal-policy --policy-source-arn <ARN del becario> --action-names s3:GetObject --resource-arns "arn:aws:s3:::informes-<huella>/*" "arn:aws:s3:::secretos-<huella>/*"
aws iam simulate-principal-policy --policy-source-arn <ARN de operaciones> --action-names iam:PutUserPolicy iam:CreateAccessKey --resource-arns <ARN de operaciones>
aws iam simulate-principal-policy --policy-source-arn <ARN de operaciones> --action-names ec2:DescribeInstances --resource-arns "*"
aws iam list-access-keys --user-name becario-<huella>

Tiene que salir:

  • Becario: las tres acciones de IAM, implicitDeny; s3:GetObject, allowed en informes-… e implicitDeny en secretos-….
  • Operaciones: las acciones de IAM, implicitDeny; ec2:DescribeInstances, allowed.
  • Claves del becario: "AccessKeyMetadata": [], ninguna.

El corrector marca fallo si, con tu empresa.tf aplicado en una cuenta nueva:

  • Falta empresa/empresa.tf o empresa/proveedor.tf, o terraform init o apply fallan.
  • Falta alguno de los tres buckets, el becario u operaciones.
  • El becario sigue teniendo una clave de acceso.
  • La simulación permite al becario o a operaciones iam:PutUserPolicy, iam:AttachUserPolicy, iam:CreateAccessKey o iam:CreatePolicyVersion sobre su propio usuario.
  • La simulación permite al becario o a operaciones s3:GetObject en secretos-<huella>.
  • Con una clave nueva que crea el corrector, el becario no puede leer informe-semanal.txt de informes-<huella>.
  • La simulación no permite a operaciones ec2:DescribeInstances.

5Sube y etiqueta

Sube tu trabajo a GitHub:

git push

Vuelve a lanzar pruebas.py (paso anterior). Cuando diga ✓ superado y no quede ningún aviso !, crea la etiqueta anotada sobre main y súbela:

git tag -a entrega-fundamentos-iac-e8 main -m "E8 resuelto"
git push origin entrega-fundamentos-iac-e8

Lanza pruebas.py otra vez. Ahora evalúa la etiqueta:

E8 · etiqueta entrega-fundamentos-iac-e8 · 7a8b9c0 · comprobando…
  ✓ superado

No hay fecha límite: entrega cada ejercicio cuando lo tengas. El progreso de cada alumno se ve en la tabla pública de entregas.

En GitHub, el resultado del corrector está en la portada de tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector iac. Hay una fila por ejercicio. Se actualiza cuando el docente lanza la corrección, no en cada push.

Si hay que corregir algo después de etiquetar

Corrige en fundamentos/iac/e8/, haz commit y súbelo con git push. Después mueve la etiqueta al commit nuevo: -f la reemplaza en tu equipo y git push -f, en GitHub (Git 3 · Mover una etiqueta). Hasta que la muevas, pruebas.py sigue evaluando la etiqueta antigua. Haz solo esto, sin commits, si pruebas.py marca ✗ la etiqueta no es anotada o avisa de que en GitHub apunta a otro commit:

git tag -fa entrega-fundamentos-iac-e8 main -m "E8 resuelto"
git push -f origin entrega-fundamentos-iac-e8

Si pruebas.py dice que en GitHub ya existe la etiqueta y no la tienes aquí, la creaste en otro equipo: tráetela con git fetch --tags.
