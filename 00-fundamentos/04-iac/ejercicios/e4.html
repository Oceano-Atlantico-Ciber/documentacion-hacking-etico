Qué entregas

En fundamentos/iac/e4/ de main:

FicheroQué es

Con tu código aplicado, terraform output da (tu huella será otra):

bucket = "e1-notas-1a2b3c4d"
usuario = "lector-1a2b3c4d"

El corrector lanza tu e1/ordenes.sh en una cuenta vacía, aplica tu código, borra a mano la política lectura-notas y comprueba que el plan lo ve y que apply la recupera. La etiqueta anotada entrega-fundamentos-iac-e4 va sobre main, subida a GitHub.

1Prepara el ejercicio

Abre la terminal de VS Code (Terminal → New Terminal; en Windows es PowerShell). Ve a tu repositorio, trae la última versión del material y vuelve a main. Cambia <tu-usuario> por tu usuario de GitHub:

cd ~/hacking-etico/entregas-<tu-usuario>
git -C ../documentacion-hacking-etico pull
git switch main

Crea el punto de partida:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/preparar.py e4

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/preparar.py e4
e4 preparado para <tu-usuario> en fundamentos/iac/e4/. Sigue el enunciado.

preparar.py ha copiado tu E3 en e4/ (no tienes que copiar nada): todos sus ficheros, sin el estado ni .terraform/. Ha cambiado el LEEME.md por uno con la orden del «compañero». Entra y léelo:

cd fundamentos/iac/e4
code LEEME.md

code LEEME.md lo abre en VS Code: léelo ahí y copia de ahí tus nombres.

Como el estado no se copia, esta carpeta empieza sin saber nada de la cuenta: los bloques import del E3 vuelven a hacer falta aquí. Déjalos. Lo del E1 debe seguir en tu Floci, como en el E3.

2Variables y salidas

Crea variables.tf con una variable para tu huella, que es lo que se repite en los nombres:

code variables.tf
variable "huella" {
  description = "La parte de los nombres que distingue mis recursos"
  type        = string
  default     = "<huella>"
}

El default es obligatorio aquí: el corrector no puede contestar si Terraform pregunta un valor, y sin default terraform apply se pararía a pedirlo. En main.tf, cambia tu huella escrita a mano por la variable, en los nombres y en los id de los import (antes → después):

"e1-notas-<huella>"              →  "e1-notas-${var.huella}"
"lector-<huella>"                →  "lector-${var.huella}"
"lector-<huella>:lectura-notas"  →  "lector-${var.huella}:lectura-notas"

Después, las salidas:

code outputs.tf
output "bucket" {
  value = aws_s3_bucket.notas.bucket
}

output "usuario" {
  value = aws_iam_user.lector.name
}

Guarda los tres ficheros y, desde fundamentos/iac/e4/:

terraform init
terraform plan

Como en el E3, debe decir Plan: 3 to import, 0 to add, 0 to change, 0 to destroy. y, además, Changes to Outputs: con tus dos salidas. Si no, revisa lo que has cambiado en main.tf. Aplica (yes) y mira las salidas y otro plan:

terraform apply
terraform output
terraform plan

terraform output da el bucket y el usuario, como en Qué entregas, y el último plan dice No changes.

3El compañero toca a mano

Ahora haces de compañero: lanza la orden del LEEME.md, que borra la política lectura-notas del lector sin pasar por Terraform. Es esta, con tu huella:

aws iam delete-user-policy --user-name lector-<huella> --policy-name lectura-notas

No escribe nada. Nadie lo ha visto todavía. Pregunta a Terraform:

terraform plan
  # aws_iam_user_policy.lectura will be created
  + resource "aws_iam_user_policy" "lectura" {
…
Plan: 1 to add, 0 to change, 0 to destroy.

El plan ha descubierto que falta la política, porque pregunta a la API cómo está cada recurso. Copia esa última línea: va en deriva.md. Deja la cuenta como dice el código:

terraform apply
terraform plan

apply (con yes) termina en Apply complete! Resources: 1 added, 0 changed, 0 destroyed. y el último plan vuelve a decir No changes.

4Explícalo

code deriva.md

Cuatro respuestas cortas, con esta forma:

# Deriva en la cuenta

- Qué cambió a mano: …
- Cómo lo vi en el plan: …
- Qué hice: …
- Qué tendría que haber hecho el compañero: …

Nombra la política que desapareció, copia la línea del resumen del plan y di qué tendría que haber hecho el compañero en vez de tocar a mano (IaC 2 · Deriva).

El corrector marca fallo si:

  • Falta main.tf, proveedor.tf o deriva.md.
  • No hay ninguna variable propia en los .tf (la variable floci de proveedor.tf no cuenta).
  • Tu e1/ordenes.sh falla en una cuenta nueva, o terraform init o apply fallan (por ejemplo, por una variable sin default).
  • Las salidas no dan el nombre del bucket y el del usuario.
  • Recién aplicado, el plan quiere cambiar algo.
  • Después de borrar a mano la política lectura-notas, el plan no lo ve, o apply no la recupera.
  • deriva.md no nombra la política lectura-notas.

5Haz commit y pruébalo

Primero, haz commit. Vuelve a la carpeta del repositorio y mira qué vas a añadir:

cd ~/hacking-etico/entregas-<tu-usuario>
git status --short -uall fundamentos/iac/e4
?? fundamentos/iac/e4/LEEME.md
?? fundamentos/iac/e4/deriva.md
?? fundamentos/iac/e4/main.tf
?? fundamentos/iac/e4/outputs.tf
?? fundamentos/iac/e4/proveedor.tf
?? fundamentos/iac/e4/variables.tf

No debe salir ningún terraform.tfstate ni nada de .terraform/: el .gitignore de fundamentos/iac/ los deja fuera, porque el estado puede guardar secretos.

git add fundamentos/iac/e4
git commit -m "feat(iac-e4): variables, salidas y deriva corregida"

pruebas.py evalúa tu etiqueta entrega-fundamentos-iac-e4, o la rama main si aún no la tienes, con las mismas comprobaciones que el corrector. Solo cuentan los commits: lo que no esté en un commit no se evalúa. Trabaja en una Floci aparte y vacía, así que no toca tu repositorio ni tu Floci.

Necesita Docker Desktop en marcha. Desde la carpeta de tu repositorio:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/pruebas.py e4

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/04-iac/ejercicios/pruebas.py e4

Antes de subir, un ejercicio bien hecho se ve así:

E4 · main, todavía sin etiqueta (provisional) · 7a8b9c0 · comprobando…
  ✓ superado
  ! main aún no está en GitHub: el corrector no lo verá hasta que lo subas
  • ✓ superado: pasa todas las comprobaciones.
  • ✗ es un fallo: el corrector también lo marcará. La línea dice qué ha encontrado y por qué no vale. Corrígelo, haz commit y vuelve a lanzar pruebas.py.
  • ! es un aviso: tu trabajo puede estar bien, pero el corrector evalúa lo que hay en GitHub, no tu equipo, y algo no coincide: «aún no está en GitHub» o «en GitHub … apunta a …, no a tu …». Antes de subir es normal: desaparece al subir en el paso siguiente. Los SHA de tus líneas serán otros.
  • sin empezar: no hay etiqueta ni fundamentos/iac/e4/ en main: falta preparar el ejercicio o hacer su commit.

6Sube y etiqueta

Sube tu trabajo a GitHub:

git push

Vuelve a lanzar pruebas.py (paso anterior). Cuando diga ✓ superado y no quede ningún aviso !, crea la etiqueta anotada sobre main y súbela:

git tag -a entrega-fundamentos-iac-e4 main -m "E4 resuelto"
git push origin entrega-fundamentos-iac-e4

Lanza pruebas.py otra vez. Ahora evalúa la etiqueta:

E4 · etiqueta entrega-fundamentos-iac-e4 · 7a8b9c0 · comprobando…
  ✓ superado

En GitHub, el resultado del corrector está en la portada de tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector iac. Hay una fila por ejercicio. Se actualiza cuando el docente lanza la corrección, no en cada push.

Si hay que corregir algo después de etiquetar

  • Si has cambiado ficheros: corrige en fundamentos/iac/e4/, haz commit y súbelo con git push. Después mueve la etiqueta al commit nuevo con las dos órdenes de abajo. Hasta que la muevas, pruebas.py sigue evaluando la etiqueta antigua.
  • Si solo falla la etiqueta, porque pruebas.py marca ✗ la etiqueta no es anotada o avisa de que en GitHub apunta a otro commit: muévela, sin hacer ningún commit.

Para mover la etiqueta, -f la reemplaza en tu equipo y git push -f, en GitHub (Git 3 · Mover una etiqueta):

git tag -fa entrega-fundamentos-iac-e4 main -m "E4 resuelto"
git push -f origin entrega-fundamentos-iac-e4

Si pruebas.py dice que en GitHub ya existe la etiqueta y no la tienes aquí, la creaste en otro equipo: tráetela con git fetch --tags.
