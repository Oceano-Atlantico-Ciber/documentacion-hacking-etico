Qué entregas

main con las dos ramas que crea preparar.py integradas, cada una de una forma:

RamaCómo entra en main
git/e3-ffCon fast-forward: su commit feat(e3): rama para fast-forward queda en la línea de main, sin merge.
git/e3-noffCon un commit de merge (--no-ff) en main que trae su commit feat(e3): rama para merge con commit.

Cada uno de esos dos commits aparece una sola vez en la historia, y ff.txt y noff.txt quedan como los dejó preparar.py. La etiqueta anotada entrega-fundamentos-git-e3 va sobre main, subida a GitHub. Así se ve con git log --oneline --graph -4 (tus SHA serán otros):

*   7a8b9c0 (HEAD -> main, tag: entrega-fundamentos-git-e3, origin/main) Merge branch 'git/e3-noff'
|\
| * 4d5e6f7 (git/e3-noff) feat(e3): rama para merge con commit
* | 2b3c4d5 (git/e3-ff) feat(e3): rama para fast-forward
|/
* 6e7f8a9 chore(e2): ignorar lo que genera la app

1Prepara el escenario

Abre la terminal de VS Code (Terminal → New Terminal; en Windows es PowerShell). Ve a tu repositorio, trae la última versión del material, vuelve a main y mira que no tengas nada a medias. Cambia <tu-usuario> por tu usuario de GitHub:

cd ~/hacking-etico/entregas-<tu-usuario>
git -C ../documentacion-hacking-etico pull
git switch main
git status

git status tiene que terminar en nothing to commit, working tree clean. Si lista ficheros, termina o descarta antes lo que tengas a medias: preparar.py no sigue con cambios pendientes. Después, crea el punto de partida:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e3

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e3
e3 preparado para <tu-usuario> en fundamentos/git/e3/. Sigue el enunciado.

Crea las ramas git/e3-ff y git/e3-noff, con un commit cada una, y te deja en main. Míralas:

git log --oneline --graph --all -4
* 2b3c4d5 (git/e3-ff) feat(e3): rama para fast-forward
| * 4d5e6f7 (git/e3-noff) feat(e3): rama para merge con commit
|/
* 6e7f8a9 (HEAD -> main, origin/main) chore(e2): ignorar lo que genera la app

Las dos ramas salen del commit en el que está main. Haz los pasos 2 y 3 seguidos, sin otros commits en main entre medias.

2Fusiona git/e3-ff con fast-forward

git merge --ff-only git/e3-ff
Updating 6e7f8a9..2b3c4d5
Fast-forward
 fundamentos/git/e3/ff.txt | 1 +
 1 file changed, 1 insertion(+)

main avanza hasta el commit de la rama, sin crear ningún commit nuevo. Hazlo antes del paso 3: después ya no sería posible.

Si sale fatal: Not possible to fast-forward, aborting., main ha avanzado desde que preparaste el ejercicio. Pon la rama encima de main y repite el merge:

git switch git/e3-ff
git rebase main
git switch main
git merge --ff-only git/e3-ff

3Fusiona git/e3-noff con commit de merge

git merge --no-ff --no-edit git/e3-noff
Merge made by the 'ort' strategy.
 fundamentos/git/e3/noff.txt | 1 +
 1 file changed, 1 insertion(+)

--no-ff obliga a crear un commit de merge aunque se pudiera avanzar sin él, y --no-edit acepta el mensaje que propone git (Merge branch 'git/e3-noff') sin abrir el editor.

4Comprueba antes de subir

git log --oneline --graph -4

Arriba, un commit de merge con dos líneas que se juntan: una trae el commit de git/e3-noff y la otra es la línea de main, donde está el commit de git/e3-ff sin merge propio. Compáralo con Qué entregas.

El corrector marca fallo si:

  • Falta el commit feat(e3): rama para fast-forward o el feat(e3): rama para merge con commit, o alguno aparece más de una vez: se copió (con cherry-pick o rehaciéndolo) en lugar de integrarse.
  • El commit de git/e3-ff lo trajo un merge, o no está en la línea principal de main.
  • git/e3-noff no entró con un commit de merge: entró con fast-forward, o no se ha integrado.
  • Falta ff.txt o noff.txt, o su contenido no es el que dejó preparar.py.
  • La etiqueta no es anotada: se creó sin -a.
  • La etiqueta se subió a GitHub, o se movió, después del cierre del plazo (05/11/2026, 23:59): sale «entregada fuera de plazo».

5Pruébalo en tu equipo

pruebas.py pasa las mismas comprobaciones que el corrector, con el mismo código. Evalúa la etiqueta entrega-fundamentos-git-e3 si ya la tienes y, si no, la rama main. Solo mira commits: lo que no esté en un commit no cuenta. No cambia nada de tu repositorio. Desde la carpeta de tu repositorio:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e3

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e3

Antes de subir, un ejercicio bien hecho se ve así (tus SHA serán otros):

E3 · rama main, todavía sin etiqueta (provisional) · 7a8b9c0
  ✓ superado
  ! en GitHub main apunta a 6e7f8a9, no a tu 7a8b9c0: el corrector evaluará el de GitHub. Sube el tuyo (…)
  • ✓ superado: pasa todas las comprobaciones.
  • ✗ es un fallo: el corrector también lo marcará. La línea dice qué ha encontrado y por qué no vale. Corrígelo, haz commit y vuelve a lanzar pruebas.py.
  • ! es un aviso: tu trabajo puede estar bien, pero el corrector evalúa lo que hay en GitHub, no tu equipo, y algo no coincide. Antes de subir es normal ver «aún no está en GitHub» o «en GitHub … apunta a …, no a tu …»: desaparece al subir en el paso siguiente. En ese aviso, el primer SHA es lo que tiene GitHub (lo último que subiste) y el segundo, tu commit.
  • sin empezar: no hay etiqueta ni trabajo en fundamentos/git/e3/ de main: falta preparar el ejercicio o hacer sus commits.
  • Si al final sale Aviso: sin el GitHub CLI con sesión iniciada (gh auth login) no se ha comprobado lo que solo sabe GitHub: el autor de los commits de E1, el commit filtrado de E8 y la hora de las etiquetas, en este ejercicio te afecta solo la hora de la etiqueta (el plazo). El corrector sí lo comprueba. Inicia sesión con gh auth login y repite.

6Sube y etiqueta

Sube tu trabajo a GitHub:

git push

Vuelve a lanzar pruebas.py (paso anterior). Cuando diga ✓ superado y no quede ningún aviso ! de GitHub, crea la etiqueta anotada sobre main y súbela:

git tag -a entrega-fundamentos-git-e3 main -m "E3 resuelto"
git push origin entrega-fundamentos-git-e3

Lanza pruebas.py otra vez. Ahora evalúa la etiqueta:

E3 · etiqueta entrega-fundamentos-git-e3 · 7a8b9c0
  ✓ superado
  ! el plazo cerró el 05/11/2026 a las 23:59: sin gh no sé a qué hora subiste la etiqueta; si fue después, el corrector la marcará fuera de plazo

Plazo. Cerró el jueves 5 de noviembre de 2026 a las 23:59. El corrector mira a qué hora se subió a GitHub la etiqueta, o se movió por última vez: si fue después, la entrega sale entregada fuera de plazo. Con gh, pruebas.py lo marca con ✗; sin gh, solo avisa con !, como arriba. Una etiqueta creada en tu equipo y aún sin subir sale con ✗ «entregada fuera de plazo si la subes ahora».

En GitHub, el resultado del corrector está en la portada de tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector git. Hay una fila por ejercicio: ✅ entregado y superado, ❌ entregado con fallos, ✏️ provisional (aún sin etiqueta) y · sin empezar. Se actualiza cuando el docente lanza la corrección, no en cada push.

Si hay que corregir algo después de etiquetar

  • Falta integrar una rama: haz su merge tal como en el paso 2 (git/e3-ff, con --ff-only) o en el 3 (git/e3-noff, con --no-ff) y súbelo con git push.
  • No copies commits con cherry-pick ni los rehagas a mano: cada commit de las ramas tiene que aparecer una sola vez.
  • Una rama entró de la forma equivocada y ya está subida (por ejemplo, git/e3-ff con un merge): no reescribas main; pregunta al docente.

Cuando pruebas.py vuelva a decir ✓ superado sobre la rama, mueve la etiqueta al commit corregido: -f la reemplaza en tu equipo y git push -f, en GitHub (Git 3 · Mover una etiqueta). Haz solo esto, sin tocar commits, si pruebas.py dice que la etiqueta no es anotada o que en GitHub apunta a otro commit:

git tag -fa entrega-fundamentos-git-e3 main -m "E3 resuelto"
git push -f origin entrega-fundamentos-git-e3

Moverla cuenta como subirla de nuevo: si ya ha cerrado el plazo, la entrega pasa a estar fuera de plazo. Si pruebas.py dice «en GitHub ya existe entrega-fundamentos-git-e3 y no la tienes aquí», la creaste en otro equipo: tráetela con git fetch --tags.
