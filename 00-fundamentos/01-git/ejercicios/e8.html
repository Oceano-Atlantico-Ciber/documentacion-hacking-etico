E8 · Secreto filtrado

Alguien subió una clave de API y luego la borró. Encuéntrala en la historia, púrgala y comprueba qué queda en GitHub.

Teoría
Git 4 · Deshacer y seguridad
Trabajas en

Etiqueta
entrega-fundamentos-git-e8 sobre git/e8-app

Qué entregas

La rama git/e8-app purgada de la clave y con tu hallazgo:

  • Siguen los cuatro commits de la rama: feat(e8): cliente de la API, feat(e8): conexión con clave, chore(e8): no versionar .env y docs(e8): instrucciones. Se purga el fichero, no los commits.
  • La clave no aparece en ningún commit de la rama, y app.py queda como estaba.
  • Un commit más encima con fundamentos/git/e8/hallazgo.txt: el SHA completo, de 40 caracteres, del commit que subió la clave a GitHub. Ese commit ya no está en la rama, porque la purga le cambia el SHA.
  • La rama subida a GitHub y la etiqueta anotada entrega-fundamentos-git-e8 sobre git/e8-app, también subida.

Así se ve con git log --oneline -5 git/e8-app (tus SHA serán otros):

f2a3b4c (HEAD -> git/e8-app, tag: entrega-fundamentos-git-e8, origin/git/e8-app) docs(e8): commit que filtró la clave
e1f2a3c docs(e8): instrucciones
d0e1f2a chore(e8): no versionar .env
c9d0e1f feat(e8): conexión con clave
b8c9d0f feat(e8): cliente de la API

El orden importa: primero se sube la rama con la clave (paso 2) y después se purga. Si purgas antes de subir, GitHub nunca conoce el commit filtrado y el ejercicio no se puede superar.

1Prepara el escenario

Abre la terminal de VS Code (Terminal → New Terminal; en Windows es PowerShell). Ve a tu repositorio, trae la última versión del material, vuelve a main y mira que no tengas nada a medias. Cambia <tu-usuario> por tu usuario de GitHub:

cd ~/hacking-etico/entregas-<tu-usuario>
git -C ../documentacion-hacking-etico pull
git switch main
git status

git status tiene que terminar en nothing to commit, working tree clean. Si lista ficheros, termina o descarta antes lo que tengas a medias: preparar.py no sigue con cambios pendientes. Después, crea el punto de partida:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e8

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e8
e8 preparado para <tu-usuario> en fundamentos/git/e8/. Sigue el enunciado.

Crea git/e8-app con cuatro commits y te deja en main. En uno de ellos alguien subió un .env con una clave de API, y en otro lo borró.

2Sube la rama tal cual

git push -u origin git/e8-app
 * [new branch]      git/e8-app -> git/e8-app
branch 'git/e8-app' set up to track 'origin/git/e8-app'.

Así simulas la filtración real: la clave ya está en GitHub. Sin este paso el ejercicio no se puede superar.

3Encuentra el commit que la introdujo

git log -p -S API_KEY= git/e8-app

-S busca los commits que añaden o quitan ese texto, y -p enseña su cambio. Salen dos: uno añade el .env (línea +API_KEY=…) y otro lo borra (-API_KEY=…). Si la salida no cabe en pantalla, baja con las flechas y sal con q. Para ver los SHA completos:

git log --format="%H %s" -S API_KEY= git/e8-app
a1b2c3d4e5f60718293a4b5c6d7e8f9012345678 chore(e8): no versionar .env
0718293a4b5c6d7e8f9012345678a1b2c3d4e5f6 feat(e8): conexión con clave

Apunta el SHA completo, de 40 caracteres, del commit que añade la clave: el que en la salida de git log -p tiene la línea +API_KEY=…, que es feat(e8): conexión con clave. En el ejemplo, 0718293a4b5c6d7e8f9012345678a1b2c3d4e5f6. El otro, chore(e8): no versionar .env, es el que la borra (-API_KEY=…): ese no.

4Purga el .env de toda la rama

git-filter-repo ya lo tienes instalado desde 03 · Git y GitHub. Antes, comprueba que no tienes nada a medias:

git status

Tiene que decir nothing to commit, working tree clean. Al terminar, git-filter-repo deja la rama en la que estás (aquí main) exactamente como en su último commit, con un git reset --hard: lo que no estuviera en un commit se perdería. Reescribe todos los commits de git/e8-app sin ese fichero:

Windows · PowerShell

py -m git_filter_repo --refs git/e8-app --path fundamentos/git/e8/.env --invert-paths --force

macOS / Linux · Terminal

git filter-repo --refs git/e8-app --path fundamentos/git/e8/.env --invert-paths --force
Parsed 21 commits
HEAD is now at 6a7b8c9 Revert "feat(e7): activar modo depuración"

New history written in 0.14 seconds...
Completely finished after 0.24 seconds.

El número de commits será otro. La línea HEAD is now at … nombra el último commit de main, que no tiene nada que ver con E8: es el git reset --hard de la rama en la que estás. Es normal. --path elige el fichero, --invert-paths dice que se quite (y no que se quede solo él) y --refs limita la reescritura a esa rama. Los SHA de los commits que tenían la clave, y de los que van detrás, cambian.

5Guarda tu hallazgo

git switch git/e8-app
code fundamentos/git/e8/hallazgo.txt
Switched to branch 'git/e8-app'
Your branch and 'origin/git/e8-app' have diverged,
and have 3 and 3 different commits each, respectively.
  (use "git pull" if you want to integrate the remote branch with yours)

Que tu rama y la de GitHub hayan divergido es lo esperado: la de GitHub aún tiene la clave. No hagas git pull: traería de vuelta los commits con la clave. Lo correcto es el push forzado del paso 8.

En VS Code, escribe en hallazgo.txt el SHA completo que apuntaste en el paso 3, en una línea, y guarda con Ctrl+S (Cmd+S en macOS). Haz el commit:

git add fundamentos/git/e8/hallazgo.txt
git commit -m "docs(e8): commit que filtró la clave"

6Comprueba antes de subir

git log -S API_KEY= git/e8-app
git ls-tree -r --name-only git/e8-app fundamentos/git/e8
fundamentos/git/e8/.gitignore
fundamentos/git/e8/README.md
fundamentos/git/e8/app.py
fundamentos/git/e8/hallazgo.txt

La primera orden no muestra nada: ningún commit de la rama tiene ya la clave. La segunda lista la carpeta, sin .env.

El corrector marca fallo si:

  • Falta alguno de los commits feat(e8): cliente de la API, feat(e8): conexión con clave, chore(e8): no versionar .env o docs(e8): instrucciones: purga el fichero, no los commits.
  • La clave sigue en algún commit de la rama.
  • app.py no tiene su contenido final, el que lee la clave de os.environ.
  • hallazgo.txt no contiene un SHA completo de 40 caracteres.
  • El commit de hallazgo.txt sigue en la historia de la rama: no has purgado, o has apuntado un commit que la purga no cambia.
  • GitHub no conoce ese commit (por ejemplo, porque purgaste antes de subir en el paso 2), o ese commit no añade la clave en fundamentos/git/e8/.env.
  • La etiqueta no es anotada: se creó sin -a.

7Pruébalo en tu equipo

pruebas.py pasa las mismas comprobaciones que el corrector, con el mismo código. Evalúa la etiqueta entrega-fundamentos-git-e8 si ya la tienes y, si no, la rama git/e8-app. Solo mira commits: lo que no esté en un commit no cuenta. No cambia nada de tu repositorio. Desde la carpeta de tu repositorio:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e8

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e8

Antes de subir, un ejercicio bien hecho se ve así (tus SHA serán otros):

E8 · rama git/e8-app, todavía sin etiqueta (provisional) · f2a3b4c
  ✓ superado
  ! en GitHub git/e8-app apunta a 9a8b7c6, no a tu f2a3b4c: el corrector evaluará el de GitHub. Sube el tuyo (…)
  • ✓ superado: pasa todas las comprobaciones.
  • ✗ es un fallo: el corrector también lo marcará. La línea dice qué ha encontrado y por qué no vale. Corrígelo, haz commit y vuelve a lanzar pruebas.py.
  • ! es un aviso: tu trabajo puede estar bien, pero el corrector evalúa lo que hay en GitHub, no tu equipo, y algo no coincide. Antes de subir es normal ver «aún no está en GitHub» o «en GitHub … apunta a …, no a tu …»: desaparece al subir en el paso siguiente. En ese aviso, el primer SHA es lo que tiene GitHub (lo último que subiste) y el segundo, tu commit.
  • sin empezar: no hay etiqueta ni rama git/e8-app: falta preparar el ejercicio.
  • Si al final sale Aviso: sin el GitHub CLI con sesión iniciada (gh auth login) no se ha comprobado lo que solo sabe GitHub: el autor de los commits de E1 y el commit filtrado de E8, en este ejercicio te afecta el commit filtrado (si el SHA de hallazgo.txt es el que subió la clave a GitHub). El corrector sí lo comprueba. Inicia sesión con gh auth login y repite.

8Sube y etiqueta

Sube tu trabajo a GitHub:

git push --force-with-lease origin git/e8-app

Es un push forzado porque has reescrito la rama. --force-with-lease solo sobrescribe si GitHub sigue como la última vez que lo miraste.

Vuelve a lanzar pruebas.py (paso anterior). Cuando diga ✓ superado y no quede ningún aviso ! de GitHub, crea la etiqueta anotada sobre git/e8-app y súbela:

git tag -a entrega-fundamentos-git-e8 git/e8-app -m "E8 resuelto"
git push origin entrega-fundamentos-git-e8

Lanza pruebas.py otra vez. Ahora evalúa la etiqueta:

E8 · etiqueta entrega-fundamentos-git-e8 · f2a3b4c
  ✓ superado

No hay fecha límite: entrega cada ejercicio cuando lo tengas. El progreso de cada alumno se ve en la tabla pública de entregas.

En GitHub, el resultado del corrector está en la portada de tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector git. Hay una fila por ejercicio: ✅ entregado y superado, ❌ entregado con fallos, ✏️ provisional (aún sin etiqueta) y · sin empezar. Se actualiza cuando el docente lanza la corrección, no en cada push.

Si hay que corregir algo después de etiquetar

Trabaja en git/e8-app (git switch git/e8-app) y nunca hagas git pull de esa rama: traería de vuelta los commits con la clave.

  • hallazgo.txt tiene un SHA equivocado: corrígelo con code fundamentos/git/e8/hallazgo.txt y haz un commit nuevo encima; aquí sí vale, porque se mira el fichero en la punta de la rama. Tiene que ser el SHA completo que viste en el paso 3, el que GitHub conoce desde el paso 2, no uno de los SHA nuevos de después de purgar: 
    git add fundamentos/git/e8/hallazgo.txt
git commit -m "fix(e8): SHA del commit filtrado"
  • La clave sigue en la rama: repite la purga del paso 4, con la rama sin cambios pendientes.
  • Falta alguno de los cuatro commits, o purgaste antes de subir en el paso 2: pregunta al docente.

Después súbela con git push --force-with-lease origin git/e8-app, como arriba.

Cuando pruebas.py vuelva a decir ✓ superado sobre la rama, mueve la etiqueta al commit corregido: -f la reemplaza en tu equipo y git push -f, en GitHub (Git 3 · Mover una etiqueta). Haz solo esto, sin tocar commits, si pruebas.py dice que la etiqueta no es anotada o que en GitHub apunta a otro commit:

git tag -fa entrega-fundamentos-git-e8 git/e8-app -m "E8 resuelto"
git push -f origin entrega-fundamentos-git-e8

Si pruebas.py dice «en GitHub ya existe entrega-fundamentos-git-e8 y no la tienes aquí», la creaste en otro equipo: tráetela con git fetch --tags.

9Mira qué queda en GitHub

Abre https://github.com/Oceano-Atlantico-Ciber/entregas-<tu-usuario>/commit/<SHA>, con el SHA de hallazgo.txt. ¿Sigue ahí la clave? ¿Qué habría que hacer con ella en un caso real?
