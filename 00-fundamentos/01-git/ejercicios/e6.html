E6 · Rebase interactivo

Cuatro commits a medias no cuentan nada. Fúndelos en uno que se lea de un vistazo.

Teoría
Git 3 · Remotos y reescribir historia
Trabajas en
fundamentos/git/e6/
Etiqueta
entrega-fundamentos-git-e6 sobre git/e6-wip

Qué entregas

La rama git/e6-wip con los cuatro commits wip(e6): paso N fundidos en uno solo:

  • El último commit de la rama se llama exactamente docs(e6): informe de alcance.
  • Ese commit crea fundamentos/git/e6/informe.md y no cambia nada más. En el commit anterior, informe.md no existía.
  • informe.md tiene el contenido del último paso, el 4.
  • No queda ningún commit wip(e6)… en la historia de la rama.
  • La rama subida a GitHub y la etiqueta anotada entrega-fundamentos-git-e6 sobre git/e6-wip, también subida.

Así se ve con git log --oneline -2 git/e6-wip (tus SHA serán otros):

0d1e2f3 (HEAD -> git/e6-wip, tag: entrega-fundamentos-git-e6, origin/git/e6-wip) docs(e6): informe de alcance
2a3b4c5 (origin/main, main) chore(e5): cambio publicado en main

1Prepara el escenario

Abre la terminal de VS Code (Terminal → New Terminal; en Windows es PowerShell). Ve a tu repositorio, trae la última versión del material, vuelve a main y mira que no tengas nada a medias. Cambia <tu-usuario> por tu usuario de GitHub:

cd ~/hacking-etico/entregas-<tu-usuario>
git -C ../documentacion-hacking-etico pull
git switch main
git status

git status tiene que terminar en nothing to commit, working tree clean. Si lista ficheros, termina o descarta antes lo que tengas a medias: preparar.py no sigue con cambios pendientes. Después, crea el punto de partida:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e6

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e6
e6 preparado para <tu-usuario> en fundamentos/git/e6/. Sigue el enunciado.

Crea git/e6-wip con cuatro commits wip(e6): paso N que van escribiendo informe.md, y te deja en main.

2Mira los cuatro commits

git switch git/e6-wip
git log --oneline -5
a4b5c6d (HEAD -> git/e6-wip) wip(e6): paso 4
93a4b5c wip(e6): paso 3
82f3a4b wip(e6): paso 2
71e2f3a wip(e6): paso 1
2a3b4c5 (origin/main, main) chore(e5): cambio publicado en main

Los cuatro wip son los que vas a fundir. HEAD~4 es el commit de debajo, el último de main.

3Abre el rebase interactivo

git rebase -i HEAD~4

Se abre en VS Code la lista de commits, del más antiguo al más nuevo:

pick 71e2f3a wip(e6): paso 1
pick 82f3a4b wip(e6): paso 2
pick 93a4b5c wip(e6): paso 3
pick a4b5c6d wip(e6): paso 4

Deja pick en la primera línea y cambia la palabra pick de las otras tres por fixup: fixup mete ese commit en el anterior y descarta su mensaje. No cambies los SHA ni borres líneas. Las líneas que empiezan por # son ayuda y dan igual.

pick 71e2f3a wip(e6): paso 1
fixup 82f3a4b wip(e6): paso 2
fixup 93a4b5c wip(e6): paso 3
fixup a4b5c6d wip(e6): paso 4

Guarda con Ctrl+S (Cmd+S en macOS) y cierra la pestaña. En la terminal:

Successfully rebased and updated refs/heads/git/e6-wip.

Si no se abre VS Code, revisa core.editor en 03 · Git y GitHub. Si algo va mal a mitad, git rebase --abort deja la rama como estaba.

4Pon el mensaje

Ahora la rama tiene un solo commit con el mensaje del primero, wip(e6): paso 1. Cámbialo por el definitivo:

git commit --amend -m "docs(e6): informe de alcance"
[git/e6-wip 0d1e2f3] docs(e6): informe de alcance
 1 file changed, 7 insertions(+)
 create mode 100644 fundamentos/git/e6/informe.md

5Comprueba antes de subir

git log --oneline main..git/e6-wip
git show --stat git/e6-wip

La primera orden muestra una sola línea, docs(e6): informe de alcance. La segunda, que ese commit solo crea fundamentos/git/e6/informe.md (1 file changed).

El corrector marca fallo si:

  • El último commit de la rama no se llama exactamente docs(e6): informe de alcance.
  • Queda algún commit wip(e6)… en la historia de la rama.
  • No queda un único commit que cree informe.md y nada más: el último commit es un merge, informe.md ya existía en el commit anterior (no fundiste los cuatro) o el commit cambia también otros ficheros.
  • informe.md no tiene el contenido del último paso.
  • La etiqueta no es anotada: se creó sin -a.

6Pruébalo en tu equipo

pruebas.py pasa las mismas comprobaciones que el corrector, con el mismo código. Evalúa la etiqueta entrega-fundamentos-git-e6 si ya la tienes y, si no, la rama git/e6-wip. Solo mira commits: lo que no esté en un commit no cuenta. No cambia nada de tu repositorio. Desde la carpeta de tu repositorio:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e6

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e6

Antes de subir, un ejercicio bien hecho se ve así (tus SHA serán otros):

E6 · rama git/e6-wip, todavía sin etiqueta (provisional) · 0d1e2f3
  ✓ superado
  ! git/e6-wip aún no está en GitHub: el corrector no lo verá hasta que lo subas
  • ✓ superado: pasa todas las comprobaciones.
  • ✗ es un fallo: el corrector también lo marcará. La línea dice qué ha encontrado y por qué no vale. Corrígelo, haz commit y vuelve a lanzar pruebas.py.
  • ! es un aviso: tu trabajo puede estar bien, pero el corrector evalúa lo que hay en GitHub, no tu equipo, y algo no coincide. Antes de subir es normal ver «aún no está en GitHub» o «en GitHub … apunta a …, no a tu …»: desaparece al subir en el paso siguiente. En ese aviso, el primer SHA es lo que tiene GitHub (lo último que subiste) y el segundo, tu commit.
  • sin empezar: no hay etiqueta ni rama git/e6-wip: falta preparar el ejercicio.
  • Si al final sale Aviso: sin el GitHub CLI con sesión iniciada (gh auth login) no se ha comprobado lo que solo sabe GitHub: el autor de los commits de E1 y el commit filtrado de E8, en este ejercicio no te afecta: todo lo que comprueba el corrector se comprueba también en tu equipo.

7Sube y etiqueta

Sube tu trabajo a GitHub:

git push -u origin git/e6-wip

Si ya habías subido la rama antes de fundir los commits, el push se rechaza (rejected … non-fast-forward). Súbela forzando con cuidado:

git push --force-with-lease origin git/e6-wip

Vuelve a lanzar pruebas.py (paso anterior). Cuando diga ✓ superado y no quede ningún aviso ! de GitHub, crea la etiqueta anotada sobre git/e6-wip y súbela:

git tag -a entrega-fundamentos-git-e6 git/e6-wip -m "E6 resuelto"
git push origin entrega-fundamentos-git-e6

Lanza pruebas.py otra vez. Ahora evalúa la etiqueta:

E6 · etiqueta entrega-fundamentos-git-e6 · 0d1e2f3
  ✓ superado

No hay fecha límite: entrega cada ejercicio cuando lo tengas. El progreso de cada alumno se ve en la tabla pública de entregas.

En GitHub, el resultado del corrector está en la portada de tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector git. Hay una fila por ejercicio: ✅ entregado y superado, ❌ entregado con fallos, ✏️ provisional (aún sin etiqueta) y · sin empezar. Se actualiza cuando el docente lanza la corrección, no en cada push.

Si hay que corregir algo después de etiquetar

Tiene que quedar un único commit que cree informe.md: nunca añadas un commit nuevo encima. Arréglalo reescribiendo ese commit, desde git switch git/e6-wip:

  • El mensaje no es exacto: 
    git commit --amend -m "docs(e6): informe de alcance"
  • Quedan commits wip o no se fundieron todos: abre otra vez el rebase interactivo con todos los commits de la rama desde main, deja pick en el primero y fixup en los demás, como en el paso 3, y pon el mensaje como en el paso 4: 
    git rebase -i main
git commit --amend -m "docs(e6): informe de alcance"

Como has reescrito la rama, súbela forzando con cuidado:

git push --force-with-lease origin git/e6-wip

Cuando pruebas.py vuelva a decir ✓ superado sobre la rama, mueve la etiqueta al commit corregido: -f la reemplaza en tu equipo y git push -f, en GitHub (Git 3 · Mover una etiqueta). Haz solo esto, sin tocar commits, si pruebas.py dice que la etiqueta no es anotada o que en GitHub apunta a otro commit:

git tag -fa entrega-fundamentos-git-e6 git/e6-wip -m "E6 resuelto"
git push -f origin entrega-fundamentos-git-e6

Si pruebas.py dice «en GitHub ya existe entrega-fundamentos-git-e6 y no la tienes aquí», la creaste en otro equipo: tráetela con git fetch --tags.
