E5 · Rebase

Un compañero ha subido un cambio a main mientras trabajabas en tu rama. Pon tu rama al día sin merges.

Qué entregas

La rama git/e5-feature rebasada sobre main, en una sola línea, sin merges:

  • La rama termina en sus dos commits, en este orden: feat(e5): escaneo de la red y, encima, feat(e5): informe del escaneo. Nada más encima.
  • Debajo de ellos está el commit del compañero, chore(e5): cambio publicado en main.
  • escaneo.txt e informe.txt como los dejó preparar.py.
  • La rama subida a GitHub y la etiqueta anotada entrega-fundamentos-git-e5 sobre git/e5-feature, también subida.

Así se ve con git log --oneline --graph -4 git/e5-feature (tus SHA serán otros):

* 9c0d1e2 (HEAD -> git/e5-feature, tag: entrega-fundamentos-git-e5, origin/git/e5-feature) feat(e5): informe del escaneo
* 6f7a8b9 feat(e5): escaneo de la red
* 2a3b4c5 (origin/main, main) chore(e5): cambio publicado en main
*   8b9c0d1 Merge branch 'git/e4-b'

1Prepara el escenario

Abre la terminal de VS Code (Terminal → New Terminal; en Windows es PowerShell). Ve a tu repositorio, trae la última versión del material, vuelve a main y mira que no tengas nada a medias. Cambia <tu-usuario> por tu usuario de GitHub:

cd ~/hacking-etico/entregas-<tu-usuario>
git -C ../documentacion-hacking-etico pull
git switch main
git status

git status tiene que terminar en nothing to commit, working tree clean. Si lista ficheros, termina o descarta antes lo que tengas a medias: preparar.py no sigue con cambios pendientes. Después, crea el punto de partida:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e5

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e5
e5 preparado para <tu-usuario> en fundamentos/git/e5/. Sigue el enunciado.

Crea git/e5-feature con dos commits y, después, añade un commit a main, como si lo hubiera subido un compañero. Míralo:

git log --oneline --graph --all -4
* 4e5f6a7 (git/e5-feature) feat(e5): informe del escaneo
* 3d4e5f6 feat(e5): escaneo de la red
| * 2a3b4c5 (HEAD -> main) chore(e5): cambio publicado en main
|/
*   8b9c0d1 (origin/main) Merge branch 'git/e4-b'

Las dos líneas se han separado: tu rama no tiene el cambio del compañero.

2Rebasa la rama sobre main

git switch git/e5-feature
git rebase main
Switched to branch 'git/e5-feature'
Successfully rebased and updated refs/heads/git/e5-feature.

Git rehace tus dos commits encima del último de main. Aquí no hay conflicto, porque tocan ficheros distintos. Si lo hubiera: resuélvelo como en E4, git add del fichero y git rebase --continue. Con git rebase --abort vuelves a como estaba. No uses git merge main: el corrector quiere la rama sin merges.

3Comprueba antes de subir

git log --oneline --graph -4 git/e5-feature

Una sola línea: el commit del compañero y, encima, tus dos commits con SHA nuevos, como en Qué entregas.

El corrector marca fallo si:

  • La rama no termina en feat(e5): escaneo de la red y feat(e5): informe del escaneo, en ese orden: por ejemplo, porque tiene otro commit encima o un merge.
  • Alguno de esos dos commits es un merge: hiciste un merge en lugar de un rebase.
  • Tus commits no parten de chore(e5): cambio publicado en main: la rama no está rebasada sobre main.
  • Falta escaneo.txt o informe.txt, o su contenido no es el que dejó preparar.py.
  • La etiqueta no es anotada: se creó sin -a.
  • La etiqueta se subió a GitHub, o se movió, después del cierre del plazo (05/11/2026, 23:59): sale «entregada fuera de plazo».

4Pruébalo en tu equipo

pruebas.py pasa las mismas comprobaciones que el corrector, con el mismo código. Evalúa la etiqueta entrega-fundamentos-git-e5 si ya la tienes y, si no, la rama git/e5-feature. Solo mira commits: lo que no esté en un commit no cuenta. No cambia nada de tu repositorio. Desde la carpeta de tu repositorio:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e5

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e5

Antes de subir, un ejercicio bien hecho se ve así (tus SHA serán otros):

E5 · rama git/e5-feature, todavía sin etiqueta (provisional) · 9c0d1e2
  ✓ superado
  ! git/e5-feature aún no está en GitHub: el corrector no lo verá hasta que lo subas
  • ✓ superado: pasa todas las comprobaciones.
  • ✗ es un fallo: el corrector también lo marcará. La línea dice qué ha encontrado y por qué no vale. Corrígelo, haz commit y vuelve a lanzar pruebas.py.
  • ! es un aviso: tu trabajo puede estar bien, pero el corrector evalúa lo que hay en GitHub, no tu equipo, y algo no coincide. Antes de subir es normal ver «aún no está en GitHub» o «en GitHub … apunta a …, no a tu …»: desaparece al subir en el paso siguiente. En ese aviso, el primer SHA es lo que tiene GitHub (lo último que subiste) y el segundo, tu commit.
  • sin empezar: no hay etiqueta ni rama git/e5-feature: falta preparar el ejercicio.
  • Si al final sale Aviso: sin el GitHub CLI con sesión iniciada (gh auth login) no se ha comprobado lo que solo sabe GitHub: el autor de los commits de E1, el commit filtrado de E8 y la hora de las etiquetas, en este ejercicio te afecta solo la hora de la etiqueta (el plazo). El corrector sí lo comprueba. Inicia sesión con gh auth login y repite.

5Sube y etiqueta

Sube tu trabajo a GitHub:

git push origin main
git push -u origin git/e5-feature

Si ya habías subido git/e5-feature antes del rebase, el segundo push se rechaza (rejected … non-fast-forward), porque has reescrito sus commits. Es tu rama: súbela forzando con cuidado, como se explica en Git 3:

git push --force-with-lease origin git/e5-feature

Vuelve a lanzar pruebas.py (paso anterior). Cuando diga ✓ superado y no quede ningún aviso ! de GitHub, crea la etiqueta anotada sobre git/e5-feature y súbela:

git tag -a entrega-fundamentos-git-e5 git/e5-feature -m "E5 resuelto"
git push origin entrega-fundamentos-git-e5

Lanza pruebas.py otra vez. Ahora evalúa la etiqueta:

E5 · etiqueta entrega-fundamentos-git-e5 · 9c0d1e2
  ✓ superado
  ! el plazo cerró el 05/11/2026 a las 23:59: sin gh no sé a qué hora subiste la etiqueta; si fue después, el corrector la marcará fuera de plazo

Plazo. Cerró el jueves 5 de noviembre de 2026 a las 23:59. El corrector mira a qué hora se subió a GitHub la etiqueta, o se movió por última vez: si fue después, la entrega sale entregada fuera de plazo. Con gh, pruebas.py lo marca con ✗; sin gh, solo avisa con !, como arriba. Una etiqueta creada en tu equipo y aún sin subir sale con ✗ «entregada fuera de plazo si la subes ahora».

En GitHub, el resultado del corrector está en la portada de tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector git. Hay una fila por ejercicio: ✅ entregado y superado, ❌ entregado con fallos, ✏️ provisional (aún sin etiqueta) y · sin empezar. Se actualiza cuando el docente lanza la corrección, no en cada push.

Si hay que corregir algo después de etiquetar

La rama tiene que terminar en tus dos commits: no añadas nada encima, ni siquiera un commit que arregle algo. Arréglala reescribiéndola, desde git switch git/e5-feature:

  • Hiciste un merge en lugar del rebase, o la rama no está sobre main: vuelve a rebasar. git rebase main rehace tus dos commits encima de main y deja fuera los merges: 
    git rebase main
  • Hay un commit de más encima: quítalo. git reset --hard HEAD~1 borra el último commit y sus cambios; mira antes con git log --oneline -3 que es el que sobra: 
    git reset --hard HEAD~1
  • Cambiaste un fichero del último commit (informe.txt): corrígelo y mételo en ese mismo commit con --amend, que lo sustituye en lugar de añadir otro: 
    git add fundamentos/git/e5/informe.txt
git commit --amend --no-edit

Como has reescrito la rama, súbela forzando con cuidado:

git push --force-with-lease origin git/e5-feature

Cuando pruebas.py vuelva a decir ✓ superado sobre la rama, mueve la etiqueta al commit corregido: -f la reemplaza en tu equipo y git push -f, en GitHub (Git 3 · Mover una etiqueta). Haz solo esto, sin tocar commits, si pruebas.py dice que la etiqueta no es anotada o que en GitHub apunta a otro commit:

git tag -fa entrega-fundamentos-git-e5 git/e5-feature -m "E5 resuelto"
git push -f origin entrega-fundamentos-git-e5

Moverla cuenta como subirla de nuevo: si ya ha cerrado el plazo, la entrega pasa a estar fuera de plazo. Si pruebas.py dice «en GitHub ya existe entrega-fundamentos-git-e5 y no la tienes aquí», la creaste en otro equipo: tráetela con git fetch --tags.
