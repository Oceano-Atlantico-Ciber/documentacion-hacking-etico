E7 · Revert

Un commit con un error ya está en GitHub. Deshazlo sin reescribir la historia que otros pueden tener.

Teoría
Git 4 · Deshacer y seguridad
Trabajas en
fundamentos/git/e7/
Etiqueta
entrega-fundamentos-git-e7 sobre main

Qué entregas

main con los tres commits que crea preparar.py intactos y, encima, un commit nuevo que deshace el erróneo:

  • Siguen en la historia, una vez cada uno, feat(e7): activar modo depuración (el erróneo) y docs(e7): instrucciones de despliegue.
  • Después del erróneo hay un commit, que no es un merge, que aplica exactamente su cambio al revés: el que crea git revert.
  • fundamentos/git/e7/config.ini queda como antes del error, con debug = false.
  • La etiqueta anotada entrega-fundamentos-git-e7 sobre main, subida a GitHub.

Así se ve con git log --oneline -4 (tus SHA serán otros):

e1f2a3b (HEAD -> main, tag: entrega-fundamentos-git-e7, origin/main) Revert "feat(e7): activar modo depuración"
c9d0e1f docs(e7): instrucciones de despliegue
b8c9d0e feat(e7): activar modo depuración
a7b8c9d feat(e7): configuración del servidor

1Prepara el escenario

Abre la terminal de VS Code (Terminal → New Terminal; en Windows es PowerShell). Ve a tu repositorio, trae la última versión del material, vuelve a main y mira que no tengas nada a medias. Cambia <tu-usuario> por tu usuario de GitHub:

cd ~/hacking-etico/entregas-<tu-usuario>
git -C ../documentacion-hacking-etico pull
git switch main
git status

git status tiene que terminar en nothing to commit, working tree clean. Si lista ficheros, termina o descarta antes lo que tengas a medias: preparar.py no sigue con cambios pendientes. Después, crea el punto de partida:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e7

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e7
e7 preparado para <tu-usuario> en fundamentos/git/e7/. Sigue el enunciado.

Añade tres commits a main. El segundo, feat(e7): activar modo depuración, activa por error el modo depuración del servidor en config.ini.

2Publica main

git push

Desde ahora el commit erróneo es público: otros pueden tenerlo, así que ya no se reescribe. Se deshace con un commit nuevo.

3Busca el SHA del commit erróneo

git log --oneline -4
c9d0e1f (HEAD -> main, origin/main) docs(e7): instrucciones de despliegue
b8c9d0e feat(e7): activar modo depuración
a7b8c9d feat(e7): configuración del servidor
2a3b4c5 chore(e5): cambio publicado en main

Apunta el SHA de la línea feat(e7): activar modo depuración: en el ejemplo, b8c9d0e.

4Revierte el commit erróneo

Cambia <sha> por el SHA que has apuntado:

git revert --no-edit <sha>
[main e1f2a3b] Revert "feat(e7): activar modo depuración"
 1 file changed, 1 insertion(+), 1 deletion(-)

Git crea un commit nuevo que aplica el cambio inverso; --no-edit acepta el mensaje que propone. No uses git reset ni git rebase: borrarían commits ya publicados.

5Comprueba antes de subir

git log --oneline -4
git show HEAD
…
--- a/fundamentos/git/e7/config.ini
+++ b/fundamentos/git/e7/config.ini
@@ -1,4 +1,4 @@
 [servidor]
 puerto = 8443
-debug = true
+debug = false
 id = 3f2a…

Siguen los tres commits y encima hay uno Revert "…" que devuelve debug = false.

El corrector marca fallo si:

  • Falta el commit feat(e7): activar modo depuración o el docs(e7): instrucciones de despliegue, o alguno aparece más de una vez: se reescribió la historia (reset, rebase…).
  • No hay un commit posterior al erróneo, que no sea un merge, que deshaga exactamente su cambio en config.ini. Hazlo con git revert.
  • config.ini no queda igual que antes del error.
  • La etiqueta no es anotada: se creó sin -a.

6Pruébalo en tu equipo

pruebas.py pasa las mismas comprobaciones que el corrector, con el mismo código. Evalúa la etiqueta entrega-fundamentos-git-e7 si ya la tienes y, si no, la rama main. Solo mira commits: lo que no esté en un commit no cuenta. No cambia nada de tu repositorio. Desde la carpeta de tu repositorio:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e7

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e7

Antes de subir, un ejercicio bien hecho se ve así (tus SHA serán otros):

E7 · rama main, todavía sin etiqueta (provisional) · e1f2a3b
  ✓ superado
  ! en GitHub main apunta a c9d0e1f, no a tu e1f2a3b: el corrector evaluará el de GitHub. Sube el tuyo (…)
  • ✓ superado: pasa todas las comprobaciones.
  • ✗ es un fallo: el corrector también lo marcará. La línea dice qué ha encontrado y por qué no vale. Corrígelo, haz commit y vuelve a lanzar pruebas.py.
  • ! es un aviso: tu trabajo puede estar bien, pero el corrector evalúa lo que hay en GitHub, no tu equipo, y algo no coincide. Antes de subir es normal ver «aún no está en GitHub» o «en GitHub … apunta a …, no a tu …»: desaparece al subir en el paso siguiente. En ese aviso, el primer SHA es lo que tiene GitHub (lo último que subiste) y el segundo, tu commit.
  • sin empezar: no hay etiqueta ni trabajo en fundamentos/git/e7/ de main: falta preparar el ejercicio o hacer sus commits.
  • Si al final sale Aviso: sin el GitHub CLI con sesión iniciada (gh auth login) no se ha comprobado lo que solo sabe GitHub: el autor de los commits de E1 y el commit filtrado de E8, en este ejercicio no te afecta: todo lo que comprueba el corrector se comprueba también en tu equipo.

7Sube y etiqueta

Sube tu trabajo a GitHub:

git push

Vuelve a lanzar pruebas.py (paso anterior). Cuando diga ✓ superado y no quede ningún aviso ! de GitHub, crea la etiqueta anotada sobre main y súbela:

git tag -a entrega-fundamentos-git-e7 main -m "E7 resuelto"
git push origin entrega-fundamentos-git-e7

Lanza pruebas.py otra vez. Ahora evalúa la etiqueta:

E7 · etiqueta entrega-fundamentos-git-e7 · e1f2a3b
  ✓ superado

No hay fecha límite: entrega cada ejercicio cuando lo tengas. El progreso de cada alumno se ve en la tabla pública de entregas.

En GitHub, el resultado del corrector está en la portada de tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector git. Hay una fila por ejercicio: ✅ entregado y superado, ❌ entregado con fallos, ✏️ provisional (aún sin etiqueta) y · sin empezar. Se actualiza cuando el docente lanza la corrección, no en cada push.

Si hay que corregir algo después de etiquetar

  • Falta el revert: hazlo como en los pasos 3 y 4 y súbelo con git push. Corrige siempre con commits nuevos encima: main ya es público, así que nada de git reset, git rebase ni git push -f de la rama, que borrarían los commits que el corrector busca.
  • Hiciste un revert de otro commit (por ejemplo, de docs(e7): instrucciones de despliegue): deshaz también ese revert con otro git revert --no-edit <sha-de-ese-revert>, revierte el commit correcto y sube.

Cuando pruebas.py vuelva a decir ✓ superado sobre la rama, mueve la etiqueta al commit corregido: -f la reemplaza en tu equipo y git push -f, en GitHub (Git 3 · Mover una etiqueta). Haz solo esto, sin tocar commits, si pruebas.py dice que la etiqueta no es anotada o que en GitHub apunta a otro commit:

git tag -fa entrega-fundamentos-git-e7 main -m "E7 resuelto"
git push -f origin entrega-fundamentos-git-e7

Si pruebas.py dice «en GitHub ya existe entrega-fundamentos-git-e7 y no la tienes aquí», la creaste en otro equipo: tráetela con git fetch --tags.
