Etiqueta E1 en cuanto esté bien. El corrector cuenta todos los commits que hayan tocado fundamentos/git/e1/ en la historia hasta la etiqueta, y hasta la punta de main mientras no la tengas: también los que hagas después, aunque deshagan algo. Un git add . en otro ejercicio que toque e1/ deja E1 con cuatro commits y suspendido. Por eso, añade siempre los ficheros por su ruta y crea la etiqueta en el último paso, antes de empezar E2.

1Comprueba tu identidad

Cada commit guarda el nombre y el correo con los que se creó, y no se cambian después sin reescribir la historia. Míralos antes de hacer ningún commit:

git config user.name
git config user.email
Ana García
ana.garcia@ejemplo.com

El correo tiene que ser uno de los verificados en GitHub (Settings → Emails); el privado …@users.noreply.github.com de esa misma página también vale. Si sale vacío o es otro, cámbialo (con tus datos, entre comillas):

git config --global user.name "Tu Nombre"
git config --global user.email "tu-correo-verificado@ejemplo.com"

Comprueba también que tienes sesión en el GitHub CLI: sin ella, pruebas.py no puede mirar si GitHub asocia tus commits a tu cuenta.

gh auth status

Debe decir Logged in to github.com account <tu-usuario>. Si no, inicia sesión con gh auth login (03 · Git y GitHub).

2Prepara el escenario

Abre la terminal de VS Code (Terminal → New Terminal; en Windows es PowerShell). Ve a tu repositorio, trae la última versión del material, vuelve a main y mira que no tengas nada a medias. Cambia <tu-usuario> por tu usuario de GitHub:

cd ~/hacking-etico/entregas-<tu-usuario>
git -C ../documentacion-hacking-etico pull
git switch main
git status

git status tiene que terminar en nothing to commit, working tree clean. Si lista ficheros, termina o descarta antes lo que tengas a medias: preparar.py no sigue con cambios pendientes. Después, crea el punto de partida:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e1

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e1
e1 preparado para <tu-usuario> en fundamentos/git/e1/. Sigue el enunciado.

Deja tres ficheros sin versionar en fundamentos/git/e1/. Míralos:

git status --short -uall
?? fundamentos/git/e1/herramientas.md
?? fundamentos/git/e1/notas.md
?? fundamentos/git/e1/objetivo.md

No cambies su contenido: el corrector lo compara con el que te ha generado.

Nunca git add . ni git add -A en la raíz del repositorio. Añade cada fichero por su ruta, como en los pasos: un git add . mete en el commit lo de otros ejercicios y lo estropea.

3Primer commit: objetivo.md

Añade solo ese fichero y haz el commit. El mensaje sigue tipo(ámbito): descripción: el tipo es feat, fix, docs, style, refactor, test o chore; el ámbito, entre paréntesis, es opcional; después de los dos puntos va un espacio. Puedes usar estos mensajes u otros con ese formato.

git add fundamentos/git/e1/objetivo.md
git commit -m "docs(e1): objetivo de la auditoría"
[main 1a2b3c4] docs(e1): objetivo de la auditoría
 1 file changed, 4 insertions(+)
 create mode 100644 fundamentos/git/e1/objetivo.md

Tiene que decir 1 file changed. El aviso LF will be replaced by CRLF no es un error: es core.autocrlf haciendo su trabajo.

4Segundo commit: herramientas.md

git add fundamentos/git/e1/herramientas.md
git commit -m "docs(e1): herramientas de la auditoría"

Otra vez 1 file changed.

5Tercer commit: notas.md

git add fundamentos/git/e1/notas.md
git commit -m "docs(e1): notas del alcance"

Otra vez 1 file changed.

6Comprueba antes de subir

git status --short -uall fundamentos/git/e1
git log --oneline --stat -- fundamentos/git/e1

La primera orden no muestra nada: no queda nada de e1/ sin commit. La segunda muestra tres commits, cada uno con 1 file changed, como en Qué entregas.

Si un commit ha salido mal y todavía no has hecho git push, deshazlo y repite el paso: git reset HEAD~1 quita el último commit y deja su fichero sin añadir, con el contenido intacto.

git reset HEAD~1

Si ya lo has subido, no lo arregles con más commits: cada uno cuenta. Pregunta al docente.

El corrector marca fallo si:

  • En la historia hay más o menos de tres commits que toquen fundamentos/git/e1/. Cuentan todos hasta la etiqueta, también los que deshacen algo o vienen de otro ejercicio.
  • Alguno de esos commits cambia más de un fichero, o un fichero que no es uno de los tres de e1/.
  • Alguno de los tres ficheros no tiene commit.
  • Algún mensaje no sigue Conventional Commits con tipo feat, fix, docs, style, refactor, test o chore.
  • Falta alguno de los tres ficheros o su contenido no es el que dejó preparar.py (no cuentan los espacios ni las líneas en blanco).
  • Alguno de los commits no está en GitHub.
  • GitHub no asocia el correo del autor a tu cuenta.
  • La etiqueta no es anotada: se creó sin -a.
  • La etiqueta se subió a GitHub, o se movió, después del cierre del plazo (05/11/2026, 23:59): sale «entregada fuera de plazo».

7Pruébalo en tu equipo

pruebas.py pasa las mismas comprobaciones que el corrector, con el mismo código. Evalúa la etiqueta entrega-fundamentos-git-e1 si ya la tienes y, si no, la rama main. Solo mira commits: lo que no esté en un commit no cuenta. No cambia nada de tu repositorio. Desde la carpeta de tu repositorio:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e1

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e1

Antes de subir, un ejercicio bien hecho se ve así (tus SHA serán otros):

E1 · rama main, todavía sin etiqueta (provisional) · 5d6e7f8
  ✓ superado
  ! en GitHub main apunta a 0f9e8d7, no a tu 5d6e7f8: el corrector evaluará el de GitHub. Sube el tuyo (…)
  • ✓ superado: pasa todas las comprobaciones.
  • ✗ es un fallo: el corrector también lo marcará. La línea dice qué ha encontrado y por qué no vale. Corrígelo, haz commit y vuelve a lanzar pruebas.py.
  • ! es un aviso: tu trabajo puede estar bien, pero el corrector evalúa lo que hay en GitHub, no tu equipo, y algo no coincide. Antes de subir es normal ver «aún no está en GitHub» o «en GitHub … apunta a …, no a tu …»: desaparece al subir en el paso siguiente. En ese aviso, el primer SHA es lo que tiene GitHub (lo último que subiste) y el segundo, tu commit.
  • sin empezar: no hay etiqueta ni trabajo en fundamentos/git/e1/ de main: falta preparar el ejercicio o hacer sus commits.
  • En E1, con sesión en gh, antes de subir salen además tres ✗ «… no está en GitHub: súbelo con git push…», uno por commit: GitHub aún no los tiene y no puede decir de quién son. Es lo esperado: desaparecen al subir en el paso siguiente.
  • Si al final sale Aviso: sin el GitHub CLI con sesión iniciada (gh auth login) no se ha comprobado lo que solo sabe GitHub: el autor de los commits de E1, el commit filtrado de E8 y la hora de las etiquetas, en este ejercicio te afecta el autor de tus commits (y si están en GitHub) y la hora de la etiqueta. El corrector sí lo comprueba. Inicia sesión con gh auth login y repite.

8Sube y etiqueta

Sube tu trabajo a GitHub:

git push

Mira en GitHub que los tres commits son tuyos: abre https://github.com/Oceano-Atlantico-Ciber/entregas-<tu-usuario>/commits/main. Cada uno debe mostrar tu avatar y tu usuario. Si sale solo un nombre en gris, GitHub no asocia ese correo a tu cuenta: verifícalo en Settings → Emails o pregunta al docente.

Vuelve a lanzar pruebas.py (paso anterior). Cuando diga ✓ superado y no quede ningún aviso ! de GitHub, crea la etiqueta anotada sobre main y súbela:

git tag -a entrega-fundamentos-git-e1 main -m "E1 resuelto"
git push origin entrega-fundamentos-git-e1

Lanza pruebas.py otra vez. Ahora evalúa la etiqueta:

E1 · etiqueta entrega-fundamentos-git-e1 · 5d6e7f8
  ✓ superado
  ! el plazo cerró el 05/11/2026 a las 23:59: sin gh no sé a qué hora subiste la etiqueta; si fue después, el corrector la marcará fuera de plazo

Plazo. Cerró el jueves 5 de noviembre de 2026 a las 23:59. El corrector mira a qué hora se subió a GitHub la etiqueta, o se movió por última vez: si fue después, la entrega sale entregada fuera de plazo. Con gh, pruebas.py lo marca con ✗; sin gh, solo avisa con !, como arriba. Una etiqueta creada en tu equipo y aún sin subir sale con ✗ «entregada fuera de plazo si la subes ahora».

En GitHub, el resultado del corrector está en la portada de tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector git. Hay una fila por ejercicio: ✅ entregado y superado, ❌ entregado con fallos, ✏️ provisional (aún sin etiqueta) y · sin empezar. Se actualiza cuando el docente lanza la corrección, no en cada push.

Si hay que corregir algo después de etiquetar

En E1 no se corrige con commits nuevos: cualquier commit más que toque fundamentos/git/e1/, aunque deshaga algo, hace cuatro y suspende. Depende de si ya has subido los commits:

  • Aún no has hecho git push y el fallo está en el último commit (su mensaje o su autor): rehazlo en el sitio con --amend, que lo sustituye en lugar de añadir otro. Para el mensaje: 
    git commit --amend -m "docs(e1): notas del alcance"
    Para el autor, después de corregir user.email (paso 1): 
    git commit --amend --reset-author --no-edit
  • Aún no has hecho git push y el fallo está en un commit anterior: deshaz los commits de E1 con git reset (quita commits y deja los ficheros sin añadir, con su contenido intacto) y repite desde el paso 3. Con los tres commits de E1 en lo alto de main: 
    git reset HEAD~3
  • Ya los has subido (si etiquetaste siguiendo los pasos, es tu caso): no reescribas main ni añadas commits; pregunta al docente.

Después sube con git push y lanza pruebas.py.

Cuando pruebas.py vuelva a decir ✓ superado sobre la rama, mueve la etiqueta al commit corregido: -f la reemplaza en tu equipo y git push -f, en GitHub (Git 3 · Mover una etiqueta). Haz solo esto, sin tocar commits, si pruebas.py dice que la etiqueta no es anotada o que en GitHub apunta a otro commit:

git tag -fa entrega-fundamentos-git-e1 main -m "E1 resuelto"
git push -f origin entrega-fundamentos-git-e1

Moverla cuenta como subirla de nuevo: si ya ha cerrado el plazo, la entrega pasa a estar fuera de plazo. Si pruebas.py dice «en GitHub ya existe entrega-fundamentos-git-e1 y no la tienes aquí», la creaste en otro equipo: tráetela con git fetch --tags.
