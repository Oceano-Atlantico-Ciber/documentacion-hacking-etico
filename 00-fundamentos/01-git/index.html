01 · Git

Cómo guarda Git la historia, ramas y fusiones, remotos y cómo deshacer sin perder nada. Cuatro temas y ocho ejercicios.

Temas

Git 1 · Modelo y commitsQué guarda Git, los cuatro objetos y el commit. Git 2 · Ramas y fusionesRamas como punteros, fast-forward, merge y conflictos. Git 3 · Remotos y reescribir historiaorigin, push y pull, rebase y rebase interactivo. Git 4 · Deshacer y seguridadrestore, reset y revert; secretos filtrados y cómo purgarlos.

Ejercicios

Antes de empezar: 03 · Git y GitHub y 06 · Primer commit.

Todos los ejercicios siguen el mismo ciclo:

preparar.py→Resolver→pruebas.py→git push→Etiqueta→Corrector

Ocho ejercicios en fundamentos/git/ de tu repositorio de entregas. Cada uno empieza con preparar.py, que crea los ficheros, ramas y commits de partida a partir de tu usuario de GitHub: tu escenario es distinto del de tus compañeros. Ejecútalo desde la carpeta de tu repositorio, con el material clonado al lado (06 · Primer commit), en main y sin cambios pendientes. En Windows, las órdenes van en PowerShell (la terminal de VS Code); en macOS y Linux, en Terminal:

cd ~/hacking-etico/entregas-<tu-usuario>
git switch main
git status

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e1

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/preparar.py e1

Antes de etiquetar, compruébalo en tu equipo con pruebas.py. Pasa las mismas comprobaciones que el corrector, con el mismo código. Evalúa la etiqueta si ya existe y, si no, la rama del ejercicio. Marca con ✗ los fallos y con ! los avisos. El aviso más habitual es que lo que hay en GitHub no coincide con tu equipo, y eso importa porque el corrector evalúa lo que hay en GitHub. Sin el número de ejercicio, los comprueba todos:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e1

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e1

Lo que solo sabe GitHub (el autor de los commits de E1, el commit filtrado de E8 y la hora de las etiquetas) lo comprueba con gh, la herramienta de GitHub para la terminal, si tienes sesión iniciada (gh auth login). Sin ella, lo salta y avisa.

Cada ejercicio se entrega con su propia etiqueta anotada, entrega-fundamentos-git-eN, sobre el commit donde está resuelto, subida a GitHub. Qué es una etiqueta y cómo se crea se explica en Git 1, antes del primer ejercicio. Cada ejercicio tiene su página con qué entregas, los pasos, cómo comprobarlo y qué mira el corrector. Hazlos en orden: cada uno usa solo lo visto en su tema y en los anteriores. Etiqueta E1 en cuanto esté bien: el corrector cuenta todos los commits que tocan fundamentos/git/e1/ hasta la etiqueta.

No hay fecha límite: entrega cada ejercicio cuando lo tengas. El progreso de cada alumno se ve en la tabla pública de entregas. Si hay que corregir algo, mueve su etiqueta (Git 3).

Dónde ver el resultado

En GitHub, el resultado del corrector está en la portada de tu repositorio. Pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector git. Hay una fila por ejercicio: ✅ entregado y superado, ❌ entregado con fallos, ✏️ provisional (aún sin etiqueta) y · sin empezar.

Se actualiza cuando el docente lanza la corrección, no en cada push. El símbolo va en el commit que se corrigió: si subes algo después, tu último commit no lo tendrá hasta la siguiente corrección.

Cómo se valora

  • Cada ejercicio vale lo mismo y se corrige de forma automática desde su etiqueta en GitHub: estructura del historial (padres de los merges, commits por rama, conflicto real) y contenido de los ficheros. Una etiqueta que no es anotada es un fallo.
  • Cuenta la etiqueta tal como esté cuando el docente lanza la corrección.
