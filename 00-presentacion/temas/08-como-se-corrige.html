Presentación · Entregas

Cómo se corrige tu entrega

Entregas con una etiqueta, el corrector la evalúa y el resultado aparece en tu repositorio y en la tabla de entregas, con el motivo de cada fallo. No hay fecha límite: puedes corregir y volver a entregar las veces que haga falta.

El recorrido

  1. Tú haces el ejercicio, lo compruebas con pruebas.py, lo subes y lo etiquetas. Cada enunciado dice su etiqueta, por ejemplo entrega-fundamentos-git-e1.
  2. El docente lanza el corrector de cada unidad. No corre en cada push: tu resultado cambia cuando se lanza la siguiente corrección.
  3. El corrector evalúa lo que hay en la etiqueta en GitHub, no en tu equipo, y deja el resultado en dos sitios: el check de tu repositorio y la tabla de entregas.

pruebas.py dice lo mismo que el corrector

Si pruebas.py dice ✓ superado sobre lo que hay en GitHub, el corrector dirá lo mismo. La única diferencia es qué mira: pruebas.py mira tus commits y te avisa con ! si GitHub no tiene lo mismo; el corrector solo ve GitHub. Cada enunciado tiene un paso «Pruébalo en tu equipo» con su orden exacta. Por ejemplo, para Git E1, desde la carpeta de tu repositorio:

Windows · PowerShell

py ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e1

macOS / Linux · Terminal

python3 ../documentacion-hacking-etico/00-fundamentos/01-git/ejercicios/pruebas.py e1

Qué significa cada símbolo

El mismo resultado se dibuja distinto en cada sitio:

TablaCheckpruebas.pyQué significa y qué haces
✓✅✓ superadoSuperado. Tiene etiqueta y pasa todo. Nada más que hacer.
×❌✗Con fallos. Lee el motivo, arréglalo y mueve la etiqueta (abajo).
·✏️(provisional)Provisional. Hay trabajo en main pero aún no hay etiqueta: no cuenta como entregado. Etiqueta cuando pruebas.py diga superado.
Pendiente de corregir. Has etiquetado después de la última corrección. Saldrá en la siguiente.
!⚠️Error del corrector, no tuyo. No cuenta contra ti. Avisa al docente.
·sin empezarSin empezar. Ni etiqueta ni trabajo en la carpeta del ejercicio.

En pruebas.py, ! es otra cosa: un aviso de que GitHub no tiene lo mismo que tu equipo (por ejemplo, falta un push). Tu trabajo puede estar bien, pero el corrector verá lo de GitHub.

Dónde ver el motivo de un fallo

  • En la tabla de entregas: pulsa tu usuario o una casilla. Se abre tu panel con cada fallo: qué ha encontrado, cómo arreglarlo, un enlace al paso del enunciado y, en «Pruébalo tú», la orden para repetirlo. Tu panel tiene su propia dirección, entregas/#alumno-<usuario>, para guardarla.
  • En tu repositorio: pulsa el ✓ o la ✗ junto al último commit de main y abre Details en el check del corrector (por ejemplo, Corrector de git). Hay una fila por ejercicio.
  • En tu terminal: pruebas.py te da lo mismo, al momento y sin esperar a ninguna corrección.

Corregir y volver a entregar

Para mover la etiqueta al commit corregido, -f la reemplaza en tu equipo y git push -f en GitHub. Las órdenes son iguales en Windows, macOS y Linux; cambia el nombre de la etiqueta y la rama por las de tu ejercicio:

git tag -fa entrega-fundamentos-git-e1 main -m "E1 resuelto"
git push -f origin entrega-fundamentos-git-e1

Más detalle en Git 3 · Mover una etiqueta. Algunos ejercicios piden algo distinto para corregir (en Git E1, por ejemplo, un commit nuevo suspende): sigue siempre lo que diga su enunciado.

No hay fecha límite ni número máximo de entregas. Cuenta lo que haya en la etiqueta cuando se lance la corrección.
