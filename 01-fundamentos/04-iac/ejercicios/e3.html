E3 · Del clic al código

El bucket y el lector del E1 existen, pero solo en tu cuenta y en tu memoria. Descríbelos en Terraform y adóptalos con import, sin borrarlos ni crearlos de nuevo.

IaC 2 · Terraform

Recursos, referencias, el ciclo init, plan, apply y los bloques import.

1Prepara el ejercicio

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/04-iac/ejercicios/preparar.py e3
cd fundamentos/iac/e3

Deja proveedor.tf, que apunta a tu Floci, y un LEEME.md con los tres recursos que tienes que adoptar. Tu Floci tiene que seguir teniendo lo del E1: compruébalo con aws s3 ls y aws iam list-users. Si hiciste down -v, vuelve a lanzar las órdenes de e1/ordenes.sh.

2Escribe los recursos

code main.tf

Un aws_s3_bucket, un aws_iam_user y un aws_iam_user_policy con la misma política que e1/politica.json, escrita con jsonencode y con referencias en vez de nombres repetidos. Y un bloque import por cada uno, con el id que dice el LEEME.md (IaC 2 · Adoptar lo que ya existe).

3Ajusta hasta que el plan solo importe

terraform init
terraform fmt
terraform plan

El objetivo es Plan: 3 to import, 0 to add, 0 to change, 0 to destroy. Si dice to change, el plan te enseña con ~ qué atributo de tu código no coincide con la cuenta: corrígelo en el código, no en la cuenta. Si dice to add, algún import no encuentra su recurso.

4Aplica y comprueba

terraform apply
terraform plan

El segundo plan tiene que decir No changes. El terraform.tfstate que aparece en la carpeta no se sube: el .gitignore de la unidad ya lo deja fuera.

El corrector marca fallo si:

  • Falta main.tf, o falta alguno de los tres recursos, o no hay ningún bloque import.
  • En una cuenta nueva donde se han lanzado tus órdenes del E1, el primer plan no importa, o además añade, cambia o destruye algo.
  • Después de apply, el plan todavía quiere cambiar algo.

5Pruébalo en tu equipo

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/04-iac/ejercicios/pruebas.py e3

Como el corrector, lanza tu e1/ordenes.sh en una Floci vacía y después tu Terraform. Corrige, haz commit y repite hasta que salga ✓ superado.

6Sube y etiqueta

git add fundamentos/iac
git commit -m "feat(iac-e3): bucket y lector adoptados con import"
git push

Cuando la fila de E3 de Corrector iac salga sin fallos:

git tag -a entrega-fundamentos-iac-e3 -m "E3 resuelto"
git push origin entrega-fundamentos-iac-e3
