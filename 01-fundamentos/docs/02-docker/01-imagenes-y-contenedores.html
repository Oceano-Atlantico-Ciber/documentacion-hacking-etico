Imágenes y contenedores

Un contenedor es un programa que arranca con todo lo que necesita y aislado del resto del equipo. Docker los fabrica a partir de imágenes, y en este curso levanta todos los laboratorios.

Ejercicio: E1

Qué problema resuelve

Una herramienta necesita su versión de Python, sus librerías y su configuración. Si cada alumno las instala a mano, cada equipo acaba distinto y aparece el clásico «en mi máquina funciona». Un contenedor lleva todo eso dentro, así que funciona igual en todos los portátiles.

Máquina virtualContenedor
ArranqueMinutos: arranca un sistema enteroSegundos: arranca un programa
TamañoGigasMegas
AislamientoFuerte: cada una tiene su núcleoMás débil: comparten núcleo. Lo verás en Docker 4

Docker en tu Windows

Los contenedores del curso son de Linux. Docker Desktop mantiene en tu Windows una máquina Linux ligera (WSL 2) y dentro de ella corre el motor de Docker. La orden docker que escribes en Git Bash es solo el mando a distancia de ese motor.

Instalación

  1. Docker Desktop lo instalaste en Presentación · Docker. Si no lo tienes, instálalo desde PowerShell y ábrelo; usa el motor WSL 2, que propone al arrancar la primera vez, y si te pide reiniciar, reinicia: 
    winget install -e --id Docker.DockerDesktop
  2. Crea una cuenta gratuita en Docker Hub e inicia sesión desde Git Bash. Docker Hub limita las descargas anónimas por dirección IP, y toda el aula sale a Internet por la misma; con sesión iniciada, cada uno tiene su propio cupo: 
    docker login
  3. Git Bash convierte cualquier argumento que empiece por / en una ruta de Windows: /usr/share llegaría a Docker como C:/Program Files/Git/usr/share. Las rutas de dentro de un contenedor son de Linux y no se deben tocar. Esta función le dice a Git Bash que no convierta nada cuando la orden es docker; añádela una vez a tu ~/.bashrc: 
    echo 'docker() { MSYS_NO_PATHCONV=1 command docker "$@"; }' >> ~/.bashrc
source ~/.bashrc
  4. Comprueba que todo responde: 
    docker run --rm hello-world
docker compose version

Imagen y contenedor

Una imagen es el molde: los ficheros de un programa y lo que necesita, de solo lectura. Un contenedor es una pieza sacada de ese molde y en marcha. De una imagen salen tantos contenedores como quieras, y cada uno tiene encima una capa propia donde escribe sus cambios.

El nombre de una imagen

Las imágenes se descargan de un registro; el que Docker usa si no dices otro es Docker Hub. El nombre completo dice de dónde viene y qué versión es:

latest no significa «la última»: es una etiqueta más, que el autor mueve cuando quiere. Dos alumnos que descargan latest en días distintos pueden tener versiones distintas. Por eso los laboratorios fijan la versión (nginx:1.27-alpine, aquasec/trivy:0.58.0). Floci se usa con latest a propósito, para recibir sus correcciones.

Ciclo de vida de un contenedor

OrdenQué hace
docker pull nginx:1.27-alpineDescarga la imagen.
docker image lsImágenes descargadas.
docker run -d --name web nginx:1.27-alpineCrea y arranca un contenedor. -d lo deja en segundo plano; --name le pone nombre.
docker run --rm imagen …Ejecuta y borra el contenedor al terminar.
docker ps / docker ps -aContenedores en marcha / también los parados.
docker logs -f webLo que el programa escribe en pantalla. -f sigue mirando; se sale con Ctrl+C.
docker exec web nginx -vEjecuta una orden dentro de un contenedor en marcha.
docker cp fichero web:/rutaCopia un fichero de tu equipo al contenedor (o al revés).
docker stop web / docker start webPara / vuelve a arrancar.
docker rm web / docker rm -f webBorra uno parado / lo para y lo borra.
docker container inspect webTodo lo que Docker sabe de él, en JSON.

Hablar con un contenedor

Un servidor web dentro de un contenedor escucha en su puerto 80, pero ese puerto es del contenedor, no de tu equipo. -p 127.0.0.1:8080:80 abre la puerta 8080 de tu equipo, solo para ti, y la conecta con la 80 del contenedor. Lo verás a fondo en Docker 3.

Para comprobar que responde basta con curl, como en API REST 3: envía una petición y muestra la respuesta. Para Docker basta con mirar la primera línea, el código de estado de API REST 2.

docker run -d --name web -p 127.0.0.1:8080:80 nginx:1.27-alpine
curl -i http://localhost:8080/      # -i: muestra también la línea de estado y las cabeceras
docker logs web                     # nginx anota cada petición recibida

Espacio en disco

Las imágenes del curso ocupan varios gigas dentro del disco de WSL 2. Revisa de vez en cuando qué ocupa sitio y borra lo que no uses:

docker system df            # imágenes, contenedores y volúmenes, y cuánto ocupan
docker container prune      # borra los contenedores parados
docker image prune          # borra las imágenes sin nombre que han quedado sueltas

Si algo falla

MensajeCausaSolución
Cannot connect to the Docker daemonDocker Desktop no está abierto.Ábrelo y espera a que diga que el motor está en marcha.
port is already allocatedOtro contenedor usa ese puerto de tu equipo.docker ps para ver cuál, y docker stop o elige otro puerto.
Conflict. The container name "/web" is already in useYa existe un contenedor con ese nombre, quizá parado.docker rm -f web y repite.
toomanyrequestsLímite de descargas de Docker Hub.docker login con tu cuenta.
Rutas como C:/Program Files/Git/usr/…Git Bash ha convertido una ruta del contenedor.Añade la función docker() de la instalación a ~/.bashrc.
the input device is not a TTYHas usado -it y Git Bash no ofrece un terminal compatible.Quita -it y pasa la orden completa: docker exec web nginx -v. En el curso no hace falta -it.

Regla de la IA

Si la IA te propone una orden de Docker, mira la imagen antes de ejecutarla: docker run descarga y ejecuta código de quien publicó esa imagen. Usa imágenes oficiales o de autores conocidos y con versión fija.

Comprobación

  • docker run --rm hello-world funciona y has iniciado sesión con docker login
  • Sabes explicar la diferencia entre imagen y contenedor
  • Sabes leer las partes de hashicorp/terraform:1.9
  • Sabes parar, arrancar y borrar un contenedor, y qué se pierde en cada caso
