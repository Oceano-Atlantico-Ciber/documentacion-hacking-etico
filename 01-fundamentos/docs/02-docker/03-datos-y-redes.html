Datos y redes

Un contenedor se puede borrar en cualquier momento, así que los datos que importan se guardan fuera de él. Y un laboratorio son varios contenedores que se hablan por una red: quién puede llegar a cada uno es una decisión de seguridad.

Ejercicios: E5 y E6

Tres sitios para los datos

Lo que un contenedor escribe en su propia capa desaparece con docker rm. Para conservarlo, se monta en una de sus carpetas algo que vive fuera: un volumen, que gestiona Docker, o una carpeta de tu equipo, un bind mount.

OrdenQué hace
docker volume create datos-dbCrea un volumen. docker run -v también lo crea si no existe.
docker run -v datos-db:/var/lib/postgresql/data …Monta el volumen en esa carpeta del contenedor.
docker run -v ./web:/usr/share/nginx/html:ro …Monta tu carpeta web/. :ro: el contenedor la lee, pero no puede cambiarla.
docker volume ls / docker volume rm datos-dbLista / borra volúmenes. Borrar uno borra sus datos.

Un bind mount sin :ro deja al contenedor escribir en tu carpeta, igual que un programa más. En los laboratorios, Trivy y la web montan lo tuyo en solo lectura por eso. Y cuando en la puesta en marcha haces docker compose down -v, la -v borra los volúmenes: Floci pierde todo lo que desplegaste.

Puertos: quién puede llegar

-p publica un puerto del contenedor en tu equipo, con la forma dirección:puerto-tuyo:puerto-del-contenedor. Si no pones dirección, Docker usa 0.0.0.0: todas las interfaces de tu equipo, también la de la wifi del aula.

docker run -d --name web -p 127.0.0.1:8080:80 nginx:1.27-alpine
docker port web          # 80/tcp -> 127.0.0.1:8080

Redes entre contenedores

Los contenedores se hablan entre sí sin publicar puertos, por una red de Docker. En una red creada por ti, Docker incluye un DNS: cada contenedor llega a los demás por su nombre. En la red por defecto no hay nombres, solo direcciones IP que cambian.

docker network create lab
docker run -d --name web --network lab nginx:1.27-alpine
docker run --rm --network lab curlimages/curl:8.11.1 -s http://web/    # llega por el nombre
docker network inspect lab     # quién está conectado y con qué IP

Una red puede tener una subred fija y cada contenedor una IP fija. La Mini auditoría lo hace para que el mapa de la empresa no cambie entre alumnos: la web siempre es 172.28.0.20.

docker network create --subnet 172.28.0.0/24 lab-mini
docker run -d --name web --network lab-mini --ip 172.28.0.20 nginx:1.27-alpine

Compartir la red de otro contenedor

Un sensor de red tiene que ver el tráfico que llega a un servidor. Para eso no se conecta a la red como uno más: se mete dentro de la red del servidor. Comparten tarjeta de red, IP y puertos, así que el sensor ve exactamente lo que ve el servidor. En la Mini auditoría, Suricata lo hace con la web.

docker run -d --name web --network lab nginx:1.27-alpine
docker run -d --name sensor --network container:web …   # en compose: network_mode: service:web

Regla de la IA

Las órdenes que propone una IA casi siempre publican puertos sin dirección (-p 8080:80). Añade tú 127.0.0.1: salvo que quieras abrir el servicio a la red.

Comprobación

  • Sabes qué significa cada parte de -p 127.0.0.1:8080:80 y quién puede llegar sin la dirección
