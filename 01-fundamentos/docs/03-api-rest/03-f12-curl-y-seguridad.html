F12, curl y seguridad

El navegador te enseña cada petición que hace una web, y curl te deja repetirla cambiando lo que quieras. Con las dos herramientas y tres reglas ya puedes mirar una API como un auditor.

Antes: Métodos, códigos y cabecerasTerminal: Git Bash

F12: lo que sale de tu navegador

Pulsa F12 en Chrome, Edge o Firefox y se abren las herramientas de desarrollo. Su pestaña Network (en español, Red) apunta cada petición que hace la página y la respuesta que recibe. Lo que ves ahí es exactamente lo que viaja: ni más ni menos.

  1. Abre la web, pulsa F12 y ve a la pestaña Network.
  2. Pulsa el filtro Fetch/XHR: deja solo las peticiones que hace el JavaScript a la API, sin imágenes ni estilos.
  3. Marca Preserve log (Conservar registro) para que la lista no se borre al cambiar de página, y recarga.
  4. Pulsa una fila. Headers enseña la URL, el método, el código y las cabeceras; Payload, el cuerpo enviado; Response, lo que devolvió el servidor.

    curl: la petición desde la terminal

    curl envía peticiones HTTP desde la terminal. Viene con Git para Windows, así que ya lo tienes en Git Bash. Elige un método, una URL, si mandas credencial y el cuerpo, y mira cómo se escribe la orden y qué hace cada pieza.

      En Git Bash, todo lo que lleve espacios, comillas dobles, ? o & va entre comillas simples. Por eso el JSON se escribe '{"score": 99}': las simples protegen a las dobles. La dirección api.ranking.example es de ejemplo y no existe; en la práctica usarás la del juego.

      Si la respuesta es un JSON largo, sin -i y con | py -m json.tool al final, Python lo imprime ordenado.

      De F12 a curl en cuatro pasos

      No hace falta escribir la orden a mano: el navegador la copia por ti con todas sus cabeceras.

      F12 → Network→botón derecho en la petición→Copy → Copy as cURL (bash)→pegar en Git Bash→cambiar un dato y repetir
      • Elige siempre la versión (bash). Las versiones cmd y PowerShell usan otras comillas y fallan en Git Bash.
      • Cambia una sola cosa cada vez y compara con la respuesta original: así sabes qué provocó cada diferencia.
      • La orden copiada lleva tus cookies y tus tokens: son tu sesión. No la pegues en una IA en la nube, en un chat ni en tu repositorio sin borrarlos antes.

      Tres reglas para mirar una API

      1 · El cliente es tuyo

      Todo lo que manda el navegador lo puede cambiar quien lo usa: con F12, con curl o escribiendo su propio programa. Si un dato importa, el servidor tiene que comprobarlo o calcularlo él.

      2 · Cada petición va sola

      Una API REST no recuerda nada entre peticiones: cada una tiene que demostrar quién la envía. Una credencial que el servidor comprueba es una prueba; una cabecera que el cliente rellena a su gusto, no.

      3 · Cada método, su papel

      Un GET no debería cambiar nada. Si lo hace, basta con que el navegador cargue una dirección para provocar el cambio, y el navegador carga direcciones solo: imágenes, enlaces, vistas previas.

      Antes de jugar

      La práctica de la unidad, Hackea el ranking, junta todo lo anterior. Ten a mano:

      • La dirección del juego, que es también el alcance: nada fuera de ella
      • F12 con la pestaña Network, el filtro Fetch/XHR y Preserve log
      • Git Bash con curl y las comillas simples
      • Un fichero de notas para apuntar cada petición, su respuesta y lo que cambió

      Comprobación

      • Encuentras en F12 una petición a una API y dices su método, su código y qué envió
      • Escribes en Git Bash un curl con método, cabecera y cuerpo JSON
      • Copias una petición como cURL (bash), cambias un dato y comparas la respuesta
      • Explicas con un ejemplo cada una de las tres reglas
