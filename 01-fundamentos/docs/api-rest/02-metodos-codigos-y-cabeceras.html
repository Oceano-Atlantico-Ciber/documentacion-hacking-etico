Métodos, códigos y cabeceras

Una petición dice qué quieres hacer con el método, y la respuesta dice cómo ha ido con el código. Al final del tema tienes una API simulada para probarlo todo sin instalar nada.

Antes: Cliente, servidor y HTTP

Anatomía de un mensaje

Petición y respuesta tienen las mismas cuatro piezas. Elige una para verla en los dos mensajes. Este ejemplo crea un jugador nuevo.

Los métodos: qué quieres hacer

La ruta dice sobre qué recurso actúas; el método dice qué haces con él. Cinco métodos cubren casi todo: leer, crear, sustituir, cambiar y borrar.

MétodoHaceCuerpoRespuesta típica
GETLeerNo200 con los datos
POSTCrear o lanzar una acciónSí201 y la cabecera Location
PUTSustituir enteroSí, el recurso completo200
PATCHCambiar una parteSí, solo lo que cambia200
DELETEBorrarNo204, sin cuerpo

Seguro e idempotente

Dos palabras que verás en toda la documentación de HTTP. Un método es seguro si solo lee: llamarlo no cambia nada en el servidor. Es idempotente si repetirlo una o diez veces deja el servidor igual que hacerlo una vez.

MétodoSeguroIdempotente
GETSíSí
POSTNoNo
PUTNoSí
PATCHNoNo siempre
DELETENoSí

Importa en seguridad: si un POST que suma puntos se puede repetir sin control, repetirlo es sumar puntos.

Códigos de estado: cómo ha ido

La primera línea de la respuesta lleva un número de tres cifras. La primera cifra ya te dice de quién es el problema.

CódigoNombreCuándo lo verás
200OKLa petición ha funcionado.
201CreatedSe ha creado un recurso; la cabecera Location dice su ruta.
204No ContentHecho, sin nada que devolver.
301, 302MovedEstá en otra dirección, que llega en Location. El navegador la sigue solo.
400Bad RequestFaltan datos o están mal escritos. Lee el mensaje de error.
401UnauthorizedNo has dicho quién eres, o la credencial no vale.
403ForbiddenSe sabe quién eres, pero no tienes permiso.
404Not FoundEsa ruta o ese recurso no existe.
405Method Not AllowedLa ruta existe, pero no con ese método. La cabecera Allow dice cuáles sí.
429Too Many RequestsVas demasiado rápido: hay límite de peticiones.
500Internal Server ErrorEl servidor ha fallado al procesarla.
502Bad GatewayUn intermediario, como un túnel, no llega al servidor.

Para un auditor, los errores también son información: un 401 en vez de un 404 confirma que una ruta existe, y un 500 suele indicar una entrada que el servidor no esperaba.

Cabeceras: datos sobre el mensaje

CabeceraVa enPara qué sirve
HostPeticiónA qué máquina va. Un mismo servidor puede atender varias.
Content-TypeLas dosFormato del cuerpo. En APIs, application/json.
AuthorizationPeticiónQuién eres: un token o una clave. Sin ella, el servidor no sabe quién pide.
Cookie y Set-CookiePetición y respuestaLa otra forma de identificarte: el servidor manda la cookie con Set-Cookie y el navegador la devuelve sola en cada petición.
LocationRespuestaDónde está el recurso creado o adónde redirige.
AllowRespuestaQué métodos admite la ruta, con un 405.
X-…PeticiónCabeceras inventadas por cada aplicación. Las escribe el cliente, así que pueden decir cualquier cosa.

Pruébalo: una API simulada

Esta API de jugadores vive dentro de la página, en tu navegador: no se envía nada por la red. Leer es libre; para cambiar datos hay que mandar la cabecera Authorization. Pulsa un ejemplo o escribe tu propia petición, envíala y mira la respuesta, los datos del servidor y el historial.

Retos para comprobar lo que has leído:

  1. Crea a marta dos veces. ¿Cuántos jugadores hay? ¿Qué método no es idempotente?
  2. Sustituye al jugador 1 con PUT enviando solo {"score": 50}. ¿Por qué falla, si con PATCH funciona?
  3. Borra al jugador 2 dos veces. Compara los dos códigos y cómo quedan los datos.
  4. Consigue un 401, un 404, un 405 y un 400, y explica cada uno con una frase.

Comprobación

  • Señalas en cualquier mensaje HTTP la primera línea, las cabeceras, la línea en blanco y el cuerpo
  • Eliges el método para leer, crear, sustituir, cambiar y borrar, y sabes cuáles son seguros e idempotentes
  • Por la primera cifra de un código sabes si el fallo es tuyo o del servidor
  • Sabes qué cabecera dice quién eres y qué cabeceras puede inventarse el cliente
  • Has resuelto los cuatro retos de la API simulada
