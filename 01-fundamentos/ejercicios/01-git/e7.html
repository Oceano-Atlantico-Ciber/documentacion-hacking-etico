E7 · Revert

Un commit con un error ya está en GitHub. Deshazlo sin reescribir la historia que otros pueden tener.

Teoría
Git 4 · Deshacer y seguridad
Trabajas en
fundamentos/git/e7/
Etiqueta
entrega-fundamentos-git-e7 sobre main

1Prepara el escenario

Desde tu repositorio, en main y sin cambios pendientes:

python3 ../documentacion-hacking-etico/01-fundamentos/ejercicios/01-git/preparar.py e7

Añade tres commits a main. El segundo activa por error el modo depuración del servidor en config.ini.

2Publica main

git push

Desde ahora el commit erróneo es público: ya no se puede reescribir.

3Revierte el commit erróneo

git log --oneline -4
git revert <sha-del-commit-erróneo>

Git crea un commit nuevo que aplica el cambio inverso. Guarda el mensaje que propone.

4Comprueba antes de subir

git log --oneline -5
git show HEAD

Siguen los tres commits y encima hay uno Revert "…" que devuelve debug = false.

El corrector marca fallo si:

  • El commit erróneo o el siguiente han desaparecido de la historia (reset, rebase…).
  • No hay un commit que deshaga exactamente el erróneo. Hazlo con git revert.
  • config.ini no queda como antes del error.

5Sube y etiqueta

git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector git. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E7 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-git-e7 -m "E7 resuelto"
git push origin entrega-fundamentos-git-e7

Cuenta la primera etiqueta que subas. Moverla o borrarla después no cambia la entrega.
