E6 · Rebase interactivo

Cuatro commits a medias no cuentan nada. Fúndelos en uno que se lea de un vistazo.

Teoría
Git 3 · Remotos y reescribir historia
Trabajas en
fundamentos/git/e6/
Etiqueta
entrega-fundamentos-git-e6 sobre git/e6-wip

1Prepara el escenario

Desde tu repositorio, en main y sin cambios pendientes:

python3 ../documentacion-hacking-etico/01-fundamentos/ejercicios/01-git/preparar.py e6

Crea git/e6-wip con cuatro commits wip(e6): paso N que van escribiendo informe.md.

2Abre el rebase interactivo

git switch git/e6-wip
git rebase -i HEAD~4

En el editor, deja pick en la primera línea y cambia las otras tres a squash (o fixup). Guarda y cierra.

Si el editor es vim y prefieres otro: git config --global core.editor "code --wait".

3Escribe el mensaje

Git te pide el mensaje del commit resultante. Borra todo y deja exactamente:

docs(e6): informe de alcance

4Comprueba antes de subir

git log --oneline main..git/e6-wip
git show --stat git/e6-wip

Una sola línea, con el mensaje exacto, que solo crea informe.md. Si ya habías subido la rama, usa git push --force-with-lease.

El corrector marca fallo si:

  • El último commit no se llama exactamente docs(e6): informe de alcance.
  • Quedan commits wip en la historia.
  • No queda un único commit que cree informe.md y nada más.
  • informe.md no tiene el contenido del último paso.

5Sube y etiqueta

git push -u origin git/e6-wip

Mira el check Corrector git junto al último commit de main en GitHub. Cuando la fila de E6 salga sin fallos, etiqueta la punta de git/e6-wip:

git tag -a entrega-fundamentos-git-e6 git/e6-wip -m "E6 resuelto"
git push origin entrega-fundamentos-git-e6

Cuenta la primera etiqueta que subas. Moverla o borrarla después no cambia la entrega.
