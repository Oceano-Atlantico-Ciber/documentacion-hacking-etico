E8 · Secreto filtrado

Alguien subió una clave de API y luego la borró. Encuéntrala en la historia, púrgala y comprueba qué queda en GitHub.

Teoría
Git 4 · Deshacer y seguridad
Trabajas en
fundamentos/git/e8/
Etiqueta
entrega-fundamentos-git-e8 sobre git/e8-app

1Prepara el escenario

Desde tu repositorio, en main y sin cambios pendientes:

python3 ../documentacion-hacking-etico/01-fundamentos/ejercicios/01-git/preparar.py e8

Crea git/e8-app. En uno de sus commits alguien subió un .env con una clave de API, y en otro lo borró.

2Sube la rama tal cual

git push -u origin git/e8-app

Así simulas la filtración real: la clave ya está en GitHub. Sin este paso el ejercicio no se puede superar.

3Encuentra el commit que la introdujo

git log -p -S API_KEY= git/e8-app

Salen dos commits: el que añade la clave (líneas con +) y el que la borra (−). Apunta el SHA completo, de 40 caracteres, del que la añade.

4Purga el .env de toda la rama

Instala git-filter-repo según tu sistema y comprueba que responde:

SistemaOrden
macOSbrew install git-filter-repo
Ubuntu o Debiansudo apt install git-filter-repo
Windowspy -m pip install git-filter-repo
git filter-repo --version

Después, purga:

git filter-repo --refs git/e8-app --path fundamentos/git/e8/.env --invert-paths --force

Reescribe todos los commits de la rama sin ese fichero. Los SHA cambian.

5Guarda tu hallazgo

git switch git/e8-app

Crea con tu editor fundamentos/git/e8/hallazgo.txt con el SHA del paso 3 en una línea y haz commit:

git add fundamentos/git/e8/hallazgo.txt
git commit -m "docs(e8): commit que filtró la clave"

6Comprueba antes de subir

git log -p -S API_KEY= git/e8-app
git ls-tree -r --name-only git/e8-app fundamentos/git/e8

La primera orden no debe mostrar nada, y en la carpeta no debe haber .env.

El corrector marca fallo si:

  • Falta alguno de los commits originales de la rama: purga el fichero, no los commits.
  • La clave sigue en la historia de la rama.
  • hallazgo.txt no contiene el SHA completo, o ese commit sigue en la rama.
  • Ese SHA no es el commit que subió la clave a GitHub, por ejemplo porque purgaste antes de subir.

7Sube y etiqueta

git push --force-with-lease origin git/e8-app

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector git. Hay una fila por ejercicio, también para los que se trabajan en una rama, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E8 salga sin fallos, etiqueta la punta de git/e8-app:

git tag -a entrega-fundamentos-git-e8 git/e8-app -m "E8 resuelto"
git push origin entrega-fundamentos-git-e8

Cuenta la primera etiqueta que subas. Moverla o borrarla después no cambia la entrega.

8Mira qué queda en GitHub

Abre https://github.com/Oceano-Atlantico-Ciber/entregas-<tu-usuario>/commit/<SHA>. ¿Sigue ahí la clave? ¿Qué habría que hacer con ella en un caso real?

Esta pregunta no se entrega: la comentamos en clase.
