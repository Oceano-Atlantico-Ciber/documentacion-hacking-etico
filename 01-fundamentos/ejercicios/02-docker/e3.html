E3 · Capas, caché y .dockerignore

Un Dockerfile que funciona, pero tarda siempre lo mismo y mete en la imagen lo que no debe. Arréglalo sin cambiar lo que hace.

Teoría
Docker 2 · Construir imágenes
Trabajas en
fundamentos/docker/e3/
Etiqueta
entrega-fundamentos-docker-e3 sobre main

1Prepara el escenario

Desde tu repositorio, con Docker Desktop en marcha:

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/ejercicios/02-docker/preparar.py e3
cd fundamentos/docker/e3

Deja un cliente de una API: Dockerfile, app.py, requirements.txt, un .env con un token y la carpeta notas/. El .env no aparece en git status: tu .gitignore ya lo excluye.

2Mira el problema

docker build -t e3-app:1.0 .
docker run --rm e3-app:1.0 ls -a /app
docker run --rm e3-app:1.0 cat /app/.env

El token y tus notas están dentro de la imagen. Cambia una letra de un comentario de app.py y reconstruye: pip install se repite entero.

3Reordena las capas

Edita el Dockerfile para que la instalación de dependencias salga de la caché mientras requirements.txt no cambie: copia primero ese fichero, instala y copia después app.py. Deja el mismo FROM y el mismo CMD.

4Deja fuera lo que no debe entrar

code .dockerignore

Excluye .env y notas/. Excluye también Dockerfile y .dockerignore, que no le hacen falta a la imagen.

5Comprueba antes de subir

docker build -t e3-app:1.0 .
# cambia un comentario de app.py y:
docker build --progress=plain -t e3-app:1.0 . 2>&1 | grep -B1 CACHED
docker run --rm e3-app:1.0 ls -a /app
docker run --rm e3-app:1.0

El paso de pip install sale como CACHED, en /app solo están app.py y requirements.txt, y el programa sigue funcionando.

El corrector marca fallo si:

  • La imagen no construye o python app.py no funciona.
  • .env o notas/ están dentro de la imagen.
  • Al cambiar app.py, pip install no sale de la caché.
  • El programa no imprime lo mismo que antes, o has cambiado requirements.txt, el FROM o el CMD.

6Sube y etiqueta

git add .
git commit -m "fix(docker-e3): capas en orden y contexto limpio"
git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E3 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e3 -m "E3 resuelto"
git push origin entrega-fundamentos-docker-e3

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. Cuenta tal como esté al cerrar el plazo; si la mueves después, la entrega queda fuera de plazo.
