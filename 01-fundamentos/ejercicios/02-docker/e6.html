E6 · Red y puertos

Una web y una base de datos en una red propia: se encuentran por su nombre, la base de datos no se publica y la web solo para ti.

Teoría
Docker 3 · Datos y redes
Trabajas en
fundamentos/docker/e6/
Etiqueta
entrega-fundamentos-docker-e6 sobre main

1Prepara la carpeta

E6 no tiene ficheros de partida. Desde tu repositorio:

mkdir -p fundamentos/docker/e6 && cd fundamentos/docker/e6

Necesitas la imagen sondeo:1.0 de E2; si la borraste, vuelve a construirla.

2Escribe levantar.sh

code levantar.sh

Con el mismo principio que en E5, el script tiene que:

  • Crear la red e6-red.
  • Arrancar e6-web (nginx:1.27-alpine) en esa red, publicado en 127.0.0.1:8086.
  • Arrancar e6-datos (postgres:16-alpine) en esa red, sin publicar ningún puerto.

3Comprueba quién llega a quién

bash levantar.sh
docker port e6-web
docker port e6-datos
docker run --rm --network e6-red curlimages/curl:8.11.1 -s -o /dev/null -w '%{http_code}\n' http://e6-web/
docker run --rm curlimages/curl:8.11.1 -s -m 3 http://e6-web/

e6-web está publicado solo en 127.0.0.1 y e6-datos, en ninguno. Dentro de la red, curl llega por el nombre (200); fuera de ella, el nombre no existe.

4Sondea desde dentro de la red

until docker exec e6-datos pg_isready -U postgres -h localhost; do sleep 1; done
{ docker run --rm --network e6-red sondeo:1.0 e6-web 80 443
  docker run --rm --network e6-red sondeo:1.0 e6-datos 5432 80; } | tee sondeo.txt
docker rm -f e6-web e6-datos && docker network rm e6-red

El 5432 de la base de datos está abierto para quien esté en la red, aunque no se haya publicado: es lo que verá nmap en la Mini auditoría.

El corrector marca fallo si:

  • levantar.sh falla en un equipo limpio.
  • e6-web o e6-datos no están en e6-red, o no salen de las imágenes indicadas.
  • La web no publica en 127.0.0.1:8086, o la base de datos publica algún puerto.
  • sondeo.txt no tiene las cuatro líneas, con 80 y 5432 abiertos.

5Sube y etiqueta

git add .
git commit -m "feat(docker-e6): red propia y puertos solo donde hacen falta"
git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E6 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e6 -m "E6 resuelto"
git push origin entrega-fundamentos-docker-e6

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. Cuenta tal como esté al cerrar el plazo; si la mueves después, la entrega queda fuera de plazo.
