E1 · Ciclo de vida

Arranca un servidor web, cámbiale la página, páralo, vuelve a arrancarlo y entrega lo que Docker sabe de él.

Teoría
Docker 1 · Imágenes y contenedores
Trabajas en
fundamentos/docker/e1/
Etiqueta
entrega-fundamentos-docker-e1 sobre main

1Prepara el escenario

Desde tu repositorio, con Docker Desktop en marcha:

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/ejercicios/02-docker/preparar.py e1
cd fundamentos/docker/e1

Deja en la carpeta index.html, una página con tu usuario. No cambies su contenido.

2Descarga la imagen y arranca el contenedor

docker pull nginx:1.27-alpine
docker run -d --name e1-web -p 127.0.0.1:8080:80 nginx:1.27-alpine
docker ps

El nombre tiene que ser exactamente e1-web y el puerto, 127.0.0.1:8080.

3Pídele la página

curl -i http://localhost:8080/

La primera línea es HTTP/1.1 200 OK y el cuerpo es la página de bienvenida de nginx.

4Cambia la página por la tuya

docker cp index.html e1-web:/usr/share/nginx/html/index.html
curl http://localhost:8080/

Ahora responde con tu página. Has cambiado la capa escribible del contenedor, no la imagen.

5Páralo y vuelve a arrancarlo

docker stop e1-web
docker ps -a
docker start e1-web
curl http://localhost:8080/

Parado, docker ps -a lo muestra como Exited. Al arrancarlo sigue sirviendo tu página: parar no borra la capa.

6Guarda las pruebas

docker container inspect e1-web > inspect.json
docker logs e1-web > logs.txt 2>&1

inspect.json es todo lo que Docker sabe del contenedor; logs.txt, cada petición que recibió nginx.

7Bórralo y comprueba

docker rm -f e1-web
curl http://localhost:8080/

El último curl falla: el contenedor y tu cambio ya no existen. Si lanzaras otro desde la imagen, volvería la página de bienvenida.

El corrector marca fallo si:

  • Faltan inspect.json o logs.txt, o index.html ha cambiado.
  • El contenedor no se llamaba e1-web, no salía de nginx:1.27-alpine o no publicaba 127.0.0.1:8080.
  • El contenedor no llegó a pararse y volver a arrancar.
  • En logs.txt no hay ninguna petición servida con tu página.

8Sube y etiqueta

git add .
git commit -m "feat(docker-e1): ciclo de vida de e1-web"
git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E1 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e1 -m "E1 resuelto"
git push origin entrega-fundamentos-docker-e1

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. Cuenta tal como esté al cerrar el plazo; si la mueves después, la entrega queda fuera de plazo.
