E4 · El secreto de la capa

Te pasan una imagen ya construida. Alguien metió en ella la clave de una API y la «borró». Recupérala como haría un atacante y reconstruye la imagen sin ella.

Teoría
Docker 2 · Construir imágenes
Trabajas en
fundamentos/docker/e4/
Etiqueta
entrega-fundamentos-docker-e4 sobre main

1Prepara el escenario

Desde tu repositorio, con Docker Desktop en marcha:

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/ejercicios/02-docker/preparar.py e4
cd fundamentos/docker/e4

Construye la imagen e4-informe:1.0 con una clave distinta para cada alumno, y borra la clave de tu carpeta: solo queda dentro de la imagen. Deja también el Dockerfile que se usó.

2Comprueba que «no está»

docker run --rm e4-informe:1.0 ls -a /app
docker history e4-informe:1.0

En el contenedor no hay ninguna clave. Pero el historial tiene una capa COPY api.key . de unos KB.

3Extrae las capas y encuentra la clave

docker save e4-informe:1.0 -o e4.tar
mkdir capas && tar -xf e4.tar -C capas
for capa in capas/blobs/sha256/*; do tar -tf "$capa" 2>/dev/null | grep api.key | sed "s|^|$capa  |"; done

Salen dos capas: una con app/api.key, la que la copió, y otra con app/.wh.api.key, la marca de «borrado» que dejó rm. Lee la clave de la primera:

tar -xOf capas/blobs/sha256/<la-capa-con-app/api.key> app/api.key

e4.tar y capas/ no se suben: el .gitignore de la carpeta ya los excluye.

4Redacta el hallazgo sin filtrar la clave

code hallazgo.txt

Una línea con la clave ocultada, como en un informe de auditoría: oa-, sus 8 primeros caracteres y … (por ejemplo, oa-3f9c1a2b…). La clave completa no debe estar en tu repositorio.

5Reconstruye sin el secreto

Guarda la clave que encontraste en api.key (tu .gitignore excluye *.key) y cambia el Dockerfile para que informe.py --comprobar la lea de un secreto de construcción, en /run/secrets/api, sin COPY. Cómo, en Docker 2 · Un secreto en una capa. Añade un .dockerignore con api.key, *.tar y capas/.

docker build --secret id=api,src=api.key -t e4-informe:2.0 .

La construcción tiene que decir clave de la API válida.

6Comprueba antes de subir

docker save e4-informe:2.0 -o e4-2.tar
mkdir capas2 && tar -xf e4-2.tar -C capas2
for capa in capas2/blobs/sha256/*; do tar -tf "$capa" 2>/dev/null | grep api.key; done
rm -r capas2 e4-2.tar

El bucle no muestra nada: ninguna capa contiene la clave.

El corrector marca fallo si:

  • hallazgo.txt no empieza por los 8 primeros caracteres de tu clave, o contiene la clave completa.
  • Algún fichero subido contiene la clave completa.
  • Con tu clave como secreto, el Dockerfile no construye o la comprobación no se ejecuta.
  • Alguna capa de la imagen resultante contiene la clave.

7Sube y etiqueta

git add .
git commit -m "fix(docker-e4): la clave ya no entra en ninguna capa"
git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E4 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e4 -m "E4 resuelto"
git push origin entrega-fundamentos-docker-e4

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. Cuenta tal como esté al cerrar el plazo; si la mueves después, la entrega queda fuera de plazo.
