E5 · Datos que sobreviven

Una base de datos que conserva sus datos aunque borres el contenedor y una web que sirve una carpeta tuya sin poder modificarla.

Teoría
Docker 3 · Datos y redes
Trabajas en
fundamentos/docker/e5/
Etiqueta
entrega-fundamentos-docker-e5 sobre main

1Prepara el escenario

Desde tu repositorio, con Docker Desktop en marcha:

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/ejercicios/02-docker/preparar.py e5
cd fundamentos/docker/e5

Deja web/index.html, la página de la empresa con tu usuario.

2Escribe levantar.sh

code levantar.sh

Un script de bash que, desde su carpeta, haga tres cosas:

  • Cree el volumen e5-datos.
  • Arranque e5-db desde postgres:16-alpine, con POSTGRES_PASSWORD y el volumen montado en /var/lib/postgresql/data.
  • Arranque e5-web desde nginx:1.27-alpine, publicado en 127.0.0.1:8085 y con ./web montada en solo lectura en /usr/share/nginx/html.

Empieza así: set -euo pipefail para que pare en el primer error, la variable que evita que Git Bash convierta las rutas (en Docker 1 va en .bashrc, pero un script no lo lee) y el cd a su carpeta:

#!/usr/bin/env bash
set -euo pipefail
export MSYS_NO_PATHCONV=1
cd "$(dirname "$0")"

La contraseña de este ejercicio puede ir escrita en el script porque es de usar y tirar. En E7 la sacarás a un .env.

3Arranca y guarda un dato

bash levantar.sh
until docker exec e5-db pg_isready -U postgres -h localhost; do sleep 1; done
docker exec e5-db psql -U postgres -c "CREATE TABLE hallazgos (id serial PRIMARY KEY, texto text NOT NULL)"
docker exec e5-db psql -U postgres -c "INSERT INTO hallazgos (texto) VALUES ('primer hallazgo de <tu-usuario>')"

El bucle until espera a que Postgres acepte conexiones: la primera vez tarda unos segundos en crear la base de datos.

4Borra los contenedores y recréalos

docker rm -f e5-db e5-web
bash levantar.sh
until docker exec e5-db pg_isready -U postgres -h localhost; do sleep 1; done
docker exec e5-db psql -U postgres -c "SELECT texto FROM hallazgos" | tee consulta.txt

El contenedor es nuevo, pero el dato sigue: estaba en el volumen. docker volume create no falla si el volumen ya existe.

5Comprueba la web

curl http://localhost:8085/
docker exec e5-web sh -c 'echo prueba > /usr/share/nginx/html/prueba.html'
docker rm -f e5-db e5-web

La web sirve tu página, y el contenedor no puede escribir en tu carpeta: Read-only file system.

El corrector marca fallo si:

  • levantar.sh falla en un equipo limpio, o no crea e5-db y e5-web como dice el enunciado.
  • Los datos de Postgres no están en el volumen e5-datos, o la web no monta ./web en solo lectura.
  • La web no responde en 127.0.0.1:8085 con tu página.
  • consulta.txt no muestra tu fila ((1 row)).

6Sube y etiqueta

git add .
git commit -m "feat(docker-e5): base de datos con volumen y web con bind mount"
git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E5 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e5 -m "E5 resuelto"
git push origin entrega-fundamentos-docker-e5

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. Cuenta tal como esté al cerrar el plazo; si la mueves después, la entrega queda fuera de plazo.
