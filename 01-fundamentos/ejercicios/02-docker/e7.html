E7 · Tu primer compose

Lo que hiciste a mano en E5 y E6, en un solo docker-compose.yml, con la contraseña fuera del repositorio.

Teoría
Docker 4 · Compose y seguridad
Trabajas en
fundamentos/docker/e7/
Etiqueta
entrega-fundamentos-docker-e7 sobre main

1Prepara la carpeta

E7 no tiene ficheros de partida: reutiliza la web de E5. Desde tu repositorio:

mkdir -p fundamentos/docker/e7 && cd fundamentos/docker/e7
cp -r ../e5/web .
code docker-compose.yml

2Escribe el compose

Proyecto e7-lab, una red lab, un volumen datos y cuatro servicios en esa red:

ServicioQué es
webnginx:1.27-alpine, publicado en 127.0.0.1:8087, con ./web en solo lectura.
datospostgres:16-alpine con el volumen datos, sin puertos publicados. POSTGRES_PASSWORD sale de ${POSTGRES_PASSWORD:?falta en .env}.
sondeoSe construye desde ../e2 con la imagen sondeo:1.0. En el perfil herramientas.
curlcurlimages/curl:8.11.1. En el perfil herramientas.

Cada clave equivale a una opción de docker run: la tabla está en Docker 4.

3La contraseña, en .env

printf 'POSTGRES_PASSWORD=\n' > .env.ejemplo
cp .env.ejemplo .env
code .env

Pon una contraseña en .env. .env.ejemplo se sube, vacío, para que otro sepa qué variable hace falta; .env no aparece en git status.

4Levántalo y pruébalo

docker compose config -q && echo correcto
docker compose up -d
docker compose ps
docker compose run --rm curl -s http://web/
docker compose run --rm sondeo datos 5432
docker compose down

up solo levanta web y datos; las herramientas se lanzan con run. Prueba también a vaciar .env: config se niega con tu mensaje.

El corrector marca fallo si:

  • docker compose config falla con un .env completo, o no falla sin él.
  • Algún servicio no cumple la tabla: imagen, puerto, montaje, red o perfil.
  • Con up, curl no recibe tu página o el sondeo no ve el 5432 de datos.
  • .env está en el repositorio, o falta .env.ejemplo.

5Sube y etiqueta

git add .
git commit -m "feat(docker-e7): el laboratorio en un compose"
git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E7 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e7 -m "E7 resuelto"
git push origin entrega-fundamentos-docker-e7

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. Cuenta tal como esté al cerrar el plazo; si la mueves después, la entrega queda fuera de plazo.
