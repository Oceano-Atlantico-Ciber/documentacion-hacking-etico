E2 · Tu primera imagen

Empaqueta en una imagen un sondeo de puertos escrito en Python y úsalo contra otro contenedor.

Teoría
Docker 2 · Construir imágenes
Trabajas en
fundamentos/docker/e2/
Etiqueta
entrega-fundamentos-docker-e2 sobre main

1Prepara el escenario

Desde tu repositorio, con Docker Desktop en marcha:

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/ejercicios/02-docker/preparar.py e2
cd fundamentos/docker/e2

Deja sondeo.py, que dice qué puertos TCP de un equipo aceptan conexiones. No hace falta que lo cambies, ni Python en tu equipo: correrá en la imagen.

2Escribe el Dockerfile

code Dockerfile

Cuatro instrucciones: parte de python:3.12-alpine, trabaja en /app, copia sondeo.py y haz que el contenedor arranque con python sondeo.py mediante ENTRYPOINT. La tabla de instrucciones está en Docker 2.

3Construye la imagen

docker build -t sondeo:1.0 .
docker run --rm sondeo:1.0

Sin argumentos, el sondeo muestra cómo se usa. La etiqueta tiene que ser sondeo:1.0: la reutilizas en E6 y E7.

4Sondea otro contenedor

Arranca un nginx sin publicar puertos y averigua su IP en la red por defecto de Docker:

docker run -d --name e2-diana nginx:1.27-alpine
docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' e2-diana

Sondea esa IP y guarda el resultado:

docker run --rm sondeo:1.0 <IP> 22 80 443 | tee sondeo.txt
docker rm -f e2-diana

El 80 sale abierto y los otros dos, cerrado. Por IP funciona; por el nombre e2-diana, no. El motivo, en Docker 3.

El corrector marca fallo si:

  • El Dockerfile no construye, no parte de python:3.12-alpine o la imagen no arranca con el sondeo.
  • Con los argumentos equipo puerto, la imagen no imprime lo mismo que python sondeo.py.
  • sondeo.txt no tiene las tres líneas, con el 80 abierto.

5Sube y etiqueta

git add .
git commit -m "feat(docker-e2): imagen del sondeo de puertos"
git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E2 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e2 -m "E2 resuelto"
git push origin entrega-fundamentos-docker-e2

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. Cuenta tal como esté al cerrar el plazo; si la mueves después, la entrega queda fuera de plazo.
