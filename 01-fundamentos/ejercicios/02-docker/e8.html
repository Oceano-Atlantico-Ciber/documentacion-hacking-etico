E8 · Auditar un compose

El panel de administración de la empresa se despliega con un compose que abre todas las puertas. Audítalo, ciérralas y documenta cada fallo.

Teoría
Docker 4 · Compose y seguridad
Trabajas en
fundamentos/docker/e8/
Etiqueta
entrega-fundamentos-docker-e8 sobre main

1Prepara el escenario

Desde tu repositorio, con Docker Desktop en marcha:

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/ejercicios/02-docker/preparar.py e8
cd fundamentos/docker/e8

Deja docker-compose.yml, la carpeta panel/ con su Dockerfile y web/.

2Levántalo tal cual y mira lo que ve cualquiera

docker compose up -d --build
curl http://localhost/docker-compose.yml
docker compose down

Cualquiera que llegue a tu puerto 80, también desde la wifi del aula, lee el propio compose con sus contraseñas. Es tu primer hallazgo.

3Pasa Trivy al Dockerfile

docker run --rm -v ./:/work:ro aquasec/trivy:0.58.0 config --severity HIGH,CRITICAL /work

4Corrige

Revisa el compose y el Dockerfile con la lista de Docker 4 · Puertas que abre un compose. El panel y la web tienen que seguir funcionando en 127.0.0.1:8000 y 127.0.0.1:8088. Las contraseñas pasan a .env, con un .env.ejemplo vacío.

5Documenta

code informe.md

Una tabla con una fila por fallo: línea original, qué riesgo tenía y cómo lo has corregido. Ningún valor de .env en el informe.

6Comprueba antes de subir

docker run --rm -v ./:/work:ro aquasec/trivy:0.58.0 config --severity HIGH,CRITICAL /work
docker compose up -d --build
curl http://localhost:8000/
curl -i http://localhost:8088/docker-compose.yml
docker compose exec panel id
docker compose down

Trivy sin avisos, el panel responde, la web ya no sirve el compose (404) y el panel no corre como root.

El corrector marca fallo si:

  • Trivy da avisos altos o críticos.
  • Alguna imagen no tiene versión fija, o algún puerto se publica fuera de 127.0.0.1; la base de datos no publica ninguno.
  • Queda privileged, el socket de Docker o una carpeta montada con escritura.
  • Alguna contraseña sigue escrita en el compose, o .env está en el repositorio.
  • El panel no arranca o corre como root, o informe.md no tiene una fila por fallo.

7Sube y etiqueta

git add .
git commit -m "fix(docker-e8): panel sin puertas abiertas"
git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector docker. Hay una fila por ejercicio, y se actualiza cuando el docente lanza la corrección. Cuando la fila de E8 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-docker-e8 -m "E8 resuelto"
git push origin entrega-fundamentos-docker-e8

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta. Cuenta tal como esté al cerrar el plazo; si la mueves después, la entrega queda fuera de plazo.
