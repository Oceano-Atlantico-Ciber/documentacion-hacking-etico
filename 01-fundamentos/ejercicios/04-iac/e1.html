E1 · A mano, una vez

Crea con la CLI de AWS un bucket con un fichero y un usuario que solo pueda leerlo. Apunta cada orden: en el E3 ese mismo trabajo pasará a Terraform.

1Prepara el ejercicio y levanta tu nube

Con la CLI de AWS configurada como dice IaC 1 · Prepara tu equipo y Docker Desktop en marcha:

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/ejercicios/04-iac/preparar.py e1
cd fundamentos/iac
docker compose up -d
cd e1

En fundamentos/iac/ quedan el docker-compose.yml de la unidad y su .gitignore. En e1/, notas.txt y un LEEME.md con los nombres que te tocan: un bucket e1-notas-<huella> y un usuario lector-<huella>. La huella sale de tu usuario de GitHub: cada alumno tiene la suya.

2Crea el bucket y sube el fichero

aws s3 mb s3://e1-notas-<huella>
aws s3 cp notas.txt s3://e1-notas-<huella>/notas.txt
aws s3 ls s3://e1-notas-<huella>

3Crea el lector y su política

Escribe politica.json con lo mínimo para que el lector pueda leer notas.txt de tu bucket: ni borrar, ni escribir, ni tocar IAM. El ejemplo de IaC 1 · Políticas de IAM te sirve de punto de partida. Después:

aws iam create-user --user-name lector-<huella>
aws iam put-user-policy --user-name lector-<huella> --policy-name lectura-notas --policy-document file://politica.json
aws iam create-access-key --user-name lector-<huella>

4Compruébalo como el lector

Guarda la clave que te ha dado create-access-key en un perfil aparte y prueba lo que puede y lo que no:

aws configure set aws_access_key_id <AccessKeyId> --profile lector
aws configure set aws_secret_access_key <SecretAccessKey> --profile lector
aws configure set region eu-west-1 --profile lector
aws configure set endpoint_url http://localhost:4566 --profile lector
aws s3 cp s3://e1-notas-<huella>/notas.txt - --profile lector
aws s3 rm s3://e1-notas-<huella>/notas.txt --profile lector
aws iam list-users --profile lector

La primera lectura enseña el fichero; las dos últimas tienen que acabar en AccessDenied. Si alguna funciona, tu política da de más.

5Apunta lo que has hecho

code ordenes.sh

Las órdenes aws que crean todo, en orden, una por línea (las de los pasos 2 y 3). Nada de las pruebas del paso 4, ni claves. El corrector las lanza en una cuenta vacía, desde esta carpeta, así que los ficheros van con ruta relativa (file://politica.json) y sin variables: escribe los nombres tal cual.

El corrector marca fallo si:

  • Falta ordenes.sh, o alguna línea no es una orden aws de S3, IAM o STS, o falla en una cuenta nueva.
  • No existe el bucket, o su notas.txt no es el que te dio preparar.py.
  • No existe el lector, o no tiene una política en línea llamada lectura-notas.
  • Con su clave, el lector no puede leer notas.txt, o puede borrarlo, o puede listar usuarios de IAM.

6Pruébalo en tu equipo

Antes de subir, con Docker Desktop en marcha, pasa las mismas comprobaciones que el corrector. Trabajan sobre una copia de lo que ya está en commits (la etiqueta si existe, si no main) y en una Floci nueva y vacía, no en la tuya:

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/ejercicios/04-iac/pruebas.py e1

Cada ✗ dice qué falla y por qué. Corrige, haz commit y repite hasta que salga ✓ superado. La primera vez descarga las imágenes de Floci, la CLI de AWS y Terraform.

7Sube y etiqueta

git add fundamentos/iac
git commit -m "feat(iac-e1): bucket y lector creados a mano"
git push

En la portada de tu repositorio en GitHub, pulsa el ✓ o la ✗ junto al último commit de main y abre Details en Corrector iac. Cuando la fila de E1 salga sin fallos, etiqueta:

git tag -a entrega-fundamentos-iac-e1 -m "E1 resuelto"
git push origin entrega-fundamentos-iac-e1

Si el corrector marca fallos después de etiquetar, corrígelos, súbelos y mueve la etiqueta.
