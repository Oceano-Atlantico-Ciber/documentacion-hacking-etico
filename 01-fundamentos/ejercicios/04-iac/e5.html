E5 · Un laboratorio completo

Escribe desde cero un laboratorio pequeño: una red, un servidor web que se ve desde fuera y una base de datos que solo ve el servidor. Es un ejemplo para practicar, no el laboratorio de ningún bloque.

Teoría
IaC 3 · Redes y servidores
Aprendes
VPC, subredes, grupos de seguridad que se refieren a otros, EC2 con user_data y RDS privada.
Trabajas en
fundamentos/iac/e5/
Etiqueta
entrega-fundamentos-iac-e5 sobre main
Plazo
Lo anuncia el docente

1Prepara el ejercicio

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/ejercicios/04-iac/preparar.py e5
cd fundamentos/iac/e5

Deja proveedor.tf y un LEEME.md con la página que tiene que servir tu servidor web.

2Escribe el laboratorio

En main.tf (o en varios .tf, como prefieras), con la forma de IaC 3 · La forma de un laboratorio:

  • Una VPC con etiqueta Name, una subred pública y dos privadas en dos zonas.
  • Un servidor web en la subred pública cuyo user_data escribe tu página en /usr/share/nginx/html/index.html.
  • Su grupo de seguridad abre el 80 a todo el mundo, y nada más hacia fuera de la VPC.
  • Una base de datos PostgreSQL en las subredes privadas, no accesible desde fuera, con un grupo que solo admite el 5432 desde el grupo del servidor web.
  • La contraseña de la base de datos en una variable sensitive, nunca en el user_data.
  • Una salida con la IP del servidor web.

3Despliega, revisa y destruye

terraform init
terraform fmt
terraform validate
terraform apply
terraform output
aws ec2 describe-security-groups --filters Name=vpc-id,Values=<tu-vpc> --query "SecurityGroups[].[GroupName,IpPermissions]"
aws rds describe-db-instances --query "DBInstances[].[DBInstanceIdentifier,PubliclyAccessible]"
terraform destroy

Los servidores y la base de datos están simulados en Floci: existen en la API con su configuración, que es lo que revisas, pero no arrancan. Un laboratorio bien escrito se crea y se borra entero con una orden.

El corrector marca fallo si:

  • apply falla o no crea exactamente una VPC.
  • La VPC tiene menos de tres subredes, o no hay servidor ni base de datos dentro.
  • El user_data del servidor no escribe tu página.
  • El grupo del servidor no abre el 80 a todo el mundo, o abre algo más a todo el mundo.
  • La base de datos es accesible desde fuera, o su grupo admite direcciones u otro grupo que no es el del servidor.
  • Las salidas no dan la IP del servidor, o después de destroy queda alguna VPC.

4Pruébalo en tu equipo

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/ejercicios/04-iac/pruebas.py e5
