01 · Git

Antes de empezar: 03 · Git y GitHub y 06 · Primer commit.

Carpeta 01-git/. Teoría: Git 1 · Modelo y commits, Git 2 · Ramas y fusiones, Git 3 · Remotos y reescribir historia y Git 4 · Deshacer y seguridad.

Ocho ejercicios en fundamentos/git/ de tu repositorio de entregas. Cada uno empieza con preparar.py, que crea los ficheros, ramas y commits de partida a partir de tu usuario de GitHub: tu escenario es distinto del de tus compañeros. Ejecútalo desde tu repositorio, en main y sin cambios pendientes:

cd ~/hacking-etico/entregas-<tu-usuario>
py ../documentacion-hacking-etico/01-fundamentos/ejercicios/01-git/preparar.py e1

Cada ejercicio se entrega con su propia etiqueta anotada, entrega-fundamentos-git-eN, sobre el commit donde está resuelto. Qué es una etiqueta y cómo se crea se explica en Git 1, antes del primer ejercicio. Cada ejercicio tiene su página con los pasos, cómo comprobarlo y qué mira el corrector. Hazlos en orden: cada uno usa solo lo visto en su tema y en los anteriores.

Cuenta la etiqueta tal como esté al cerrar el plazo, que es el del bloque: jueves 5 de noviembre a las 23:59. Si el corrector marca fallos, se puede mover (Git 3). Moverla después de la fecha límite deja la entrega fuera de plazo. Antes de etiquetar, sube tu trabajo y mira el resultado provisional: en GitHub, junto al último commit de main, aparece el check Corrector git con una fila por ejercicio. Se actualiza cuando el docente lanza la corrección: si has subido commits después, el último aún no tiene símbolo hasta la siguiente corrección. Cuando tu ejercicio salga sin fallos, etiqueta.

Cómo se valora

  • Cada ejercicio vale lo mismo y se corrige de forma automática desde su etiqueta: estructura del historial (padres de los merges, commits por rama, conflicto real) y contenido de los ficheros.
  • Las fechas de los commits no cuentan: se corrige cada etiqueta tal como esté al cierre del bloque.

Carpeta api-rest/. Teoría: API REST 1, API REST 2 y API REST 3. La práctica es el minijuego.

Hackea el ranking: los cuatro objetivos y qué entregar

Solución de «Hackea el ranking», reto a reto
Ficheros
docker-compose.yml, server/server.py y web/index.html

Solo la dirección del juego que proyecta el docente, solo durante la clase

fundamentos/casos-analizados/hackea-el-ranking.md, como explica De truco a vulnerabilidad

Se juega desde el navegador, F12, curl y la IA.

Levantar el juego (docente)

El servidor tiene dos modos: trusted, que acepta la puntuación que manda el navegador, y validated, que lleva la partida en el servidor. Se juega con el primero y se termina desplegando el segundo para ver que los mismos trucos ya no funcionan. Desde api-rest/hackea-el-ranking/:

MODE=trusted docker compose up -d --remove-orphans      # http://IP-DEL-DOCENTE:8080  (?scoreboard para el proyector)
MODE=validated docker compose up -d --force-recreate --remove-orphans

El docente abre un túnel con Pinggy desde su equipo; la URL https://….pinggy.link que imprime es la dirección del juego y el alcance de la práctica. Se proyecta con ?scoreboard al final.

ssh -p 443 -R0:localhost:8080 free@a.pinggy.io

En el plan gratuito el túnel se cierra a los 60 minutos y al reabrirlo cambia la URL: hay que volver a proyectarla. El juego tiene que estar levantado antes de abrir el túnel o la URL responde 502.

Para repetirlo en casa, levanta el juego en tu equipo desde Git Bash con la primera orden: la dirección pasa a ser http://localhost:8080.

Empresa con Terraform

Carpeta empresa-con-terraform/. Enunciado: La empresa en Floci. Cómo montar el laboratorio paso a paso: Puesta en marcha.

  1. Copia plantilla-alumno/alcance.html a fundamentos/alcance.html y rellénalo: objetivo (la cuenta emulada en tu portátil), qué se permite, quién autoriza (el docente) y fechas.
  2. Copia el laboratorio a fundamentos/ de tu repositorio, como explica la puesta en marcha, y desde fundamentos/ levanta la nube: docker compose up -d floci.
  3. Pasa Trivy y guarda la salida: docker compose run --rm trivy | tee trivy-antes.txt.
  4. Por cada aviso, pide a la IA que explique qué significa y qué cambio propone, compruébalo en la documentación del recurso de Terraform y aplícalo. Repite Trivy hasta que no quede ningún aviso alto ni crítico y guarda esa última salida en trivy-despues.txt.
  5. Despliega en Floci y comprueba con la CLI de AWS que la empresa existe: 
    docker compose run --rm terraform init
docker compose run --rm terraform apply
docker compose run --rm aws s3 ls
docker compose run --rm aws iam list-users

Cómo se valora

  • Trivy sin avisos altos ni críticos sobre el Terraform entregado.
  • El Terraform sigue desplegando sin errores. Corregir no es borrar: la empresa necesita su bucket, su usuario y su cortafuegos.
  • Commits a lo largo del trabajo, no un volcado final.

Carpeta mini-auditoria/. Como en Empresa con Terraform, se copia a tu repositorio y se trabaja desde ahí: el laboratorio despliega el Terraform que corregiste y la regla que escribas se entrega en su sitio. Enunciado: Fases de un ataque y auditoría vigilada.

  1. Copia el laboratorio y para el de Empresa con Terraform, que usa el mismo contenedor floci y el puerto 4566:

cp -r ../documentacion-hacking-etico/01-fundamentos/ejercicios/mini-auditoria fundamentos/

    Desde aquí, todos los comandos se lanzan en fundamentos/mini-auditoria/.
  2. Levanta el laboratorio y despliega en este Floci el Terraform que corregiste en Empresa con Terraform, para que la cuenta tenga contenido. Terraform verá que los recursos no existen en este Floci y los volverá a crear: 
    docker compose up -d
docker compose run --rm terraform init
docker compose run --rm terraform apply
  3. Reconocimiento: qué equipos hay en la red. 
    mkdir -p ../inventario ../alertas
docker compose run --rm auditor -sn 172.28.0.0/24 | tee ../inventario/red.txt
  4. Enumeración: qué servicio y versión hay en cada equipo y qué recursos tiene la cuenta. 
    docker compose run --rm auditor -sV 172.28.0.10 172.28.0.20 172.28.0.30 | tee -a ../inventario/red.txt
docker compose run --rm aws s3 ls | tee ../inventario/nube.txt
docker compose run --rm aws iam list-users | tee -a ../inventario/nube.txt
docker compose run --rm aws ec2 describe-security-groups | tee -a ../inventario/nube.txt
  5. Mira la web con curl desde dentro de la red del laboratorio y anota qué descubres: 
    docker compose run --rm curl -i http://172.28.0.20/
docker compose run --rm curl -i http://172.28.0.20/robots.txt
  6. Detección: etiquetar.py resume las alertas de Suricata por fase y por origen. 
    py etiquetar.py | tee ../alertas/resumen.txt
  7. Escribe al menos una regla propia en suricata/local.rules (sid a partir de 1000100) que detecte algo que hayas hecho y que no saltara. Reinicia Suricata con docker compose restart suricata, repite lo que hiciste y comprueba con py etiquetar.py que salta. Se entrega ese mismo fichero. Lo que escribe Suricata en salidas/ no se sube.

Opcional: en floci-ec2/ hay un Terraform que pide a Floci una instancia EC2 de verdad (un contenedor). Si arranca y aparece en docker ps, es la base de lo que haremos en Redes y sistemas.
