Lab Empresa con Terraform: puesta en marcha

Una cuenta AWS emulada en tu equipo (Floci), la infraestructura de una empresa ficticia desplegada con Terraform y Trivy para encontrar sus fallos de configuración. Solo necesitas un motor de contenedores.

Floci→Trivy→corregir→Terraform apply→AWS CLI

Todos los comandos se lanzan desde la carpeta del ejercicio:

cd documentacion-hacking-etico/01-fundamentos/ejercicios/empresa-con-terraform

Requisitos

Basta con uno de los dos motores. Floci, Terraform, Trivy y la CLI de AWS llegan como contenedores.

MotorQué instalarNotas
Docker DesktopDocker Desktopdocker compose viene incluido.
Podmanpodman y podman-composeEn macOS y Windows necesita su máquina virtual arrancada.

Además: el puerto 4566 libre y conexión a Internet la primera vez, para descargar las imágenes.

1Preparar el motor de contenedores

Con Docker Desktop, ábrelo y espera a que diga que está en marcha. Con Podman, crea y arranca su máquina virtual (init solo la primera vez):

podman machine init
podman machine start

Comprueba que responde:

docker ps

Con Podman, en todos los comandos puedes escribir podman compose en lugar de docker compose.

2Arrancar la nube (Floci)

Floci responde como AWS en http://localhost:4566, región eu-west-1, credenciales test/test. Lo que crees se guarda en un volumen y sobrevive a reinicios.

docker compose up -d floci
  1. Abre http://localhost:4566: el panel de Floci con los servicios emulados.
  2. Pulsa Open Floci UI. La primera vez tarda unos segundos: Floci lanza la consola web en otro contenedor (floci-aws-ui) y la abre en http://localhost:4500.

3Analizar con Trivy

Trivy revisa los ficheros de terraform/ y avisa de los fallos de gravedad alta o crítica. El comando muestra los fallos en la terminal y deja informe-trivy.html en la carpeta del ejercicio.

docker compose --profile herramientas run --rm trivy
open informe-trivy.html

En Windows o Linux, abre el HTML con doble clic. La primera ejecución descarga las reglas y tarda algo más.

Con Docker Desktop basta docker compose run --rm trivy. Con Podman hay que añadir --profile herramientas, porque Trivy, Terraform y la CLI de AWS están en ese perfil.

4Desplegar con Terraform

Terraform crea en Floci un bucket S3 de copias, un usuario IAM de operaciones con su política y el cortafuegos (security group) del servidor web. El estado queda en terraform/terraform.tfstate.

docker compose --profile herramientas run --rm terraform init
docker compose --profile herramientas run --rm terraform apply

Escribe yes cuando lo pida.

5Comprobar con la CLI de AWS

La CLI ya apunta a Floci. Los mismos recursos se ven en la consola web, en S3, IAM y EC2.

docker compose --profile herramientas run --rm aws s3 ls
docker compose --profile herramientas run --rm aws iam list-users
docker compose --profile herramientas run --rm aws ec2 describe-security-groups

6Corregir y repetir

Este es el ciclo de la práctica. El enunciado completo está en La empresa en Floci.

  1. Lee cada aviso de Trivy, pide a tu IA que lo explique y comprueba la propuesta en la documentación del recurso de Terraform.
  2. Corrige terraform/empresa.tf. Corregir no es borrar: la empresa necesita su bucket, su usuario y su cortafuegos.
  3. Vuelve al paso 3 hasta que no quede ningún aviso alto ni crítico.
  4. Vuelve al paso 4 y comprueba que el despliegue sigue terminando sin errores.

Problemas frecuentes

Lo que vesPor qué pasaQué hacer
missing services [trivy] (o terraform, aws)Con Podman, los servicios de un perfil no se activan solos.Añade --profile herramientas al comando.
«Floci UI couldn't start… could not reach the container runtime»Floci no ve el socket de Docker/Podman para lanzar la consola web.Usa el docker-compose.yml del repositorio, que monta /var/run/docker.sock con label=disable, y recrea Floci: docker compose up -d --force-recreate floci.
Cannot connect to the Docker daemonEl motor no está arrancado.Abre Docker Desktop o lanza podman machine start.
El puerto 4566 ya está en usoHay otro Floci o LocalStack levantado.Para el otro contenedor con docker ps y docker stop <nombre>.
ERROR [rego] … specify_ami_owners.rego al pasar TrivyUna regla descargada no encaja con esta versión de Trivy.Nada. Solo afecta a esa regla y el análisis sigue.

Apagar y limpiar

Para el laboratorio y conserva la cuenta emulada:

docker compose down

Para empezar de cero, borrando también lo que había en Floci:

docker compose down -v

Después de down -v, borra también terraform/terraform.tfstate. Si no, Terraform cree que los recursos siguen existiendo.
